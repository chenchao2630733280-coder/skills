# Short Drama Spec — 短剧故事规格（阶段 2）

本 skill 是 AI 短剧制作流水线的**阶段 2**，职责是读取已立项的蓝图，把选题扩展成"能持续产生剧情的完整故事规格 + 分集大纲"，为阶段 3 正式剧本提供总纲。

**核心信条**：先做故事发动机，再做分集。发动机没立住之前，禁止生成分集大纲。

---

## 一、输入与输出

**输入**（固定路径，必读）：
- `docs/SHORT_DRAMA_BLUEPRINT.md`：立项蓝图（高概念 / 类型 / 集数 / 工具链 / 阶段裁剪）

**输出**（固定路径，与总纲 §八 严格一致，不允许自定义路径）：
- `docs/STORY_SPEC.md`：故事规格（发动机 / 核心规则 / 人物系统 / 秘密系统 / 整剧阶段 / 情绪曲线 / 评分）
- `docs/EPISODE_OUTLINE.md`：分集大纲（每集目标与卡点设计，供阶段 3 引用）

**读图须知**：蓝图"9. 阶段裁剪建议"决定本阶段执行范围；蓝图集数决定大纲集数上限；蓝图类型/受众决定情绪配比与卡点密度；蓝图缺字段时用默认值补齐并标注假设（如总集数默认 60、单集 1-3 分钟）。

---

## 二、执行顺序（强制，先发动机后分集）

1. 选题复核（§三.0）
2. 故事发动机（§三.1-3.3）
3. 核心规则设计（§四，若故事含超能力/AI 系统/特殊制度等）
4. 人物系统（§五）
5. 秘密与真相系统（§六）
6. 整剧结构 6-8 阶段（§七）
7. 情绪曲线（§九）
8. 分集大纲（§八）
9. 评分 + 合规独立否决（§十）
10. 写回两份输出文档（§十一）

每一步完成后跑该步自检，不合格按 `runtime.yaml` 的 degrade 处理（单步重做 ≤2 轮）。

---

## 三、故事发动机（先做这个）

### 3.0 选题复核（前置门）

检查：概念能否一句话讲清；是否有独特变量（不是旧套路换皮）；是否具备 ≥5 轮目标升级、≥3 次关系变化、≥2 次真相反转、1 个不可逆选择；是否适合短剧而非长剧/电影（强连续剧、1-3 分钟单集、60-100 集可支撑）。

**不通过 → 输出问题清单，建议回退阶段 0/1（topic-brainstorm / blueprint）重做，不强行推进**（见 runtime.yaml degrade 第 1 条）。

### 3.1 发动机八部件（详细模板见 `references/story-engine.md`）

| # | 部件 | 必填字段 |
|---|---|---|
| 1 | 主角 | 表面身份 / 真实处境 / 最大性格缺陷 / 最擅长能力 / 最怕面对的事 |
| 2 | 主角欲望 | 表层目标 / 深层需求 / 隐藏欲望 |
| 3 | 启动事件 | 第一集发生 / 不可逆 / 改变原有生活 / 与核心规则相关 / 产生结尾卡点 |
| 4 | 主角为什么不能退出 | ≥2 个原因（时间压力 / 身份暴露 / 亲人安全 / 巨大利益 / 无法解除的契约 / 规则反噬 / 社会性死亡 / 道德责任…） |
| 5 | 核心阻碍 | 外部 / 内部 / 关系 / 规则 四类 |
| 6 | 对手 | 目标 / 行动逻辑 / 资源优势 / 合理动机 / 主动攻击能力 / 识别主角弱点的能力 / 与主角的**镜像关系** |
| 7 | 升级机制 | ≥6 种升级维度（见 3.2） |
| 8 | 最终选择 | 两个重要价值之间的选择（复仇 vs 救人 / 真相 vs 亲情 / 胜利 vs 底线 / 掌控规则 vs 摧毁规则…），**不能只是打败反派** |

### 3.2 升级机制（至少选 6 种，铺进 6-8 个阶段）

对手升级 / 信息升级 / 代价升级 / 时间压力升级 / 关系破裂 / 规则失控 / 身份暴露 / 目标改变 / 真相改变 / 盟友转敌 / 敌人转盟 / 更大系统出现。

### 3.3 发动机 7 问（验证，任一不通过回炉）

1. 这个故事为什么能**持续**发生（而不是只发生一次）？
2. 主角在每个阶段**主动做了什么**？
3. 主角为什么不能退出？
4. 对手的目标与主角冲突的本质是什么？
5. 每一次胜利带来了什么新问题？
6. 核心规则如何持续制造剧情？
7. 最终选择发生在哪两个价值之间？

## 四、核心规则设计（若故事含超能力/AI 系统/特殊制度/民俗规则/时间循环/身份交换/记忆交易等）

每一条规则必须明确：**触发 / 收益 / 即时代价 / 长期代价 / 使用限制 / 禁止事项 / 规则漏洞 / 规则误导 / 规则反噬 / 对手反制 / 与结局的关系**。

规则铁律：
1. 容易理解，难以逃避
2. 可重复触发，每次触发制造不同结果
3. 使用越多风险越大，不可无成本使用
4. 对手能利用或反制
5. **删除规则后故事仍成立 → 规则只是装饰，必须重写**

---

## 五、人物系统

### 5.1 人物功能表

| 功能 | 责任 | 要求 |
|---|---|---|
| 主角 | 推动剧情 | 主动行动，不长期被动 |
| 核心对手 | 制造阻碍 | 有目标/逻辑/资源/动机，不是纯恶 |
| 情感关系人物 | 制造拉扯 | 与主角互相有欲望 |
| 利益盟友 | 阶段性帮助 | 可倒戈 |
| 潜在背叛者 | 中段反转 | 铺垫 ≥2 次征兆 |
| 秘密持有者 | 控制信息 | 知道的比说的多 |
| 镜像人物 | 映照主角 | 提供选择对照 |

功能可合并（一人多职），但不能只剩工具属性。

### 5.2 重要关系 7 问（每段关键关系必答，模板见 `references/character-system.md`）

A 想从 B 身上得到什么？B 想从 A 身上得到什么？A 为什么不能直接说出真实目的？B 误解了 A 什么？双方共同利益是什么？双方最终冲突是什么？关系会经历哪三次变化？

### 5.3 人物卡模板

姓名 / 身份 / 年龄 / 外在特征 / 表面性格 / 真实欲望 / 恐惧 / 秘密 / 弱点 / 能力 / 底线 / 谎言 / 与主角的关系 / 想从主角身上得到什么 / 立场三阶段 / 结局（完整模板见 `references/character-system.md`）。

---

## 六、秘密与真相系统（四层）

| 层 | 作用 | 揭露节奏 |
|---|---|---|
| 即时秘密 | 负责前几集追更 | 前 5 集内揭 |
| 关系秘密 | 改变信任与人物立场 | 中段揭 |
| 主线秘密 | 改变主角目标与调查方向 | 中后段揭 |
| 终极真相 | 重新解释前文、回应主题 | 终局揭 |

每层秘密必须填写：**谁知道 / 谁不知道 / 谁误解 / 首次暗示集数 / 部分揭露集数 / 完全揭露集数 / 揭露后改变什么 / 是否产生新问题**（模板见 `references/secrets-system.md`）。

终极真相必须提前埋下：行为异常 / 道具线索 / 时间矛盾 / 语言漏洞 / 人物回避 / 重复细节。

---

## 七、整剧结构（6-8 个故事阶段）

推荐八阶段（可合并为 6-7 阶段，不可少于 6）：

| # | 阶段 | 内容 |
|---|---|---|
| 1 | 异常进入 | 建立日常 → 异常出现 → 规则启动 → 迫使行动 |
| 2 | 试探规则 | 尝试解决问题，小胜，暴露代价 |
| 3 | 主动进攻 | 形成计划，主动利用规则，首次正面对抗 |
| 4 | 错误胜利 | 阶段性成功，实际落入更大局面 |
| 5 | 中点反转 | 真相变化，对手目标反转，原目标不再成立 |
| 6 | 全面失控 | 规则反噬、盟友背叛、身份暴露、资源尽失 |
| 7 | 最低点与重新选择 | 认识缺陷，放弃错误目标，作出新选择 |
| 8 | 终极对决 | 线索汇合、利用规则漏洞、揭晓真相、完成选择 |

**阶段大纲模板**（每阶段一条）：阶段名称 / 覆盖集数 / 阶段目标 / 主角当前目标 / 对手当前目标 / 主角行动策略 / 核心冲突 / 主要关系变化 / 揭露的信息 / 保留的信息 / 阶段性胜利 / 阶段性代价 / 阶段末大反转 / 下一阶段进入钩子。

---

## 八、分集大纲

### 8.1 每集模板（EPISODE_OUTLINE.md 每集一节）

本集目标 / 开场钩子 / 主角行动 / 对手反制 / 核心冲突 / 新增信息 / 关系变化 / 本集结果 / 结尾卡点。

### 8.2 单集原则

- 开场 5 秒内出冲突 / 异常 / 危险 / 结果预告
- 主角每集必须想完成一件具体的事，且不能按计划顺利完成
- 每集至少改变一项：信息 / 关系 / 风险 / 目标
- 每集结尾必须产生追更动力
- 禁止连续使用同类型卡点

### 8.3 卡点类型库（五种，轮换使用）

| 类型 | 内容 | 举例 |
|---|---|---|
| 信息型 | 关键证据 / 真相反转 / 隐藏信息 / 错误对象 | 线索指向了错误的人 |
| 危机型 | 被抓 / 将死 / 规则触发 / 身份暴露 / 时间耗尽 | 倒计时还剩 24 小时 |
| 关系型 | 盟友背叛 / 恋人倒戈 / 被利用 / 情感承认 | 最信任的人突然反水 |
| 选择型 | 二选一 / 主动入局 / 使用高风险规则 / 牺牲关系 | 救 A 就保不住 B |
| 反转型 | 受害者是操控者 / 对手在保护主角 / 记忆为假 | 一直在查的人才是幕后 |

---

## 九、情绪曲线规则

每 10 集左右一个情绪循环：**压迫 → 反击 → 小胜 → 新疑问 → 关系升温 → 风险增加 → 背叛 → 绝境 → 反转 → 释放**。

全剧至少保证：
- 3 次爽点高潮
- 2 次关系重大变化
- 2 次真相级反转
- 1 次主角最低点
- 1 次不可逆损失
- 1 次最终情绪释放

在 STORY_SPEC.md 的情绪曲线章节逐阶段/逐集标注：爽点 / 虐点 / 甜点 / 悬疑点 / 反转点 / 最低点 / 释放点。

## 十一、输出文档结构与交互约定

### 11.1 STORY_SPEC.md 结构

项目理解（名称/高概念/类型/受众/集数/假设）→ 选题复核结论 → 故事发动机（八部件 + 升级机制 + 最终选择）→ 核心规则 → 人物系统（功能表 + 关系 7 问 + 人物卡）→ 秘密系统（四层）→ 整剧阶段（6-8 阶段大纲）→ 情绪曲线（标注表）→ 综合评分与风险诊断（含合规/侵权检查结论）。

### 11.2 EPISODE_OUTLINE.md 结构

每集一节（按 8.1 模板），节首标注：集数 / 所属阶段 / 情绪循环位置 / 卡点类型；节末标注：衔接下集的开场钩子建议。

### 11.3 交互约定

- 读取蓝图后**不问用户问题**，直接产出（蓝图已含决策）；蓝图信息不足时以默认值补齐并标注假设
- 产出后简报："故事规格与分集大纲已生成（共 N 集，M 个阶段）。下一步可调用 short-drama-script 进入正式剧本"
- 不自行调用下游 skill，等总纲 / 用户调度

- [ ] 发动机八部件全部填写，无空项

- [ ] 主角不能退出原因 ≥2
- [ ] 核心规则有代价，删除规则后故事不成立
- [ ] 人物功能表完整，关键关系都答了 7 问
- [ ] 四层秘密各有暗示/揭露节点，终极真相有铺垫
- [ ] 阶段 6-8 个，每阶段有完整阶段大纲
- [ ] 分集集数与蓝图一致，每集模板完整
- [ ] 情绪循环每 10 集一个，全剧硬指标达标
- [ ] 评分 ≥70（<70 需标注处理），合规/侵权无否决项
- [ ] 产物自评：按 skill-auditor 后评测模式自查（可选）
