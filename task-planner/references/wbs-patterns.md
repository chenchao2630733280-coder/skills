# WBS 拆解模式 (task-planner)

本文件定义 task-planner 在"选择 WBS 模式"阶段可用的三种拆解模式。
拆解模式决定根任务向叶子任务延伸的方向,选错模式会导致依赖混乱、并行度低。

## 一、按功能拆解

- **适用场景**:产品功能开发、特性交付、模块化构建。需求可按业务功能自然切分时首选。
- **拆解步骤**:
  1. 识别需求覆盖的全部功能模块。
  2. 每个模块继续拆到"子功能"层。
  3. 子功能拆到"实现任务"(叶子),每个叶子可在 1 次 skill 调用内完成。
  4. 横向标注模块间依赖(如 B 模块依赖 A 模块的接口)。
- **树形结构**:根 → 功能模块 → 子功能 → 实现任务
- **示例**(需求:做一个博客系统):
  - 根:博客系统
    - 文章管理 → 文章 CRUD → 实现"创建文章"接口 / 实现"编辑文章"接口
    - 用户管理 → 用户注册登录 → 实现注册接口 / 实现登录接口
    - 评论管理 → 评论提交 → 实现评论接口
- **优先级提示**:核心主链路功能标 P0,辅助功能标 P1,锦上添花标 P2。

## 二、按层拆解

- **适用场景**:系统建设、全栈工程、多层架构交付。需求横跨数据/后端/前端/集成各层时使用。
- **拆解步骤**:
  1. 按技术架构分层(数据层 → 后端层 → 前端层 → 集成层)。
  2. 每层内部按功能/模块拆到叶子任务。
  3. 标注跨层依赖:上层依赖下层的产物(数据依赖)。
  4. 集成层任务通常依赖前端+后端同时完成(控制依赖)。
- **树形结构**:根 → 数据层 → 后端层 → 前端层 → 集成层
- **示例**(需求:搭建电商后台):
  - 根:电商后台
    - 数据层 → 设计商品表 / 设计订单表
    - 后端层 → 商品接口 / 订单接口(依赖数据层)
    - 前端层 → 商品列表页 / 订单详情页(依赖后端接口契约)
    - 集成层 → 联调下单流程(依赖前端+后端)
- **优先级提示**:下层基础任务多为 P0(阻塞上层);集成层任务按业务关键度排优先级。

## 三、按时序拆解

- **适用场景**:流程类任务、阶段化交付、有明确先后顺序的运营/迁移任务。
- **拆解步骤**:
  1. 把需求按时间或阶段切分(阶段1 → 阶段2 → 阶段N)。
  2. 每个阶段内部按子步骤拆到叶子任务。
  3. 标注阶段间依赖:后阶段依赖前阶段产出(控制依赖为主)。
  4. 同阶段内可并行的任务标注 parallel_with。
- **树形结构**:根 → 阶段1 → 阶段2 → 阶段N
- **示例**(需求:数据迁移上云):
  - 根:数据迁移上云
    - 阶段1:评估 → 盘点现有数据 / 评估迁移工具
    - 阶段2:准备 → 建目标库 / 编写迁移脚本(依赖阶段1)
    - 阶段3:执行 → 全量迁移 / 增量同步(依赖阶段2)
    - 阶段4:校验 → 数据比对 / 切流(依赖阶段3)
- **优先级提示**:靠前阶段的关键路径任务标 P0;后续阶段视阻塞程度排 P1/P2。

## 四、模式选择决策

| 需求特征 | 推荐模式 |
|---------|---------|
| 多个独立功能,可并行开发 | 按功能拆解 |
| 涉及数据/后端/前端多层 | 按层拆解 |
| 有严格先后阶段、流水线式 | 按时序拆解 |
| 混合特征 | 选主模式,局部混合(如按层为主,层内按功能) |

> 选择后若发现依赖关系错乱(如大量跨层回依赖),应回退重选模式。
