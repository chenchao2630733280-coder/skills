# 嵌入模型选择 (embedding-models)

> codebase-rag 的嵌入模型选择参考。`index_codebase.py build --embedding <模式>` 时查阅。

## 三种嵌入模式

### 1. local(本地嵌入,默认)

**实现**:使用 `scikit-learn` 的 TF-IDF 向量化 + 余弦相似度。

**优点**:
- 无需 API 密钥,隐私友好
- 零成本(无 API 调用费)
- 离线可用

**缺点**:
- 非真正的语义嵌入(TF-IDF 是词频统计,非深度语义)
- 对同义词/近义词无法识别(如"登录" vs "login")

**适用**:关键词明确的检索场景;无 API 密钥的离线环境。

**安装**:
```bash
python -m pip install scikit-learn numpy
```

### 2. none(无嵌入)

**实现**:不生成向量,降级为关键词子串匹配。

**优点**:
- 零依赖,任何环境可用
- 索引体积最小

**缺点**:
- 无语义检索能力
- 检索精度最低(纯子串 + 词频)

**适用**:临时索引;嵌入库不可用时的降级方案。

### 3. api(API 嵌入)

**实现**:调用外部嵌入 API(如 OpenAI embeddings / 本地 Ollama)。

> 注:当前版本未实现 API 嵌入,预留接口。实际 API 嵌入需配置 API 密钥 + 调用嵌入接口。

**优点**:
- 真正的语义嵌入
- 检索精度最高

**缺点**:
- 需 API 密钥(成本)
- 依赖网络
- 隐私风险(代码片段上传到 API)

**适用**:对检索精度要求高的大型项目;有 API 预算的团队。

## 降级链

```
api(有密钥) → local(有 scikit-learn) → none(无依赖)
```

`--embedding local` 时,若 scikit-learn 不可用,自动降级为 none 并提示。

## 模式对比

| 维度 | local(TF-IDF) | none(关键词) | api(语义) |
|------|--------------|-------------|----------|
| 语义能力 | 弱(词频) | 无(子串) | 强(深度) |
| 依赖 | scikit-learn | 无 | API 密钥 |
| 成本 | 零 | 零 | 按 token 计费 |
| 隐私 | 本地 | 本地 | 上传 API |
| 离线 | 可用 | 可用 | 不可用 |
| 精度 | 中 | 低 | 高 |

## 推荐配置

- **个人项目 / 离线环境**:`local`(TF-IDF,平衡精度与成本)
- **快速临时索引**:`none`(零依赖)
- **大型企业项目**:`api`(精度优先,需预算)
- **不确定**:`local`(默认,有库则 TF-IDF,无库降级 none)
