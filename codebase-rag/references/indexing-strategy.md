# 分块策略 (indexing-strategy)

> codebase-rag 的代码分块策略参考。`index_codebase.py build --chunk-strategy <策略>` 时查阅。

## 四类分块策略

### 1. file(整文件一块)

**适用**:小型文件(≤50 行)、配置文件(JSON/YAML/TOML)、Markdown 文档。

**优点**:简单,索引快,检索时上下文完整。

**缺点**:大文件检索时返回过多无关代码。

**示例**:
```
src/config.json (30 行) → 1 块(整文件)
```

### 2. function(按函数/方法分块)

**适用**:中型代码文件(50-300 行),含多个函数/方法定义。

**分块规则**:检测 `def` / `class` / `function` / `func` / `fn` 等关键字,每个函数/类定义作为一块。

**优点**:检索粒度精确,命中函数即返回完整函数体。

**缺点**:依赖关键字检测,非主流语言可能不准。

**示例**:
```
src/utils.py (200 行,含 5 个函数) → 5 块(每函数一块)
```

### 3. semantic(按语义边界分块)

**适用**:大型代码文件(>300 行),或语义结构复杂(嵌套类/长函数)。

**分块规则**:按语义边界(类定义/模块边界/双换行分段),结合固定行数上限(默认 300 行)。

**优点**:语义完整,适合大型文件。

**缺点**:分块逻辑复杂,可能切分不够精确。

### 4. hybrid(混合,默认)

**适用**:混合项目(推荐默认)。

**分块规则**:
- 小文件(≤50 行)→ file 策略(整文件一块)
- 中型文件(50-300 行)→ function 策略(按函数分块)
- 大文件(>300 行)→ function 策略,分块失败时按 300 行均分

**优点**:自适应,兼顾简单与精确。

## 策略选择速查

| 场景 | 推荐策略 |
|------|---------|
| 配置文件为主 | `file` |
| 纯函数式代码 | `function` |
| 大型 OOP 项目 | `semantic` |
| 混合项目(默认) | `hybrid` |
| 不确定 | `hybrid`(自适应) |

## 分块大小建议

- 单块建议 50-300 行(过小导致索引碎片,过大导致检索噪声)
- 超过 300 行的块按行数均分
- 每块 text 限制 2000 字符存储(防索引过大)

## 忽略目录

索引时默认跳过以下目录:
- `.git` / `node_modules` / `__pycache__` / `.trae-cn`
- `dist` / `build` / `.next` / `vendor` / `export` / `Build`
