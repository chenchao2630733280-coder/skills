# 通用 UI 设计规范

本规范是全局 Skill 的**通用默认档案**，不绑定任何具体项目、品牌、城市平台或业务系统。项目中的 `output/spec/design-tokens.json` 与页面原型文档中的项目覆盖值优先于本文件。

## 1. 优先级

1. 用户本轮明确指定的视觉与端侧要求；
2. 当前项目 `design-tokens.json`；
3. 当前项目页面原型文档中的项目覆盖；
4. 当前项目既有且已确认的设计系统；
5. 本文件默认值。

不得用本文件默认值覆盖已有项目设计系统。冲突时记录为构建问题。

## 2. 默认设计档案

默认档案名：`Emerald Enterprise`。仅在项目没有设计 Token 时使用。

- 主色：`#39BC7A`
- 主色悬停：`#2E9B66`
- 成功：`#39BC7A`
- 警告：`#F59E0B`
- 错误：`#EF4444`
- 信息：`#3B82F6`
- 主文本：`#323233`
- 次文本：`#646466`
- 边框：`#E5EAF0`
- 页面背景：`#F5F7FA`
- 容器背景：`#FFFFFF`

默认 PC 框架：侧栏 264px、顶栏 58px、工作区页签栏 52px、内容内边距 20px、基础圆角 8px。导航活动态默认使用浅蓝背景 `#EAF4FF` 和蓝色文字 `#2589F5`。默认移动基准：375×812、页面边距 12/16px、最小触控区域 44×44px。

以上均为 fallback，不是业务硬约束。

## 3. PC 管理端

- 使用清晰的信息层级：全局导航、页面标题、筛选/操作、主体内容、反馈。
- 列表、表单、详情、仪表盘根据真实任务选择，不机械套用表格。
- 数值右对齐；文字左对齐；日期、金额和 ID 使用等宽数字。
- 关键操作有明确主次关系；危险操作需二次确认并说明影响。
- 侧栏、顶栏和内容尺寸优先读取项目 Token。

## 4. 移动端

- 单列任务流优先，避免把 PC 页面等比例压缩。
- 底部固定操作不得遮挡内容；考虑安全区。
- 主要触控区域不小于 44×44px。
- 输入、键盘、滚动、返回和中断恢复需有明确行为。
- 风险信息必须使用图标、标题和正文，不只依赖颜色。

## 5. 组件与图标

- 项目内只使用一套图标体系；默认优先本地 SVG。
- 不混用 Emoji、FontAwesome、Ant Design Icons 等多套图标。
- 默认不依赖 CDN；资源放在当前项目 `output/site/assets/`。
- 组件样式必须来自 Token，不在单页随意新增颜色、圆角和阴影。

## 6. 状态与反馈

状态按对象适用性声明，不要求每个页面机械实现全部状态。

- 数据加载页面通常考虑：`normal/loading/empty/error/permissionDenied`。
- 表单通常额外考虑：`validationError/submitting/success`。
- 静态说明、局部组件或纯预览可将不适用状态标为 `notApplicable`。
- 只有真实业务需要的状态才进入原型和 HTML。

## 7. 可访问性与安全

- 使用语义化 HTML、关联 label、可见焦点和键盘操作。
- 不禁止浏览器缩放。
- 动态文本优先使用 `textContent`；富文本必须经过白名单清洗。
- 示例数据不得包含真实敏感信息。
- 颜色对比、错误提示和禁用状态不能只依赖颜色表达。
