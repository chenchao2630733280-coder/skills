# 产出规范（交付物通用约定）

本文件是多个生成/交付类 skill 共用的**交付物产出规范**唯一事实来源，避免每个 skill 各写一份导致口径漂移。

引用方（`generate-prototype` / `generate-html-pc-admin` / `generate-html-mobile` / `generate-portal` 等）在 SKILL.md 中以 `../_shared/references/output-conventions.md` 引用；**编辑只在本目录进行**。

适用对象：**面向交付的静态站点 + 说明文档 + JSON 工件 + 演示门户**（原型工程、文档工程、可演示交付物）。

---

## 1 交付物读作「初版」，无变更口吻

交付物是**当前状态**的描述，不是「改动流水账」。读者看到的应是「它现在是什么样」，而不是「它曾经怎么样、后来改了什么」。

| 反例（变更口吻） | 正例（初版口吻） |
|---|---|
| 原 `Pxx` / 已整合 / 正名为 / 由…迁移 | 直接述说「当下如何」 |
| 新增「X」 | 含「X」 |
| 不再… / 已移除… | 不… |

**刻意保留**：运营性文案（如「新增核销员」「本次核销」「本月新增 8 家」「下架后不再展示」）—— 这些描述的是**业务动作本身**，不是文档的变更史，不要顺手改。

**注意**：说明文档里若需要保留「原 X 正名为 Y」这类**迁移说明**（有的门禁靠它合法化旧词），属例外，仅限指定章节。

---

## 2 零图片资源 ⇒ 图形一律程序化

**原则**：交付物**不引用外部图片**（外链图无网即挂、且会导致离线校验失败）。图形一律**程序化生成**。

| 图形类型 | 做法 |
|---|---|
| 图标 / 商品图 / 封面占位 / 票面 | 程序化 **SVG**，内联为 `data:image/svg+xml;charset=utf-8,` + `encodeURIComponent(svg)` |
| 判据 | `naturalWidth > 0` 可判其已解码；零网络请求、同源解码 |

**分层**：共享层出**纯函数**（如「按名称生成图形」），呈现层只负责渲染；不要把生成逻辑散进各页面。

> ⚠️ data URI 的 percent-encoding **必须转义 `"` 与 `'`**，否则 XML 属性会提前闭合。

**例外**：确实需要「真实外链图片」的字段（如内容封面）可保留 URL，但要在文档里说明「演示依赖外网」，并知道它会破坏离线/零资源校验。

---

## 3 开发注释与产品提示双轨分离

页面上的「说明文字」有两种受众，**样式与内容都要分开**，不得混用：

| 受众 | 载体 | 内容 |
|---|---|---|
| **技术开发（DEV）** | 可折叠 `<details class="dev-note">`（默认收起，含角标） | 规则编号（BR-/V-/T-/PERM- 等）、字段级技术说明 |
| **后台使用者（OPS）** | 页面级 `form-tip--block` 或字段级 `form-tip` | 操作说明；**不写**规则编号 |

**纪律**：
- 规则编号（`BR-` / `V` / `T` / `TBD-` / `PERM-`）**只进 DEV**，不进 OPS 提示。
- 静态说明块**不得与 JS 运行期 `alert` 混用**样式。
- 若某样式只在 A 端定义，**B 端不得使用该内部标签**（用了会变形）。
- 断言可折叠块正文前**必须先展开**（`<details>` 默认收起 ⇒ 否则断言恒假）。

---

## 4 流转记法统一 ASCII `>`

状态流转/链路统一用 **ASCII `>`** 连接（如 `A > B > C`），不用全角箭头 `→`。

**纪律**：全交付集统一替换时，**某些工具脚本/校验正则里的 `→` 要刻意保留** —— 换掉它会让「附近窗口」判据恒真，导致检查**静默空转**（永远绿、永远没查）。

> 若门禁里有一条「全站不得出现 `→`」的规则，则**新页里的任何 `→` 都会失败**；趋势类标识用 `↑ 上升 / ↓ 下降 / — 持平`。

---

## 5 表格列宽：程序化对齐，不手敲空格

markdown 表格若要求列对齐，**用「取源行列宽 + 右补空格」程序化构造新行**（East-Asian-Width 记 2）。

**反模式**：
- 手敲空格对齐 ⇒ 容易错位、不可复现。
- **整表重排**（把列宽统一取全表最大）⇒ 会把**所有行**一并规范化，diff 放大到全表，且若原表本就不对齐，长度断言必失败。**只改目标行，不重排其它行。**

---

## 6 术语统一要带白名单

统一口径（如「企业 → X」「结算 → Y」）时，**技术标识不动**：英文标识、字段名、路由段、文件名、代码里的 key 一律保留原样。

**做法**：维护一份白名单（`enterprise` / `settlement` / 字段名 / `/路由段` / 文件名 …），替换只作用于「自然语言文本」，命中白名单的跳过。

## 维护规则

- 修改本文件后运行 `powershell -File _shared/validate.ps1` 校验引用完整性。
- 新增规范时，同步在引用它的各 skill 的参考文件表里登记（不复制正文）。
- skill 特有规范只写在对应 SKILL.md，不回写本文件。
