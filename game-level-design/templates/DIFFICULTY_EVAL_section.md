## §0 评估口径与可复现性

### 0.1 口径声明

| 项 | 值 | 说明 |
|---|---|---|
| 评估档位 | `{deterministic}` | 依据：局面**离散可枚举**，能把"初盘→终局"反推出来 |
| 判定口径 | `naive` 必输 **且** 可解 | 两个条件缺一不可 |
| 排序口径 | `{压力 = C × (1 + T)}`，按 {最大值} 归一化 | **只用于排序，不参与判定** |
| 一票否决项 | `solvable = false/unknown` → 该关不参与难度讨论 | 无解关的"难度分"描述一个不可能发生的事件 |
| 参考列（不进判据） | `strict` / `greedy` | 它们失败说明"打法不行"，不说明"关卡不行" |
| 已废弃口径 | `{抽样乱点通关率，2026-XX-XX 作废：不可复现，同日三组互斥读数}` | 见到该数字一律忽略，不得引用 |

### 0.2 可复现证据

```
命令: {level_designer --dir data/levels} 连跑两次 → repro_check.py
结果: REPRO {PASS}  比对字段 {862}  剔除计时 {40}（其中 {24} 项确实变化）
结论: 决策字段逐一相等；差异仅存在于计时字段
```

- [ ] 比对字段数 ≥ 10（低于此数视为**假 PASS**：闸门空转和闸门放行在日志里长得一样）
- [ ] 剔计时是**按字段名**，覆盖所有层级（`entry.ms` / `policies.*.ms` 都要剔）
- [ ] 若未跑：本项记 `NOT_RUN`，并在 §0.6 声明"难度数字未经验证，不可作为门禁依据"

### 0.3 闸门自检（变异测试）

| 注入的坏关卡 | 怎么造 | 闸门实际报了什么 | 应报 | 判定 |
|---|---|---|---|---|
| 无解关 | {删掉某必需颜色的全部卡片} | `{solvable=false}` | 不可解 | {PASS} |
| 无决策关 | {槽位开到 ≥ 卡数} | `{naive 通关 → FAIL 无决策}` | 无决策 | {PASS} |
| 难度倒挂 | {手工改最难关压力分为最低} | `{rank 与分数不一致}` | 排序错 | {PASS} |

> **三条必须全红。** 只要有一条是绿的，说明闸门对该类问题失明；
> 此时"全量通过"比"红"更危险——它给出的是虚假的安心。

### 0.4 指标有效性（四问）

| 问题 | 做法 | 结果 | 判据 |
|---|---|---|---|
| **能复现吗** | §0.2 两次运行 | `{PASS}` | 决策字段逐一相等 |
| **单调吗** | 单旋钮扫描：槽位 `+1` / 卡数 `-2` / 抽掉死卡段 | `{放宽 → 分数单调不增}` | 任一放宽使分数上升 ⇒ 公式有抵消项，是公式错 |
| **能分得开吗** | 全量分数极差 / 相邻差 | `{极差 }{ 相邻差均 > 0}` | 确定性下噪声为 0，相邻差必须 > 0，且不能全挤在一点 |
| **能证伪吗** | 给每个指标写"什么观测会推翻它" | 见下 | 写不出 = 指标是叙事，删掉 |

**证伪条件（必须能被现有工具产出，不是思想实验）：**

- 压力分声称衡量容错压力 → **若最高分的关 `naive` 能过，则指标失效**。
- 陷阱 `T` 声称 `T ≥ 1` 则 `naive` 必死 → **若某关 `T ≥ 1` 而 `naive` 存活，则 T 与 `naive` 走位不同源**。
- {本作特有的一条：}

**锚点校准**：公认最易 `{L01}` 与最难 `{L05}` 的分数序为 `{69 < 100}`，与体感一致 ✅ /
不一致 ❌ —— 若反了，**改公式不改关卡**。

### 0.5 逐关判定

| 关 | 盘面 | 卡 | 槽 | 容量 C | 陷阱 T | 压力 | 可解 | 证明方式 | `naive` | `strict` | 最优线 步/峰/星 | 判 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| {L01} | {24×24} | {12} | {4} | {3.00} | {0.00} | {69} | 是 | {greedy witness 12 步} | 过 | 过 | {12/2/3} | {PASS·教程豁免} |
| {L02} | … | | | | | | | | **过** | | | **FAIL·无决策** |

判定图例：

- `PASS` = 可解 **且** `naive` 死（或已登记豁免）
- `FAIL·无决策` = 可解但 `naive` 也能过 → 这关只有"点几下"，没有决策
- `FAIL·死局` = `naive` 死但不可解 → 必死不是难度，是 bug
- `BLOCKED` = 可解性 `unknown`（穷举预算用尽）→ 加大预算，**不许调参过关**

### 0.6 汇总与处置

```
关卡 {8} 关 | 可解 {8} | 豁免 {1} | PASS {2} | FAIL {6} | BLOCKED {0}
闸门结论: {FAIL}（{2}/{8} 通过；豁免不计入分子）
根因: {结构问题，不是数值问题——单卡载荷 {48} 格 / 入口 {4}/4 全开 / 仅 {12} 个决策点}
处理顺序（不得跳步）:
  1. {动结构：拆细单元 → 决策点 12 → 30}
  2. {收容量：槽位 6 → 4~5}
  3. {造无产出段：死卡段 ≥ 槽位}
  4. {按压力重排编号}
  5. {重跑闸门 → 通过才写回正式目录}
```

> **报告的价值不在 PASS，而在说清"为什么不过、按什么顺序改"。**
> 一份写着"8 关全可解、7 关 naive 也能过"的 FAIL 报告，比一份漂亮的 PASS 报告有用得多。
