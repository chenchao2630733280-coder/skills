## 2. 工位开关（Q1–Q5）

逐条回答，答"否"要写清砍掉了什么、砍掉的风险由谁兜。

| # | 问题 | 答案 | 结论 |
|---|---|---|---|
| Q1 | 局面离散、可枚举、可序列化？ | {是/否} | {否 = 不该做生成器，回 references/14} |

| Q3 | 有资源容器（库存/手牌/预算）？ | {是/否} | {是 → 开 B 分配} |

## 3. 每工位算法与参数

只写开了的工位；砍掉的写一句"不适用，因为……"。

| 工位 | 算法 | 关键参数 | 为什么选它（而不是另一个） |
|---|---|---|---|
| A 量化 | {K-means / 固定调色板 / 抖动} | {颜色数 N、量化后连通块数上限} | {颜色是机制旋钮时必须用固定调色板} |
| B 分配 | {贪心装箱 / 最大余数 / CP-SAT} | {容量库、每种容量出现次数} | |
| C 布局 | {随机撒 / 分层拓扑 / 生成树} | {盘面尺寸、层数、依赖边生成规则} | |
| D 验证 | {DFS+记忆化 / A* / 双向 BFS} | {搜索预算、剪枝条件、状态哈希} | |
| E 打分 | {蒙特卡洛 / 双极端策略对跑} | {模拟次数、策略定义} | {随机策略通过率 ≠ 难度} |

## 4. 四条不变量的裁决

**逐条给结论，不许留空。** 不适用也要写"不适用 + 原因"。

| 不变量 | 本作是否适用 | 怎么保证 | 怎么验证 |
|---|---|---|---|
| I1 容量守恒（Σ容量 = 需求 + 允许剩余，剩余有去处） | {是/否} | {允许剩余 = 可弃置数} | {断言/检查命令} |
| I2 需求序 ⊑ 可达序（先要的不能被后解锁的压住） | {是/否} | {拓扑序与消耗序一致} | {对每条依赖边 u→v（u 压着 v）断言 need_time(u) ≤ need_time(v)} |
| I3 干扰项可处置（能消耗后丢弃/换出） | {是/否} | {干扰项数 ≤ 可临时占用+可弃置} | |
| I4 托盘压力上界（存在一条不超容的消耗序） | {是/否} | {构造期维护压力 ≤ 上限} | {输出峰值占用/容量比值} |

> 不适用的情况举例：没有容量上限的游戏，I1/I4 不成立；没有遮挡的游戏，I2 退化为"无约束"。

## 5. 验证器规格

- 状态定义：`{剩余需求 need, 存活集合 alive, 容器占用 used}` → 压缩为 {整数位段 / 元组}
  - **放 `alive`（还没被取走的全部），不要放"可见集合"**：可见是 `alive` + 遮挡关系的派生量，
    两个 `alive` 不同、可见恰好相同的状态会被误判成同一个，**漏掉分支**（`references/16` §7.2）
- 启发/剪枝：{死锁判据 + 容量上界 + 记忆化}（三条都要有，缺一条就会在批量里超时）
  - 容量上界求和对的是**全部存活容器**，不是可见容器（同上，见 `references/16` §4 剪枝 2）
- 搜索预算：单关 {N} 节点 / {ms}；超预算如何处理：{判"未验证"而不是判"无解"}
- 输出：`{solvable, solution_count, shortest_len, peak_pressure}`

## 6. 失败回流策略

| 情况 | 回到哪个工位 | 重试上限 | 超限后怎么办 |
|---|---|---|---|
| 验证无解 | {B / C} | {N 次} | {丢弃并记录特征，供人工分析} |
| 解路数 < 下限（P2） | {C} | {N 次} | {降级为"高难但唯一解"并标注} |
| 峰值压力 = 容量（I4） | {B} | {N 次} | {必丢——这是设计失误不是难度} |

## 7. 已知限制

写"生成器做不到什么"，**这是本文件最容易被跳过、也最重要的一节**：

- {例如"可解性未经机器验证（Q5 答否），仅人工抽查 N 关"}
