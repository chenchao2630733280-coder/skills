# 评审交付验收清单

交付前逐项打勾；任何一项未满足，不算完成。

## 一、可复算

- [ ] 报告由 `tools/design_review.py` 生成，不是手写或改写过的数字。
- [ ] `campaign.json` 与 `attempts.csv` 的版本/快照可追溯到具体提交。
- [ ] `review.json` 保留完整中间量（分数、预测、模拟、诊断、建议），能被第三方复算。
- [ ] `data_source` 明确标注是否真实数据；示例数据必须写"虚构"。

## 二、结论可信

- [ ] 每个诊断都有证据（数值 + 类型 + 主因维度），不是形容词。
- [ ] 样本量 < `min_sample` 的关卡没有任何调参结论。
- [ ] 预测与实际差 ≥15% 的关卡，处理建议是"先查模型/埋点"。
- [ ] 没有把"模拟通关率"当成"真实通关率"对外表述。

## 三、建议可用

- [ ] 每条建议都是单变量、在合法范围内、不超过 `max_delta`。
- [ ] 建议写明预期效果（各分层）、副作用、验证指标。
- [ ] 明确标注"待验证假设"，并给出实验分组与回滚条件。
- [ ] 没有对"随机性不稳定"的关卡推荐随机性旋钮。

## 四、边界诚实

- [ ] 报告"假设与置信度"段落列出了 spread、θ、权重、per_unit、模拟参数的状态。
- [ ] 说明了"模拟是替代模型，不能替代真机测试与真实玩家数据"。
- [ ] 说明了阈值是占位值，且未为了让报告变绿而调整。

## 五、下一步清晰

- [ ] 有明确的处理顺序（可解性 → 模型可信度 → 跳变 → 随机性 → 配平 → 补数据）。
- [ ] 指定了试点关卡与灰度方式。
- [ ] 指定了回滚条件与责任人。
