# 11｜参数反向推荐引擎

## 1. 它解决的问题

"这关偏难 12 个百分点"是诊断，不是动作。推荐引擎要回答的是：
**动哪个参数、动多少、预期变成多少、有什么副作用、怎么验证。**

## 2. 计算链条

```
目标通关率 p* ──反解──▶ 目标难度分 s* = 0.5 + (θ_ref − logit(p*)) / spread
                      ↓
             需要的分差 Δs = s* − s_当前
                      ↓
    旋钮敏感度 e = 维度权重 w × per_unit（每 1 参数单位带来的分数变化）
                      ↓
              需要的参数步数 ≈ Δs / e，再按 step 取整
                      ↓
   用新的维度值重算分数与通关率，检查是否落入目标带（容差 ×0.6）
```

链式关系意味着：**权重或 per_unit 错了，推荐一定是错的**。所以推荐结果永远标"待验证"。

## 3. 三类方案

| 方案 | 约束 | 用途 |
|---|---|---|
| 对齐邻近 | 参数恢复到前 3 / 后 3 关的中位数 | 针对 CONFIG_OUTLIER：先排除漏改，再谈调优 |
| 渐进 | 单次改动 ≤ 原值 25% | 符合迭代习惯，一轮验证一个假设 |
| 一步到位 | 在合法范围与 `max_delta` 内误差最小的改动 | 用来看"差距到底有多大"，不一定要执行 |
| 备选 | 换一个难度维度 | 给第二种杠杆，避免永远只动步数 |

排序逻辑：先看是否落带（误差 ≤ 容差×0.6），再比误差，再比改动幅度。

## 4. 硬约束（引擎里真的会拦）

1. **单变量**：一次只动一个参数，保证可归因。多参数组合请人工设计因子实验。
2. **合法范围**：超出 `legal_ranges` 的方案直接丢弃。
3. **max_delta**：单次最大改动。没有它，引擎会给出"障碍种类 1→4"这类破坏性建议。
4. **单次 35% 上限**：接近或超过 35% 仍不落带，输出"分 2–3 轮迭代或复核目标"，不再给数值。
5. **随机性旋钮禁用**：关卡被判定 UNSTABLE 时，不允许推荐 `colors` 之类随机性旋钮——
   这时问题是种子分布，不是均值难度，调参只会掩盖问题。

## 5. 什么时候不该给推荐

- **样本不足**（DATA_GAP）：先补数据。
- **预测与实际背离**（PRED_ACTUAL_DIVERGENCE）：模型都不准，推荐没有意义。
- **可能是无解**：先跑求解器，确认可解再调参。
- **目标本身可疑**：整个阶段所有关卡都同向偏离时，大概率是 phases 目标定错了，不是 16 关全错。

引擎会把"无可用方案"显式输出为结构性建议（拆关、换机制、复核目标），而不是硬凑一个数值。

## 6. 一个算例

设定：`spread=4`，`θ_regular=0`，当前难度分 `s=0.40`（预测首通 59.9%），阶段目标 54%。

1. `s* = 0.5 + (0 − logit(0.54))/4 = 0.460`
2. `Δs = 0.060`
3. 步数旋钮：`w(resource_pressure)=0.20`，`per_unit=−0.045` → `e = −0.009` 分/步
4. 步数变化 ≈ `0.060 / (−0.009) = −6.7` → 取整 −7 步（23 → 16）
5. 复核：新分数 0.463，新首通 54.1%，落带 → 输出

若 `per_unit` 实际是 −0.02（真实边际效应更小），同样的目标需要 15 步——所以**必须先测 per_unit**。
小样本下 `per_unit` 的置信区间会很宽，这也是推荐只给"方向 + 待验证幅度"的原因。

## 7. 怎么验证推荐

1. **先离线**：改一个参数，重跑 `design_review.py`，确认预测方向与幅度；
2. **灰度**：单变量、对照组不动，随机化单位用玩家（不是关卡，关卡是固定难度）；
3. **看主指标 + 护栏**：首通率、失败进度分布、道具使用率、下一关继续率、会话时长；
4. **预设停止规则**：护栏恶化（继续率下降超 X、道具消耗异常上升）立即回滚；
5. **回归到模型**：用实验结果更新 `per_unit` 与权重，让下一轮推荐更准。

## 8. 常见失败模式

- **推荐成了"拉平"**：所有关卡都被建议调到目标带中值，曲线失去节奏。修法：目标带本身要有宽度，别用单点目标。
- **只动一个旋钮**：每关都建议改步数，看起来像"步数是唯一变量"。修法：`knobs` 补全维度，或看"备选"方案。
- **数值越调越偏**：没有回写校准，`per_unit` 一直是猜的。修法：每轮实验后更新敏感度，并在报告"假设"表里记录版本。
