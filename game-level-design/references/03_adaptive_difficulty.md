# 03｜动态难度调整（DDA）设计规范

## 1. 先判断是否需要DDA

适合考虑：
- 玩家能力差异显著；
- 玩法允许多个等价难度路径；
- 静态关卡难度已稳定；
- 有足够样本估计能力和调节效果；
- 动态调整不会破坏公平比较。

暂不适合：
- 核心体验是固定解谜/竞技公平；
- 数据量不足；
- 难度问题来自规则不清或关卡缺陷；
- 玩家会明显察觉并认为系统操纵结果；
- 线上排行榜要求相同挑战条件。

## 2. DDA三类实现

### A. 关卡间调节
根据近期表现，调整后续关卡的可选辅助、资源量或关卡变体。
优点：易解释、易回滚、不会改变当前挑战。
风险：玩家可能觉得表现好就被惩罚。

### B. 局内软辅助
在不改变核心规则的前提下提供提示、额外机会、辅助资源或可选简化。
优点：可保持关卡主体一致。
风险：辅助出现时机和可见性需谨慎设计。

### C. 实时调节
改变速度、敌人强度、生成频率等。
优点：适合连续动作类。
风险：易破坏玩家对规则的信任，且调试复杂。

## 3. 建议优先级

优先顺序：
1. 修复关卡缺陷和规则理解问题；
2. 提供玩家可选择的辅助；
3. 关卡间调整辅助资源；
4. 调整非核心压力参数；
5. 最后才考虑实时改变随机结果或核心规则。

## 4. 状态估计

建议状态至少包括：
- 长期能力估计；
- 近期表现；
- 近期失败原因；
- 玩家当前疲劳/连续游玩时长（如有可靠数据）；
- 是否使用辅助；
- 当前阶段与新机制学习状态。

不要只使用“连续失败次数”作为唯一触发条件。

示意平滑：
`skill_t = λ × recent_skill + (1-λ) × long_skill`
对近期表现进行截尾/稳健处理，降低单次异常的影响。

## 5. 触发规则示例（仅为初始假设）

| 条件 | 可选动作 | 限制 |
|---|---|---|
| 同关多次失败且失败进度接近目标 | 提供可选提示/额外机会 | 不自动改变胜负随机数 |
| 连续轻松通关 | 后续提供可选挑战目标 | 不减少基础奖励或暗中加难 |
| 新机制首次出现且误操作偏高 | 增加教学提示 | 不将其判定为能力不足 |
| 高疲劳/长会话且操作失误上升 | 提醒休息或降低非核心操作负担 | 不静默操纵结果 |

## 6. 防抖与公平

- 设置最小触发样本数；
- 设置冷却时间/关卡数；
- 设置每次最大调节幅度；
- 设置难度上下限；
- 不因一次失败立即调整；
- 不在排行榜/赛事中改变竞争条件；
- 对玩家提供可理解的辅助说明；
- 保留实验组、控制组和回滚开关。

## 7. 伪代码示例

```python
def choose_assist(player, level, state):
    if level.is_competitive or level.is_ranked:
        return None

    if state.is_new_mechanic_tutorial:
        return tutorial_hint_if_confused(state)

    if state.sample_count < MIN_OBSERVATIONS:
        return None

    if state.recent_failures >= FAILURE_TRIGGER \
       and state.failure_progress_p50 >= NEAR_GOAL_THRESHOLD \
       and state.cooldown_passed:
        return offer_optional_assist(level)

    if state.easy_wins >= EASY_WIN_TRIGGER:
        return offer_optional_challenge(level)

    return None
```

以上阈值必须由项目数据验证。`offer_optional_assist` 应是可见且可选择的辅助，而非暗中修改随机结果。

## 8. DDA评估

实验组与控制组比较：
- 关卡完成率；
- 玩家主动接受辅助率；
- 下一关继续率；
- 主观公平感；
- 退出/流失；
- 长期能力成长；
- 付费/广告变化（仅作护栏，不作为唯一目标）。

必须检查DDA是否只是把失败推迟到后续关卡，或让不同玩家体验到不公平的挑战。
