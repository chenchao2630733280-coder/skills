# 10｜跳变与异常的分类、判据与优先级

## 1. 跳变类型（相邻关卡之间）

| 类型 | 定义 | 判据 | 玩家感受 |
|---|---|---|---|
| CLIFF 跳崖 | 突然变难 | 参考分层首次通关率下降 ≥ 阈值（默认 10pt） | "怎么突然过不去了" |
| DIP 断崖回落 | 突然变简单 | 上升 ≥ 1.3×阈值 | "刚才那么难，现在这么简单？" |
| OVERLOAD 多维同升 | 多个维度同时抬升 | ≥3 个维度上升 ≥0.12，且 Δ难度分在 1.6×阈值以内 | "每样都变了，没有能依赖的旧套路" |
| MECHANIC_SPIKE | 新机制与难度上调同关 | 该关有新机制 且 通关率下降 ≥0.5×阈值 | "还没学会就被考" |
| SAWTOOTH 锯齿 | 方向反复 | 5 关内方向翻转 ≥3 次 | "难度在随机抖" |
| PLATEAU 平推 | 长期无变化 | 连续 4 关 Δ难度分 < 0.15×阈值 | "怎么打都一样" |

判据用的阈值取 `max(配置阈值, min(3×MAD, 1.6×配置阈值))`：
- MAD 让阈值自适应本战役的波动幅度，避免"整体波动大时全部漏报"；
- 上限 1.6 倍防止少数极端值把阈值抬得太高（曾出现 10pt 阈值被抬到 18.8pt，
  导致 25pt 的跳崖只算 WARN）；
- 关卡数 < 3 时不做鲁棒估计，直接用配置阈值。

## 2. 异常类型（单关层面）

| 类型 | 判据 | 说明 |
|---|---|---|
| BAND_MISS | 预测首通率偏离阶段目标 > 容差（默认 5pt） | 偏离 > 2×容差记 HIGH |
| NEAR_UNWINNABLE | 模拟最终通关率 < 0.35 | 先查可解性，而不是手感 |
| UNSTABLE | 批间标准差 > 0.09 | 同一关不同初始局面差异大，玩家体验时难时易 |
| OVERLOAD_COGNITIVE | ≥3 个维度 ≥0.7 | 认知负荷叠加，建议拆关 |
| MECHANIC_FIRST_HARD | 有新机制 且 预测低于目标带 | 教学与考核挤在一关 |
| CONFIG_OUTLIER | 参数与邻近关卡中位数偏离 >1.5× 或 <0.67× | 只对"全战役稳定"的参数检查（变异系数 ≤0.25） |
| DATA_GAP | 样本量 < 30 | 不做调参，先补样本 |
| PRED_ACTUAL_DIVERGENCE | 实际与预测差 ≥15pt 且样本 ≥30 | 先查模型与埋点 |
| BLOCKER 卡点 | 该关有 CLIFF/MECHANIC_SPIKE 且 模拟终通率 <0.65 | 最高优先级 |

### 为什么 CONFIG_OUTLIER 要按"邻近关卡 + 稳定参数"双重过滤

目标量、障碍种类这类参数本来就随进度爬坡，用全局中位数会把整条爬坡线判成离群（实测 16 关里误报 14 条）。
现在只检查变异系数 ≤0.25 的参数（步数、颜色数、时限、连击窗口），并且与前后各 3 关的中位数比。
真实项目里它抓的是"复制关卡后忘改步数"这类事故，而不是正常的设计变化。

## 2.5 量尺与结构性判据（报告第 0 节，先于一切诊断）

这五类不走 `diagnose.py`，走 `tools/cdl/audit.py`，输出在报告第 0 节与 `review.json.audit`。
它们回答的不是"哪一关难"，而是"**这套分数可不可信**"。

| 代码 | 判据 | 级别 | 处理方向 |
|---|---|---|---|
| TRIVIAL_BY_CONSTRUCTION | campaign 声明的 `dominance` 关系在某一关成立（如 `slotMax >= colors`） | **HIGH** | 该关"输"在数学上不可能发生。修复方向与"加槽提难度"**相反**：减槽 / 增色 / 加干扰 |
| DIM_CONSTANT | 某维度全战役 max−min ≤ 0.01 | WARN（<10 关降 INFO） | 等于给所有关加同一个常数，对排序无贡献；删掉、改成减分项、或换口径 |
| DIM_SATURATED | 某维度 p10 ≥ 0.90 | 同上 | 分母过小、刻度顶格，没有区分度 |
| DIM_UNDERUSED | 某维度 max ≤ 0.01，或 p90 ≤ 0.35 且 max ≤ 0.50 | 同上 | 特征没派生出来 / 分母过大，该维度几乎不参与排序 |
| SCALE_COMPRESSED | 全战役最高加权分 < 0.60（8 维满分 1.00） | INFO | 分档会全挤在低段，"用等分切档"的假设失效（与星级标定的经典错误同源） |

**为什么必须放在最前**：量尺坏了，CLIFF / DIP / OVERLOAD 只是量尺的噪声。先修尺子，再看读数。

**`dominance` 怎么写**（campaign.json 顶层，声明式，不做表达式求值）：

```json
"dominance": [
  {"lhs": "slotMax", "op": ">=", "rhs": "colors",
   "means": "槽位不少于颜色数，每种颜色都能独占一槽，数学上不可能输"}
]
```

`op` 支持 `>= > <= < == !=`。不声明则完全不检查（向后兼容）。示例见 `examples/campaign_trivial_demo.json`。

## 3. 严重度规则

- **HIGH**：超过判据 1.5 倍，或属于阻断类问题（NEAR_UNWINNABLE、BLOCKER、UNSTABLE 极端值）→ 评审不通过。
- **WARN**：达到判据但未超 1.5 倍 → 逐条复核，可带解释放过。
- **INFO**：需要人工确认意图（如 DATA_GAP）或未达 WARN 的观察项。

## 4. 处理优先级（不要按报告顺序改）

1. **可解性**：BLOCKER / NEAR_UNWINNABLE → 求解器、种子回归，确认不是无解。
2. **模型可信度**：PRED_ACTUAL_DIVERGENCE → 预测都不准时，后面的推荐一律不作数。
3. **跳变**：CLIFF / MECHANIC_SPIKE → 拆分教学与考核、单维度回退。
4. **随机性**：UNSTABLE → 查初始局面生成、极端坏局、洗牌逻辑。
5. **配平**：BAND_MISS / DIP / PLATEAU / OVERLOAD → 单变量调参。
6. **数据**：DATA_GAP → 延观察窗口，不动手。

## 5. 误报与漏报怎么处理

**常见误报**
- 刻意的缓冲关被判 DIP：在关卡 `notes` 里写明"设计缓冲"，复核时放过，并考虑把该阶段形状改成 `relief`。
- 阶段切换处被判 CLIFF：如果上一阶段未到达目标带、下一阶段直接从更高起点开始，这是目标定义问题，先修 phases。
- 平推被判 PLATEAU：确实是留白时，把连续平推控制在 3 关以内，第 4 关必须给变化。

**常见漏报**
- 分类目权重不分：用统一权重时，某品类的真实主因维度可能权重偏低（例如跑酷的操作压力），需要覆盖 `weights`。
- 维度没进模型：只填了 params 但 `feature_model` 覆盖不全，缺失维度会当 0，导致难度被低估。
- 玩家能力差异被平均：只看参考分层，会漏掉"高手觉得无聊、新手打不过"的双峰问题——同时看 `simulation.csv` 的三个分层。

## 6. 判据校准

阈值不是真理，但**不能为了让报告变绿而放松阈值**。正确做法是：
1. 收集一批已上线关卡的真实通关率；
2. 用真实通关率反推"玩家真正有感的跳变幅度"（例如流失率明显上升的那些相邻对）；
3. 用这些样本校准 `jump_winrate` / `band_tolerance`，并在 `references/12` 记录变更理由与影响范围。
