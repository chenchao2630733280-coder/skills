# 14 关卡生产路线：正向手调 / 反向生成 / 导入

> 本文回答一个问题：**关卡的"解"应该从哪里来**。
> 三条路线的差别不在用什么工具，而在"解"的来源顺序：
> 正向是"先定初盘，再看能不能玩通"；反向是"先定终局，让构造保证可解"；导入是"先定画面，再看参数上限"。
>
> 本文只沉淀**机制无关**的部分。反向生成的三个具体构造步骤（画布时间线 / 切轴 / 反向填盘拓扑）强绑定
> "拼豆-线轴"的几何拓扑，换游戏不成立，见 §7「不可搬运清单」。**别照抄，照抄就是过拟合。**

---

## 1 先判适用性，再选路线

一句话判据：**这个游戏有没有"离散、可枚举、可序列化"的局面？**

| 游戏 | 有离散局面 | 可选路线 |
|---|---|---|
| 消除 / 解谜 / 卡槽 / 拼合 / 棋盘 / 排序 | 是 | 三条都可选 |
| 跑酷 / 平台跳跃 / 实时动作 / 物理沙盒 / 音游 | 否 | **只有手调** |

为什么连续游戏不能反向生成：它没有"初盘"这个概念——位置、速度、时机都是连续量，
不存在"从终局反推出一个初始状态"的对应关系；"可解性"也不是构造能保证的，
只能靠实跑采样。**给连续游戏写生成器是这一整套方法论里最容易踩空的地方。**

| 路线 | 前提 | 解从哪来 | 主要失败模式 |
|---|---|---|---|
| 正向手调 | 关卡数少 / 教学关 / 叙事关 | 人给定 | 量大后维护成本压不住 |
| 反向生成 | 有离散局面 + 操作可逆 | **构造自带** | 唯一解（无决策）、初盘退化 |
| 导入 | 有美术稿 | 画稿投影 | 画稿决定色数/形状上限 |

---

## 2 反向生成的五步（机制无关骨架）

这是本文唯一可以跨机制搬的部分。五步里只有 ① ② 的具体表达是机制绑定的，③④⑤ 完全通用。

### ① 定终局
写"通关后屏幕长什么样"，**不是**写"通关了"。要具体到状态：哪些容器空、哪些满、哪些对象还在。

- ❌ "第 3 关，难度中等"
- ✅ "所有线轴为空、画布拼满 12×18、剩余空槽 0"

判据：终局必须能被**有限个字段**描述完，否则说明这个游戏不该走反向生成（回 §1）。

### ② 定一条合法操作序列，倒着写
不要写"我想让玩家先做 A 再做 B"，而是**从终局往前倒推每一步**，每写一步都要回答：
"这一步的逆操作，在正向规则里合法吗？"

这一步是整个方法论的枢纽：它同时产出了**关卡**和**它的解**。

### ③ 反推初盘
倒放结束时的状态就是初盘。**可解性由构造保证**——② 那条序列就是一条正解，
不需要生成完再去筛。这是反向生成相对正向的核心优势。

### ④ 校验（两条，缺一不可）
- **自证**：把初盘 + 规则交给求解器跑一遍，确认 ② 那条序列能被复现（防止 ② 写错或规则理解偏）
- **解路数**：解不唯一，或解路数 ≥ 下限。**唯一解 = 无决策**，玩家只能穷举，难度虚高而策略深度为零

第二条是本 skill 不含的能力——它需要游戏侧求解器。接口可与模拟器共用（`references/06` 的
`initial_state`/`legal_actions`/`step`），但**求解器要的是"枚举出所有解"，模拟器要的是"按策略走一条路"**，
两者不能互相顶替：模拟器跑一万次没通关，不等于无解；模拟器每次都通关，也不等于只有一条路。
没有求解器时，只能在作者手册里写死"本关解路数下限"并由人工抽查，标注为假设。

### ⑤ 测难度，进曲线
用 `tools/` 的正常流程给初盘打八维分，第 0 节量尺体检先过。反向生成的关卡在
"步骤数"这一维上天然好看，但 `strategy_depth` 经常是 0——见 §3 P3。

## 3 四条判据

| # | 判据 | 违反后果 |
|---|---|---|
| P1 | **可解性必须由构造保证**，不许把"生成后求解器筛一遍"当作唯一保险 | 那就退化成正向生成，且筛不出来的全被丢掉，产出率极低 |
| P2 | **解路数 ≥ 下限**（建议 ≥2，且两条解的"形状"不同） | 唯一解 = 没有决策，玩家体验是"试出来"不是"想出来" |
| P3 | **步骤数是难度代理，不是难度本身** | 反向生成天然可调步骤数，容易做出"很长但每步唯一"的关，难度分数高、好玩度低 |
| P4 | **初盘退化必查**：反推出的初盘若出现"某区域全空/全满/只有一种颜色" | 结构化必赢/必输（见 `references/10` §2.5 `TRIVIAL_BY_CONSTRUCTION`），量尺再好也是废关 |

P4 可以在现有工具里直接查：`tools/cdl/audit.py` 的 `dominance` 判据 + `validate_levels.py`
的 `check_dominance`，不需要新增工具。

## 4 反向生成的三个特有陷阱

### 4.1 唯一解陷阱
倒放只有一条路径，所以初盘天然"紧"——每一步都不能浪费。上线后表现为：
玩家卡住 → 试对 → 通关，但说不出为什么。

**修法**：反向生成后**主动加冗余**——补 1~2 条合法但不最优的路（多给一个空槽、多留一种可消组合），
然后用 P2 复查解路数。冗余是设计出来的，不会自己出现。

### 4.2 倒放不可逆陷阱
正着能做的操作，倒着不一定合法。典型：合并类操作（正向可合，逆向要"拆分"但规则里没有拆分）、
消耗性操作（正向消耗，逆向要凭空补回）。

**判据**：写 ② 之前先列一张"正向操作 ↔ 逆操作"对照表，**逆操作不在正向规则里的，这条路直接不适用**，
不要试图"倒推个近似"。

### 4.3 元信息丢失
终局只记了画面，没记"为什么这么摆"（主题意图、教学目的、节奏位置）。
产物是"画面像但不知道为什么要玩"的关卡。

**修法**：① 定终局时同时写一句"这一关想让人学会什么"，跟着关卡一起存进 `tag`/`note` 字段。

## 5 导入路线的上限，先算再走

画稿 → 网格是有损的，损失发生在三处：**色数被画稿决定**、**形状被网格量化**、**画稿的留白会被读成"空槽"**。

先做量化再决定要不要走这条路线：
1. 数画稿的独立颜色数 vs 游戏机制支持的颜色上限 → 超了就得合并色，画面会脏
2. 画稿分辨率 vs 网格尺寸 → 非整数倍时先降采样，看主体是否还认得出
3. 留白区域在游戏语义里是什么？空槽？背景？还是不该存在的洞？

三步里任何一步答不上来，就别走导入——**生成器变不出画稿没有的东西**，
硬走的结果是"关卡能量产，但每一关都长得像马赛克"。

## 6 换游戏时的移植检查表

逐条问，任何一条答"否"就停：

| # | 问题 | 答"否"怎么办 |
|---|---|---|
| 1 | 把机制名词全换成抽象词（对象/容器/槽/操作）后，五步还成立吗？ | 说明你以为的通用只是换词，回 §1 重判 |
| 2 | 终局能被有限个字段描述完吗？ | 不可反向生成，走手调 |
| 3 | 每个正向操作都有合法逆操作吗？ | 见 §4.2，这条路不适用 |
| 4 | 有求解器能验证解路数吗？ | 可以走，但 P2 降级为人工抽查 + 标注假设 |
| 5 | 关卡数是否 ≥ 30？ | 低于 30 关，生成器的调参成本通常高于手写 |

## 7 不可搬运清单（照抄即过拟合）

以下内容属于"拼豆-线轴"这一具体机制，**换游戏完全不成立**，本文不收录、也不要从原项目搬：

| 项 | 为什么不可搬 |
|---|---|
| 画布时间线（把画稿按时间轴切分） | 依赖"画布上一格一色"的呈现方式 |
| 切轴的两条约束 + `settleSpools` 的 `bound` | 依赖线轴这个容器的物理语义 |
| 反向填盘拓扑 | 依赖"盘面 = 网格 + 槽位"的具体几何 |
| P0–P7 引擎架构分层 | 与生成算法无关，属引擎实现 |

判断方法很简单：**把这些名词换成游戏里的对应物之后，步骤还描述得通吗？** 描述不通就是不可搬。

---

## 8 什么时候别做这条路

- **关卡数 < 30**：手写更快，生成器的调参时间收不回来
- **设计意图强**（叙事关/教学关/节奏关）：反向生成给不出"为什么这关放在这里"，这些关必须人来排
- **没有求解器**：P2 守不住，产物会偏向唯一解，而这是反向生成最容易出的问题
- **机制还在变**：规则一改，构造链全部作废，等于重做
