# 01｜难度模型库：设计规则、适用条件与边界

## 0. 模型选择原则

模型是对难度来源的解释，不是给游戏贴标签。一个关卡可以同时有多个难度来源，但应选出1–2个主导模型，并用其他模型作为补充诊断。

| 模型 | 核心问题 | 主要品类 | 常见参数 |
|---|---|---|---|
| 资源约束 | 可用资源够不够完成目标？ | 三消、合成、经营 | 步数、能量、生命、库存 |
| 搜索空间/解题复杂度 | 玩家需要搜索多少可能路径？ | 解谜、三消、数独 | 分支数、规划深度、状态空间 |
| 机制组合/认知负荷 | 玩家需要同时理解和协调多少规则？ | 三消、益智、混合玩法 | 机制数、规则例外、目标切换 |
| 操作/反应压力 | 操作精度、速度和频率要求多高？ | 跑酷、动作休闲 | 反应窗口、输入频率、容错 |
| 时间/队列压力 | 单位时间内任务负荷是否超过处理能力？ | 时间管理、经营 | 到达率、服务率、等待耐心 |
| 经济/产出效率 | 资源生产、消耗与目标需求是否平衡？ | Merge、经营 | 产出率、冷却、合成链长度 |
| 随机性/可控性 | 结果多大程度受随机影响？ | 三消、卡牌、掉落 | 随机分布、方差、可控重排 |
| 能力/项目反应理论 | 关卡对不同能力玩家的区分度如何？ | 关卡制、测评型玩法 | 玩家能力θ、关卡难度b、区分度a |

## 1. 资源约束模型

### 适用
三消步数限制、合成能量、经营库存、生命/弹药等有限资源场景。

### 核心定义
资源压力 = 目标所需资源 / 玩家可用资源。建议计算“期望需求”和“尾部风险”，不要只用平均值。

示例：
- `步数压力 = 期望所需有效步数 / 初始可用步数`
- `能量压力 = 订单预期能量消耗 / 当前可用能量`
- `库存压力 = 关键物料需求 / 可用物料`

### 设计规则
1. 先估算最优/熟练玩家需求，再估算普通玩家需求。
2. 留出合理的操作误差和随机波动空间。
3. 同时检查资源的可恢复性、补充来源和等待成本。
4. 不要把“资源不足”与“目标数量太大”重复计分。
5. 资源限制应能被玩家理解、预测和规划。

### 评估
- 资源耗尽率；
- 完成目标时剩余资源分布；
- 资源补充/续关使用率；
- 资源耗尽发生在任务进度的哪个阶段；
- 不同玩家分层的资源缺口。

### 典型失败
- 资源预算基于理想路径，普通玩家几乎无容错；
- 资源充足但目标不可达，误以为是步数问题；
- 资源补充改变经济节奏，影响长期平衡。

## 2. 搜索空间与解题复杂度模型

### 适用
需要规划、推理、找路径、组合技能或多步预判的玩法。

### 可观测近似量
- 每个决策点的合法选择数（branching factor）；
- 达成目标所需规划深度；
- 状态空间规模；
- 关键决策数量；
- 误选后恢复成本；
- 是否存在明显优势策略。

### 设计规则
1. 难度不等于选择数量；选择必须有意义且可理解。
2. 避免大量表面选择但只有一个隐藏正确答案。
3. 通过渐进方式增加规划深度，不要同时增加分支数和惩罚强度。
4. 提供足够反馈，让玩家知道策略为何有效或失败。
5. 对关键路径进行自动求解或大量模拟，检查是否存在可行解。

### 评估
- 平均决策时间；
- 撤销/重试次数；
- 关键节点错误率；
- 求解器最优解与玩家路径差距；
- 玩家主观“想不出来”评分。

### 典型失败
- 题目难但不清晰；
- 唯一解依赖玩家无法推断的信息；
- 随机因素淹没策略价值。

## 3. 机制组合与认知负荷模型

### 适用
新障碍、新规则、多目标、多机制组合的关卡。

### 机制生命周期
`引入 → 示范 → 单机制练习 → 变化练习 → 机制组合 → 精通考核`

### 设计规则
1. 新机制首次出现时，减少其他同时变化的维度。
2. 先让玩家理解机制，再要求策略优化。
3. 每个关卡设定一个主要学习目标。
4. 组合机制前，确保玩家已分别理解每种机制。
5. 区分“规则复杂”与“策略深”：复杂规则不必然产生有趣挑战。
6. 对视觉提示、术语、反馈和规则例外进行可理解性测试。

### 评估
- 新机制首次尝试成功率；
- 教学提示触发率；
- 规则理解问卷；
- 错误操作类型；
- 机制使用率；
- 首次出现关卡的退出率。

### 典型失败
- 同一关引入多个陌生规则；
- 视觉表现无法解释规则；
- 玩家失败是因为不知道规则，而非不会解决问题。

## 4. 操作与反应压力模型

### 适用
跑酷、轻动作、节奏、点击速度、拖拽精度等玩法。

### 参数
- 反应窗口（ms）；
- 输入频率（actions/min）；
- 连续操作时长；
- 容错范围；
- 目标尺寸与可点击区域；
- 操作切换频率；
- 失败惩罚。

### 设计规则
1. 难度应逐步压缩反应窗口，而不是突然跳变。
2. 先教会动作，再提高速度或组合复杂度。
3. 考虑触屏误差、帧率、延迟、单手操作和无障碍需求。
4. 对高频操作设置疲劳护栏。
5. 关键失败必须能归因于玩家可理解的操作，而非输入判定不稳定。

### 评估
- 输入成功率；
- 反应时间分布（中位数与P90）；
- 误触率；
- 连续失误次数；
- 不同设备/帧率下的表现差异。

## 5. 时间与队列压力模型

### 适用
餐厅、整理、顾客服务、订单处理、多任务管理。

### 核心变量
- 到达率 λ（单位时间任务/顾客数）；
- 服务率 μ（单位时间完成任务数）；
- 队列长度；
- 顾客耐心/截止时间；
- 任务切换成本；
- 并行任务数量。

在稳定、简化的单队列系统中，可用 `ρ = λ / μ` 作为负荷率的粗略指标。ρ接近或超过1时，队列可能持续增长；真实游戏通常有优先级、批处理和多服务台，需模拟验证。

### 设计规则
1. 新增顾客频率时，不要同时大幅提高订单复杂度。
2. 让玩家看得懂优先级与失败倒计时。
3. 区分手速压力与路线/排程策略。
4. 检查高峰时段是否存在理论上无法服务的状态。
5. 用模拟器覆盖不同操作效率玩家。

### 评估
- 超时率；
- 平均/最大队列长度；
- 顾客满意度；
- 任务切换次数；
- 单位时间有效操作；
- 关卡结束时未完成订单数。

## 6. 经济与产出效率模型（Merge/经营）

### 适用
合成链、生产器、冷却、订单、资源循环。

### 核心量
- 目标物品的合成路径长度；
- 生产器单位时间产出；
- 冷却时间；
- 能量消耗；
- 棋盘占用格数；
- 订单需求与产出分布；
- 稀有物品的期望等待时间。

### 设计规则
1. 同时评估能量压力和棋盘空间压力。
2. 不能只按合成层级估难度，还要计算生成器可用性和随机产出。
3. 检查订单是否造成空间死锁或长期阻塞。
4. 评估玩家是否有替代路径或可规划的生产顺序。
5. 随机产出需看期望值和尾部等待风险。

### 评估
- 完成订单所需时间；
- 单订单能量消耗；
- 生成器利用率；
- 棋盘占用率/P90；
- 阻塞/出售低价值物品比例；
- 关键物品等待时长。

---

## 7. 随机性与可控性模型

### 适用
随机棋盘、掉落、发牌、生成器产出、随机事件。

### 设计规则
1. 区分“不可预测”与“不可控”；玩家可以接受未知，但需要合理影响结果。
2. 检查随机分布是否导致极端坏局。
3. 同时评估均值、方差、P10/P50/P90，不只看平均值。
4. 为关键目标设置最低可行性保障或可恢复机制。
5. 若使用保底/洗牌/补偿机制，明确触发条件和公平性影响。
6. 不要为提高付费而暗中操纵玩家输赢。

### 评估
- 不同随机种子的通关率分布；
- 极端坏局比例；
- 随机因素对胜负的解释度；
- 玩家可控操作对结果的边际影响；
- 可解率/软锁率。

## 8. 玩家能力与关卡测量模型

### 简化能力分
可将玩家近期表现标准化为能力估计，但需做平滑和分层：
`θ_t = λ × θ_recent + (1-λ) × θ_long`
其中 λ 由数据验证，不能随意宣称固定最佳值。

### IRT/Rasch思路
对于二元通关结果，可先参考 Rasch 模型：
`P(pass) = 1 / (1 + exp(-(θ - b)))`
- θ：玩家能力；
- b：关卡难度参数。

若数据支持，可使用2PL：
`P(pass) = 1 / (1 + exp(-a(θ - b)))`
- a：关卡区分度。

注意：
- 模型假设需要检查（单维性、局部独立等）；
- 关卡尝试存在选择偏差（玩家可能不尝试某关）；
- 道具、付费续关、随机种子和玩家学习会影响结果；
- 不应将IRT输出直接用于实时惩罚玩家。

### 使用场景
- 关卡难度排序；
- 玩家分层；
- 识别异常难关；
- 估计不同能力群体的通过概率。
