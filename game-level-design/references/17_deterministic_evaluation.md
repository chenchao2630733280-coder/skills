## 0. 一句话

难度评估的「科学性」不在公式漂亮，而在三件事：

**判定可复现 · 指标可证伪 · 闸门有牙齿。**

三者任一缺失，报告里的数字就只是文采。

## 1. 抽样通关率为什么不能当难度

不是"不够准"，是**方向错**——它测的是"机器人的运气"，不是"关卡的难度"。

| 硬伤 | 实测证据 | 后果 |
|---|---|---|
| **不可复现** | 同一条命令、同一份关卡数据，当天跑出过 `0.94→0.51`、`0.48→0.55`、`0.78→1.00` 三组互斥曲线 | 报告互相矛盾，无法作为门禁判据 |
| **不单调** | 换一组种子，同一关从 0.30 跳到 0.90 | 两关差值小于抽样噪声时，"谁更难"说不清 |
| **混了两个变量** | 结果同时受「关卡结构」与「机器人抽签」影响 | 改一个槽位要重跑 40 局才知道变了多少 |
| **不可比** | 每关的样本独立，方差不同 | 排序不可信，曲线全是毛刺 |

**处置**：这类数字一律标 `DEPRECATED_SAMPLING`，**不得进入 gate 判定**，只能在
`docs/LEVEL_PLAN.md §5` 里作为历史包袱解释一句。

**什么时候仍可以用抽样**：状态不可枚举、含随机发牌或连续动作的游戏（跑酷、动作、三消发牌）。
但那时它只能做**风险筛查**（发现明显不可能过的关），不能做判定；判定要锚定真实数据
（见 `02` / `05` / `06`）。判据只有一条：**能不能把"初盘→终局"枚举出来**。
能枚举 → 走本文；不能枚举 → 走 `02` 的抽样口径，并在报告头写明 `tier: sampled`。

## 2. 三层结构：证明 / 判定 / 排序

| 层 | 回答的问题 | 量的类型 | 工具 | 能否否决别的层 |
|---|---|---|---|---|
| **L0 可解性** | 存在通关路径吗？ | 三元：可解 / 不可解 / 未知 | 求解器 | **否决一切** |
| **L1 决策性** | 需要动脑，还是照着点就行？ | 二元：PASS / FAIL | 确定性策略对局 | **否决 L2** |
| **L2 难度序** | 谁更难、该怎么编号？ | 连续分 | 静态结构分 | **不得否决 L0 / L1** |

### 三条铁律

1. **判定只认 L0/L1，排序只认 L2。** L2 分很高但 `naive` 能过 → 仍然 FAIL。
   分数高只说明"乱点会死得快"，不说明"需要决策"。
2. **L0 未定则 L1/L2 的数字无意义。** 无解关的"难度分"描述的是一个不可能发生的事件；
   逐关调参没有意义，先修结构。
3. **参考列的失败不构成证据。** `strict`（会看但不做计划）输在打球风格，不在关卡；
   它失败只能触发"去查"，不能触发"改关"，更不能推出"无解"。

> 历史事故：L02 / L08 都被贪心策略判成死局，实际都有 12 步解。把参考列当判据，
> 会把好关卡改坏，而且越改越水。

## 3. L0 可解性证明规格

### 3.1 三级强度，措辞不能混

| 做法 | 结论强度 | 报告里**必须**这么写 | 不许写 |
|---|---|---|---|
| 确定性贪心找到一条线 | **可解**（构造性证明，附 N 步 witness） | `solvable: witness(N=12)` | "应该能过" |
| 有界穷举，预算内**穷尽**所有分支仍无解 | **不可解**（确定） | `unsolvable: exhausted(nodes=417)` | "很难" |
| 有界穷举，预算用尽 | **未知** | `unknown: budget_hit(400/400)` | "不可解" |

"未知"是合法结论。**把未知写成不可解，是这一层最常见的伪证。**

### 3.2 四条实现纪律

1. **witness 必须可回放**：拿到解后，在**真实 core** 上逐步 `apply`，每步校验合法性，
   最后确认 `state == victory`。不接受只在搜索抽象态里成立的解。
2. **状态去重 key 必须含全部影响合法动作的字段**。漏一个字段 = 假剪枝 = 假的"穷尽" = 假无解。
   加字段宁可慢，不要漏。
3. **预算与结论分开记**：`nodes_used` / `budget` / `budget_hit` 三个字段都要落地，
   否则半年后没人知道那个"不可解"是真结论还是预算不够。
4. **唯一实现在真实 core 上**：搜索里不许再写一份 `isLegal` / `apply`。
   两份规则迟早分叉，那时闸门验的不是游戏。

### 3.3 为什么不能只靠贪心

贪心失败有两种可能：关卡真无解，或它不会玩。二者**不可区分**，所以贪心失败
**只触发穷举，不直接下结论**。这条纪律看起来慢，实际是整个评估体系的地基——
地基塌了，后面的分数、排名、星级全都建在流沙上。

## 4. L1 三态闸（判定层）

### 4.1 三个策略，各代表一个人

| 策略 | 行为 | 代表谁 | 用途 | 进不进判据 |
|---|---|---|---|---|
| `naive` | 永远点"列表第一个可点项"，不看颜色/不看后果 | 看到亮的就点 | 判**有没有决策** | **进** |
| `strict` | 只做此刻确定有产出的动作，没有就等，绝不投资 | 会看但不做计划 | 参考列 | 不进 |
| `greedy` | 有活干就干；一张都干不了才投资一张"最接近能开工"的 | 会看也会算 | 找 witness、量入口宽度 | 不进（仅触发穷举） |
| `golden` | 走求解器给的那条 witness | 知道答案的人 | 最优线步数/峰值/星级可达性 | 不进 |

一局一跑、**无随机数**：结果固定，同一关同一天跑两次一字不差（计时除外，见 §6.1）。

### 4.2 判据组合

| `naive` | 可解性 | 结论 | 动作 |
|---|---|---|---|
| 死 | 可解 | **PASS** | 有决策，进 L2 排序 |
| 过 | 可解 | **FAIL（无决策）** | 动结构，不动数值（见 §8 第 1 行） |
| 死 | 不可解 | **FAIL（死局）** | 必死不是难度，是 bug |
| 死 | 未知 | **BLOCKED** | 加大穷举预算，不许调参过关 |

### 4.3 豁免必须登记

教程关允许 `naive` 通过（要让玩家先赢一次），但：

- 必须在 `docs/LEVEL_PLAN.md` 逐关登记 `level_id + 理由`；
- 豁免总数 **≤ max(1, ⌈10% × 关卡数⌉)**（8 关时允许 1 关；**写"≤10%"会在小关卡数下自相矛盾**——
  1/8 = 12.5% 就超了，等于把教程关逼成违规）；
- 且只能是序列前段；
- 豁免关**不得**计入"闸门通过率"的分母美化（报告要分别写 `豁免 N / 实测 M`）。

未登记的豁免一律按 FAIL 处理。**"这关是教程"是最容易被拿来讲故事的借口。**

### 4.4 `golden` 顺带回答一个常被忽略的问题

最优线的**整局峰值占槽**决定星级阈值是否可达。若 `golden` 的峰值是 5，
而 3★ 要求"峰值 ≤ 半桌"（6 槽关要求 ≤ 3），那 3★ 永远达不到——
**这时错的是星级阈值，不是关卡**。这类"结构性不可达"必须在 L2 之前修掉，
否则所有玩家都在追一个不存在的目标。

**但峰值必须取"最优线的峰值"，不是"随便哪条线的峰值"。** 常见错误：拿贪心求解器
找到的**第一条**获胜线当 `golden`。贪心在没活干时会反复投资"要等"的单元，一口气把容量占满，
峰值被它自己抬高 —— 实测同一关贪心 4 峰、带一步前瞻的策略 2 峰，于是 3★ 被误判成
"结构上不可能"。做法：跑齐手上所有确定性策略，**取获胜局里峰值最低的那条**，并记录是谁跑出来的。

**反向的话不许说**：这样得到的只是**上界**（"有人做到过 ≤k"）。要说"这关做不到 k"
需要下界证明，即带峰值上限的搜索（剪掉超限分支）—— 那玩意儿每个节点都要整局重放，
实测 54ms/节点，几十张单元的关卡是分钟级，进不了 CI。所以结论只能写
**已证 / 未证**，绝不写 **可达 / 不可达**。预算用尽 ≠ 不可能。

## 5. L2 结构压力分（只做排序）

### 5.1 公式形态

```
容量 C  = 待处理单元数 / 并发上限        （槽位是血条，单元是一件件塞进去的货）
陷阱 T  = 最长"无产出消耗"段 / 并发上限   （点进去连任务都起不来，只占容量）
压力分  = C × (1 + T)                     → 跨关卡按最大值归一化到 100
```

只读内容 JSON，**不跑模拟、不带随机**：改完立刻能看曲线，秒级。

### 5.2 迁到别的品类：先找两个物理载体

公式本身可搬，**分量定义必须重推**。找不到载体说明这个品类不该用它。

| 载体品类 | C（容量） | T（陷阱） | 陷阱的物理定义 | `naive` 的走位 |
|---|---|---|---|---|
| 卡槽归集（本项目） | 卡片数 / 槽位数 | 最长死卡段 / 槽位数 | 该颜色此刻在棋盘上零暴露面 | 按 `shift_mode` 逐列点穿（**不是**只数第一排） |
| 步数消除 | 目标需求 / 步数 | 无效步占比 | 落下既不消除也不开路 | 固定点最左可行格 |
| 层叠依赖（拆螺丝/遮挡） | 待拆件数 / 并发位 | 开局点不动件 / 并发位 | 被上层压住、无暴露面 | 永远点列表第一项 |
| 波次防守 | 波次数 / 并发接待位 | 空转波占比 | 该波无法产出资源 | 无脑放最便宜单位 |

### 5.3 三条配方纪律

1. **与 T 高相关的量只做诊断列，不进公式。** 例：埋深 D 与 T 高度相关（前排是深色时 T 自然高），
   乘进去等于把同一现象算两遍，还会让"层次复杂但操作轻松"的关被误判为难关。
2. **归一化基准会漂移，绝对值不可跨版本直比。** 基准由"当前最大值"决定，加一关就可能整体缩放。
   跨版本只比**相对序**与**分段比值**（如"中段均值 / 后段均值"）。报告必须写明基准版本。
3. **分数不参与判定。** 见 §2 铁律 1。

### 5.4 单向不等式（背下来）

- `T ≥ 1` ⇒ `naive` 必死（塞满即判负）：**充分条件**。
- `T < 1` **不保证** `naive` 能活：这只是必要条件没被满足。

这条只能往一个方向读。把它当充要条件用，会让一堆"其实没决策"的关混过闸门。

**而且 `T ≥ 1` 的前提是：那一段陷阱真的在走位最前面。** 这是本体系最贵的一个坑：

- "死卡 / 点不动的单元"的定义是**开局**零暴露面。它只说明开局动不了，
  **不说明走到那一步时还动不了** —— 只要清掉任一种邻接内容，它就露出面了。
- 而 `naive` 走位是**列优先**，走到第 k 位时前面已经清掉好几整列。于是后置的陷阱段
  在它到达时往往已经失效，`T` 描述的是一个从未发生的事件。
- 实测（把前置单元全部清掉、在残局上重算腐蚀）：偏 1~5 位放陷阱，八关**全部**"被救活"。
  当时 `naive` 照样会死，但死在"临时堵满"而不是陷阱上 —— **逐关判定全绿，错的是归因**。

**自查手段两个，都要有**：

1. 构造期：`dead_offset` 必须为 0，脚本里硬断言（前置为空 ⇒ 无内容被清 ⇒ 确实零暴露
   ⇒ `并发上限` 个一填满就再也出不来）。可证明，不靠运气。
2. 校验期：加一条不变量 **"从第 0 位起连续动不了的个数 == 全图最长动不了的连续段"** ——
   两者只在"段在最前面"时相等。同一概念的两次测量**必须钉在一起**，
   否则会像本项目那样：一个指标报 0、另一个报 4，同一个谎被量了两遍却没人对比。

前置的可证明版有个好看的副产品：`naive` 会**恰好在第 `并发上限` 步**死，一个不多一个不少。
读数整齐到这种程度，通常说明构造对了；飘在 5~8 步之间，往往说明归因有问题。

## 6. 科学验收五项

**这一节是"科学"的全部内容。** 每项都要在报告里留证据，不能只写"已检查"。

### 6.1 可复现（Reproducibility）

| 项 | 内容 |
|---|---|
| 做法 | 同一输入连跑**两次**，逐字段比对（用 `tools/repro_check.py`） |
| 判据 | 决策字段逐一相等；**计时字段除外** |
| 失败处置 | 指标作废，先修随机源（未播种 rng / 字典哈希序 / 目录遍历顺序） |

**陷阱**：直接 `cmp` 两个输出文件必然报"不一致"——`ms` 计时差 4 字节（实测 `12781` vs `12777`），
那是计时不是逻辑。必须**按字段比、剔计时**。把计时当逻辑，会逼着团队去"修"一个不存在的不确定性。

### 6.2 单调（Monotonicity）

| 项 | 内容 |
|---|---|
| 做法 | 单旋钮扫描：槽位 `+1` / 单元数 `-2` / 抽掉死卡段，每步重算分数 |
| 判据 | 任一"放宽"操作必须使分数**单调不增**；反之亦然 |
| 失败处置 | **不是关卡错，是公式错**——配方里有抵消项 |

这条是"改一个参数能不能预测结果"的唯一保证。没有它，调参就是碰运气。

### 6.3 可分（Discrimination）

| 项 | 内容 |
|---|---|
| 做法 | 看全量分数分布：极差、分位、**相邻两关差值** |
| 判据 | 确定性口径下噪声为 0，相邻差必须 `> 0`；且不能全部挤在一点 |
| 失败处置 | 某个维度恒定 / 顶格 / 未参与 → 回到 `02` 的"量尺体检"，先修尺子 |

### 6.4 可证伪（Falsifiability）

| 项 | 内容 |
|---|---|
| 做法 | 给**每个**指标写一句"什么观测会推翻它" |
| 判据 | 这句话必须能被现有工具产出（不是思想实验） |
| 失败处置 | 写不出 = 该指标是叙事，删掉 |

示例（可直接抄）：

- 压力分声称衡量"容错压力" → **若高分关 `naive` 能过，则指标失效**。
- 陷阱 T 声称"T≥1 则必死" → **若某关 T≥1 而 `naive` 存活，则 T 的定义与走位不同源**。

### 6.5 锚点校准（Anchor Validation）

| 项 | 内容 |
|---|---|
| 做法 | 取**公认最难**与**最易**的两端关卡作锚点，看公式给的序是否一致 |
| 判据 | 端点序反了 ⇒ 公式失效（**不是关卡错**） |
| 失败处置 | 重推分量，不要改关卡去迁就公式 |

**实证**：某调研给出的经验公式「依赖深度 × 颜色交叉度 ÷ 有效容量」直接搬到另一个同品类游戏上，
给"只需点 5 次"的关打 12 分、给"要点 56 次"的关打 25 分，**结论正好相反**。
原因：该公式只覆盖"看颜色顺序"这一个难度载体，而那个游戏的难度有两个独立载体。
→ 跨作搬运公式前，必须先用锚点验一遍。

## 7. 口径治理（换代码时最容易被忘的一步）

1. **一次只允许一套口径在线。** 旧口径必须在文档顶部写墓志铭：作废日期 + 为什么 + 现行口径指向。
   三条口径并存是最常见的引用事故（"报告说 0.94，代码跑出 0.48，谁在说谎？"——都没说谎，是版本不同）。
2. **代码里可以保留旧参数，但只许打印废弃警告，不许再产出数字。** 例如 `--samples` / `--policy=random`
   能被解析但只输出 `DEPRECATED`。留着入口是为了不让老脚本报"未知参数"崩掉，不是为了继续用。
3. **报告头必须四件套**：`tier`（deterministic / sampled / telemetry）、`metric`、`归一化基准版本`、`数据来源`。
4. **换代后要写清"哪一条对应现在的代码"**：`A 口径 → B 口径 → C 口径`，只有最后一条有效。

## 8. 病征 → 处置

| 病征 | 说明 | 处置 |
|---|---|---|
| 全关 `naive` 都过 | 没有决策 | **动结构不动数值**：拆细单元、加数量、收容量、造无产出段 |
| `naive` 死在第一步 | 开局不可读 | 调**入口宽度**（开局可用色数 / 前排活卡数），不是降难度 |
| `T ≥ 1` 但 `naive` 没死 | 不等式只单向 / 走位不同源 | 查 `naive` 的走位顺序与 `shift_mode` 是否同一套 |
| 分数很高但可解性未知 | 无解关 | 先证明，再谈分数 |
| 分数序与体感相反 | 锚点失配 | 重做 §6.5，别改关卡 |
| 相邻关分数塌陷 > 40% | 断崖 | 查是否复制关卡未调 / 刻意缓冲未登记 |
| 最高分关不是最后一关 | 编号没按分排 | 按压力分重排，不按制作顺序 |
| 关卡全可解、`naive` 死、仍不好玩 | 这是引导/反馈问题 | 别在难度层修，去找教学与提示 |

## 9. 局限（写进报告，不要藏）

- 结构分只衡量**容错压力**（乱点会多快死），**不衡量思考深度**，与"好不好玩"无关。
- 证明只证"存在解"，不证"人类想得到"——那是引导、反馈、教学关的事。
- 只适用**离散可枚举**局面；连续动作游戏没有"初盘→终局"的反推关系，别硬套。
- 归一化后的绝对值不可跨版本直比。
- 规模上限：离散穷举随状态空间指数增长，超过几千节点后"未知"会成为常态——
  那时要么裁剪搜索（分层/子目标分解），要么接受"未知 + 人工复核"。
