# Game Teardown — 游戏复刻拆解

本 skill 是 AI 游戏生成流水线的**阶段 0.5（复刻专线）**。当用户的需求不是"从 0 想一个游戏"，而是"**照着某款游戏做**"时，先经本阶段把参考游戏拆成**产品系统**，再交给 `game-blueprint`。

**一句话原则**：先拆「循环—规则—数值—内容—交互」，再拆「表现—技术—运营」；先做可玩核心，再换高保真表现；**只学结构与参数，不搬素材与表达**。

**与相邻 skill 的边界**：

| skill | 职责 | 不做 |
|---|---|---|
| `game-topic-brainstorm` | 从 0 找选题（无参考对象） | 不拆具体游戏 |
| **本 skill** | 把**已有游戏**拆成可复刻的系统与参数 | 不产出蓝图、不写代码、不判断"好不好玩" |
| `game-blueprint` | 把拆解结论收敛成一页纸蓝图 | 不做拆解 |

---

## 一、何时调用

**调用**（满足任一）：
- 用户点名一款参考游戏，要"复刻/对标/仿制/做成一样的/换皮"
- 用户给录屏、截图、试玩描述，要求"按这个做"
- 用户要"拆解竞品，做差异化版本"
- `game-forge-master` 识别到需求含参考对象并路由到本阶段

**不调用**：
- 从 0 脑暴选题 → `game-topic-brainstorm`
- 用户已有明确玩法、无需参考 → 直接 `game-blueprint`
- 只想听"这游戏值不值得玩/好不好玩" → 对话回答即可
- 要改已有工程代码 → 直接 Edit/Write

---

## 二、输入与输出

**输入**：
- 必需：参考游戏标识（名称 / 录屏 / 截图 / 试玩记录，至少一种）
- 可选：复刻档位（T0~T3）、目标平台、工期预算、必须保留的原作特征、必须改掉的差异方向

**输出**（固定路径，3 份，缺一不可）：

| 产物 | 路径 | 读者 | 作用 |
|---|---|---|---|
| 拆解报告 | `docs/GAME_TEARDOWN.md` | 人 + 下游 skill | 12 维结论、循环图、判定依据 |
| 复刻矩阵 | `docs/TEARDOWN_MATRIX.json` | 机读 + 质量门 | 每条结论的三色/证据/敏感度/MVP 归属 |
| 数值模型 | `docs/NUMERIC_MODEL.csv` | Excel/Sheets + `game-spec` | 参数、区间、公式、证据等级、来源 |

**材料不足时的处理**：用 AskUserQuestion 只问 1 轮（档位 + 材料补齐方式）；仍不足则按 **T1 + 结构级拆解** 执行，并在报告 §14 明确列出盲区与证据覆盖率，**不得虚构数值**。

## 三、第一原则：复刻不是复制（三色判定）

拆解结论的每一条都必须打上三色标签，否则视为未拆完。

| 标签 | 含义 | 判定问句（任一命中即归此类） | 处理 |
|---|---|---|---|
| **M / Must** | 必须复刻的核心 | "去掉它，玩家还会说这像 XX 吗？" → 不会 | 进 MVP，按原版参数尽量贴 |
| **S / Swap** | 可替换的表现 | "它决定这是'XX 的什么皮'，而不是'这是不是 XX'" | 可原创，是差异化的主战场 |
| **X / Cannot** | 禁止复制的表达 | 属于受保护表达：具体美术/音频/代码/文本/角色名/商标/关卡地图排布 | **必须写出替代方案**，否则 Gate 直接 FAIL |

**硬规则**：
1. 每个维度至少 1 条 **M**——只有 S 说明没拆到核心。
2. 每个 **X** 必须有 `replacement` 字段（合法替代手法），空即 FAIL。
3. **M/S/X 与"重要程度"无关**：X 项可能极其重要（如核心 UI 布局），但它仍然不能抄，只能"换一种方式达到同样效果"。
4. 复刻档位只改 M 的数量与深度，**不改变 X 的边界**（任何档位都不能抄素材）。

---

## 四、复刻档位 × 拆解深度（先定档，再决定拆多深）

不区分档位就全维度拆到公式级，是最常见的浪费。

| 档位 | 定义 | 拆解深度 | 交付判据 |
|---|---|---|---|
| **T0 学习原型** | 只复刻核心玩法循环 | 循环 L2，规则 L1，数值 L1（仅区间），表现全 S | 能跑通"一次完整循环" |
| **T1 玩法克隆** | 规则/系统/数值接近，表现原创 | 循环 L2，规则 L2，数值 L2，内容 L1 | 老玩家上手能认出同一玩法 |
| **T2 高保真复刻** | 连交互节奏、关卡节奏、UI 信息结构都接近 | 全部 L2，关键项 L3，交互 L3 | 前 5 分钟体验节奏与原作同构 |
| **T3 商业产品** | 追加商业化/运营/合规 | T2 + 经济与付费 L2~L3 + 运营节奏 L1 | 有可运营的数值与付费结构 |

**深度分级**：

- **L1 结构级**：有哪些模块、先后顺序、界面层级、存在与否
- **L2 区间级**：数值范围、时长、频率、概率量级、难度节奏
- **L3 公式级**：曲线形状、伤害/成长公式、掉落权重分布、经济闭环平衡点

**两条约束**：
1. **深度上限由可观测性决定**（见 §六），不可观测的维度拆到 L3 就是编造。
2. **只有高敏感项才值得 L3**（见 §七）。给玩家感知不到的参数做 L3 是自嗨。

## 五、12 维拆解流程（4 个 Pass）

按"可玩核心优先"排序，**不允许先拆表现层**。

### Pass A — 循环与规则（维度 2、3）

| 拆什么 | 方法 | 产出 |
|---|---|---|
| 玩家目标、30 秒/5 分钟/1 小时各做什么 | 录屏按时间轴切片，标"操作—反馈—奖励" | 三时间尺度表 + 循环图（Mermaid） |
| 输入→反馈→奖励→成长→新挑战闭环 | 画闭环，找断点（哪里会让玩家想退出） | 循环图 + 断点清单 |
| 失败与重试成本 | 计时：死亡到重开几步/几秒/损失什么 | 重试成本表（决定留存下限） |
| 核心乐趣排序 | 操作 / 策略 / 成长 / 收集 / 社交 / 叙事 | 乐趣权重（决定 M 项取舍） |
| 系统模块（属性/战斗/建造/AI/成长/多人） | 每系统填"输入、状态、规则、输出、边界" | 系统表（6 字段不得缺） |

**产出物要求**：核心循环图 + 一次循环的时长与步数（可被 `game-spec` 直接换算成关卡节奏）。

### Pass B — 数值与内容（维度 4、5）

- 属性/伤害/命中/暴击/护甲公式族，成长与经验曲线，掉落权重与保底
- 资源产出/消耗闭环、货币层级、体力与冷却
- 关卡结构、波次、敌人配置、机关、难度峰值位置、教学关设计
- **只学"节奏与结构"**：关卡的具体地图排布、剧情文本、角色设定属 X

方法：录屏逐帧统计 → 控制变量实测 → 公式族反解 → 拟合 → 建 CSV 模型 → 敏感度分析。
详见 `references/numeric-reverse-engineering.md`。

### Pass C — 交互与表现（维度 6、7）

- 屏幕信息层级（HUD/菜单/背包/地图/结算）、操作路径长度（点到目标几步）
- 反馈密度：打击感（顿帧/位移/闪白）、飘字、音效触发点、震动、动画时长
- 引导流程、错误提示、加载与存档、失败反馈
- 美术风格坐标系（色相/明度/饱和度范围、比例、线宽、镜头）、动画节奏、叙事结构

**拆法**：逐屏截图 → 页面流程图 + 交互状态机（每个界面的"进入/空/满/错误/退出"五态）。
表现层**全部默认 S**，只把"反馈密度与节奏"当 M（这是玩家觉得"手感像不像"的真正来源）。

### Pass D — 工程与商业（维度 1、8、9、10、11、12）

- 引擎/客户端架构/数据驱动/存档/联机/服务器/性能指标（多为不可观测，见 §六）
- 配置表结构、编辑器需求、埋点、构建与热更、调试命令
- 测试与调优：功能边界、平衡、可玩性、性能、回归
- 合规与伦理（硬门，见 §八）
- 运营与商业化：付费点、活动节奏、留存/转化指标（仅 T3）

**原则**：技术维度**不还原原实现**，只保证"行为等效"；能观测到的只有表现与节奏，架构一律标 O3。

## 六、证据分级与可观测性（防编造，本 skill 的核心闸门）

AI 做逆向拆解最大的失败不是拆不全，而是**把推断写成事实**。

### 6.1 证据等级（每条数值/结论必带）

| 等级 | 定义 | 举例 |
|---|---|---|
| **E3** | 实测或可交叉验证的公开数据 | 自己控制变量试 20 局取分布；官方wiki/攻略站公式；补丁说明 |
| **E2** | 采样统计 | 录屏 10 局，逐帧统计单局时长/敌人数/掉落频率 |
| **E1** | 合理推断 | 同类游戏公式族 + 参数反解，能解释已观测现象 |
| **E0** | 猜测 | "应该是这样"、没有样本、无法解释反例 |

### 6.2 可观测性（每个维度必标）

- **O1 直接可见**：循环、UI、表现、关卡结构、反馈
- **O2 可统计推断**：数值区间、节奏、概率量级、经济产出速率
- **O3 不可观测**：服务端匹配、掉落权重真值、付费算法、反作弊、架构

### 6.3 硬规则（违反即 Gate FAIL）

1. **进蓝图的数值必须 ≥E2**；E0/E1 只能进报告 §14「待验证清单」，并写清验证方法与成本。
2. **O3 维度只写"行为等效设计"**，禁止写"原作是如何实现的"。句式：`原作效果可观测为 X → 复刻采用 Y 达到等效`。
3. 每条数值必须带 `source`：帧号区间 / 样本局数 / 链接 / 实测次数。**没有来源的数字不许进 CSV。**
4. 不确定就写**区间**（`0.8~1.2s`），不写单点精确值（`0.97s`）。
5. 禁止"看起来差不多"作为证据；禁止用"业界惯例"替代观测。
6. 证据覆盖率（达到 E2 及以上的维度数 / 12）必须写进报告 §0 摘要，**低于 60% 要在报告首行标红提示**。

## 七、敏感度排序（决定"像不像"的真旋钮）

拆完 12 维不等于每项都值得复刻。必须再收一刀：

1. 从所有 **M** 项里挑 **3~5 个**"决定辨识度"的变量（去掉它就不像了）。
2. 每个打 `sensitivity: high / mid / low`，写一句"为什么高"。
3. 规则：
   - **high** → MVP 必做，参数贴原作（E2+）
   - **mid** → MVP 做简化版
   - **low** → 允许大改，**同时构成差异化锚点**
4. 复刻必须有**至少 1 个原创差异点**（题材/叙事/一个新机制/一个新反馈层），写进矩阵 `differentiation`。这既防"换皮混淆"，也防做出来只是个廉价复制品。

典型高敏感项（按品类参考，需实测确认）：操作响应延迟、单局时长、反馈密度（每秒事件数）、失败惩罚力度、成长可见速度、随机性的可解释度。

## 八、合规红线（硬门，无替代方案即阻断）

三层边界（细则见 `references/legal-clone-boundary.md`）：

| 层 | 内容 | 处理 |
|---|---|---|
| ✅ 可学 | 玩法机制、规则逻辑、数值结构、操作方式、循环结构、品类惯例 | 直接复刻（M） |
| ⚠️ 需改写 | UI 的具体视觉排版、关卡的具体布局、文案结构、镜头与配色方案 | 学"目标"不学"具体解"，重做一套（S） |
| ⛔ 禁止 | 美术素材、音频、代码、商标、角色名与设定、剧情文本、逐格复制的地图 | 必须原创替代（X） |

**换皮混淆自检（命中 ≥2 条即高风险）**：同题材 + 同美术风格 + 同 UI 布局 + 同角色名/术语 + 同关卡顺序。

**产出要求**：`TEARDOWN_MATRIX.json` 中**所有 `class = X` 的条目必须带 `replacement`**（X 清单一律从 `items[]` 派生，不另存一份，避免两份口径漂移）；报告 §11 给出风险评级（低/中/高）与"发布前需法务确认项"。本 skill **不提供法律意见**，商业发布须咨询律师。

## 九、灰盒 MVP 裁剪规则

复刻的返工大头是"先做表现、后发现循环不对"。裁剪顺序固定：

| 类别 | 处理 |
|---|---|
| M 且 high 敏感 | **必进 MVP**，灰盒实现（几何/色块/文字），参数贴原作 |
| M 且 mid/low 敏感 | 进 MVP 但简化（少关卡、少单位、少特效） |
| S 表现层 | 全部**占位**（纯色块 + 文字标签 + 静音） |
| X 禁止项 | 用原创替代方案，MVP 期可用更简陋的替代 |
| O3 不可观测 | 用"行为等效"最小实现（如本地伪匹配、固定掉落表） |

**MVP 一句话定义模板**：`能验证「{核心循环}」的最小可玩切片：{1 个关卡/1 种单位/1 条成长线}，其余全部占位。`

**验收**：MVP 必须能连续玩 3 分钟不出现"卡住/空白/无反馈"，且 3~5 个高敏感项可被肉眼辨认出与原作同构。

## 十四、反模式（出现即返工）

1. **只拆画面和玩法**：跳过数值与节奏，做出来"看着像，玩着不像"。
2. **把推断写成事实**：没有样本也给出精确公式，后续数值全歪。
3. **把"复刻"当"复制"**：直接搬素材/文案/地图 → 法律风险 + 平台下架。
4. **先做表现层**：美术做完了才发现循环不对，返工成本最高。
5. **平均用力**：12 维都拆到 L3，却没有敏感度排序，MVP 里塞满低价值系统。
6. **忽略失败成本**：只拆成功路径，重试太贵导致留存崩。
7. **忽略三时间尺度**：只写"一局怎么玩"，没写"玩一小时后还剩什么"。
8. **无差异点**：100% 照搬 = 换皮混淆高风险，且没有存在理由。
