# 解空间与难度（可复算的难度，而不是凑出来的分数）

> 解决两个问题：**为什么"难度 0.62"这种说法没意义**，以及**拆解阶段怎么把难度变成可复现的指标**。
> 对应 SKILL.md §十。

---

## 一、先找瓶颈资源，再谈难度

难度不是一个数字，而是"玩家被什么逼着做取舍"。**先找瓶颈**，再找指标。

| 品类 | 瓶颈资源 | 失败条件（典型） | 扩容闸门 |
|---|---|---|---|
| 颜色分类 / 螺丝拆解 | 暂存槽容量 | 槽满且无合法操作 | 广告/内购加槽、加盒 |
| 三消 | 步数 / 时间 | 步数耗尽的分数不足 | 加步道具、复活 |
| 塔防 | 资源产出速率 / 人口 | 漏怪 / 基地血量归零 | 加速产出、额外塔位 |
| 推箱子 / 滑块 | 空间自由度 | 把箱子推进死角（不可逆） | 撤销、重置 |
| 卡牌构筑 | 卡组容量 / 手牌上限 / 能量 | 手牌溢出或费用不足 | 抽牌、加能量 |
| 平台跑酷 | 时间 / 生命 | 超时或掉落 | 复活、加速 |

### 容量的三个参数 + 一个闸门

拆瓶颈资源时，这四个数缺一不可：

| 参数 | 问法 | 例 |
|---|---|---|
| 上限 | 最多容纳几个 | 暂存槽 5 格 |
| 单次占用 | 一次操作吃几格 | 1 格/颗 |
| 释放条件 | 什么情况下回收空间 | 同色凑满 3 颗自动清 3 格 / 用道具清空 |
| 扩容闸门 | 什么时候可以变大、代价是什么 | 看广告 +1 格；内购解锁第 3 个盒子 |

**没有释放条件的容量 = 计时器**；**没有扩容闸门的容量 = 硬墙**（玩家只会流失）。这两种都要在报告里点名。

## 二、四个解空间指标（难度的可复算表达）

| 指标 | 定义 | 怎么算 | 判读 |
|---|---|---|---|
| **分支因子分布** | 每步"合法操作"的数量 | 求解遍历时统计每个状态的合法动作数 | 全 1＝机械流程；恒 >8＝无方向；理想：多数 2~4，关键节点出现 1（唯一正解）或 ≥5（多解权衡） |
| **死路率** | 随机走 N 步后进入不可解状态的比例 | 蒙特卡洛：随机策略跑 100 次（N=最优步数×1.5），统计不可解比例 | 过高＝挫败；过低＝无压力。休闲解谜常见目标 20%~40% |
| **步数冗余度** | 最优解步数 / 最少必要操作数 | 最优解 ÷ 对象总数 | 接近 1＝线性；>1.5＝有真实规划空间 |
| **解的数量** | 通关路径条数（上限截断） | 求解器统计前 K 条（K=20 即够） | 唯一解→需防呆提示；多解→检查是否"随便点都过" |

**口径纪律**：
- 等权加权分（`0.2C+0.2O+...`）只作**排序占位**，不能当难度绝对值。归一化基准一变，绝对值就不可跨版本比较。
- 难度必须写成"**指标 + 区间 + 样本**"：`分支因子 2~4（关键节点 1）、死路率 28%（100 次随机）`。
- 同一套指标才能比较；跨品类比较无意义（三消的步数压力 ≠ 拆解的容量压力）。

## 三、求解器：拆解就要跑，不是开发才写

### 3.1 最小实现

```
状态 = (对象可用集合, 容器状态, 场景剩余目标)
动作 = 当前所有合法操作（由同一套规则函数判定）
搜索 = DFS/BFS + 状态哈希 + 记忆化
输出 = { solvable, solution[], steps, deadEnds, branchFactor[], solutionCount }
```

**两条硬要求**：
1. **复用游戏规则函数**，不许为求解器另写一套判定（否则验证自洽、实机不符）。
2. **状态哈希只包含权威状态**：不含动画时间、不含随机种子、不含渲染顺序。哈希里混入表现状态，会导致"同一局面被当成不同状态"，搜索爆炸。

### 3.2 状态爆炸时的对策（按优先级）

| 对策 | 说明 |
|---|---|
| 对称压缩 | 同色同形可交换的对象归一化（把"哪颗红螺丝"变成"红螺丝计数"） |
| 不可逆剪枝 | 一旦进入不可解状态立即回溯，不展开（推箱子类必做） |
| 分层求解 | 先解容器层（颜色配对），再解空间层（遮挡顺序） |
| 上限截断 | 只统计前 K 条解、只搜到深度 D，用于难度评分而非全解 |
| 采样近似 | 蒙特卡洛估死路率，不求精确解数 |

### 3.3 求解器的三种用途

1. **验关**：上线前全量跑，无解关卡是事故级缺陷（不是"有点难"）。
2. **反推难度曲线**：把每关的分支因子/死路率画成曲线，看递增是否平滑、有没有"断崖"。
3. **生成筛选**：程序生成 → 求解 → 评分 → 只留合格关（见下节）。

## 四、难度落位四档（决定关卡要不要改）

| 档位 | 特征 | 处理 |
|---|---|---|
| **无解** | 求解器 `solvable=false` | 报废或改参数重生成，禁止上线 |
| **唯一解 + 分支因子全 1** | 每步只有一条路 | 太机械，增加"可逆的选择"或降低信息提示 |
| **少解（2~10 条）+ 分支 2~4** | 有规划但不唯一 | 理想区间，作为标准关 |
| **多解（>K）+ 死路率低** | 随便点都能过 | 加容量压力/加遮挡，或明确做成"放松关" |

**新手关例外**：前 3 关允许"唯一解 + 分支 1"，因为它承担教学而非挑战；但从第 4 关起必须出现真实取舍。

## 五、内容产能：拆解时要判断原作的产能来源

| 产能模式 | 特征 | 你的成本 | 必须建的工具 |
|---|---|---|---|
| 手工配置 | 每关布局都不同、无参数规律 | 随关卡数线性增长 | 关卡编辑器（否则产能封顶） |
| 参数化生成 | 模板 + 参数（形状/颜色数/层数） | 一次性投入 + 边际极低 | 生成器 + 参数面板 |
| 求解器筛选 | 生成后自动验解、评分、淘汰 | 前期最贵，后期最省 | 生成 → 求解 → 评分 → 筛选管线 |

**判据**：如果一个品类的关卡可以"生成—验解—评分"，那么**真正的壁垒是这条管线**，不是玩法和美术。
复刻时应该把这条管线列为独立交付物（报告 §9），并明确"目标产能：X 关/人日"。

## 六、验收清单

- [ ] 瓶颈资源四要素已填（上限/单次占用/释放条件/扩容闸门）
- [ ] 至少 3 关有分支因子分布与死路率（T2/T3 全部关卡）
- [ ] 有至少 1 关的完整最优解路径（步数可复核）
- [ ] 求解器复用游戏规则函数，且状态哈希只含权威状态
- [ ] 难度写成"指标 + 区间 + 样本量"，没有单独的加权总分
- [ ] 无解关卡为 0（上线门禁），或已明确标为"待修复"
- [ ] 难度曲线形状已画（递增平滑 / 有断崖需解释）
- [ ] 内容产能模式已判定，对应工具已进交付清单
