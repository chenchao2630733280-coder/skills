# 拆解产物格式（三份文件的模板与字段契约）

> 本文件从 `game-teardown/SKILL.md` §十四 抽离，作为三份产物的完整模板。
> 生成 `docs/GAME_TEARDOWN.md` / `TEARDOWN_MATRIX.json` / `NUMERIC_MODEL.csv` 时读取本文件。
>
> 三条使用纪律：
> 1. **结构不增不减**——下游（`game-blueprint` §0 一页摘要、`game-spec` 数值表）按字段名取值，
>    自行加章节或改名会让下游取不到值而静默回退到默认。
> 2. **`matrix_id` 不能悬空**——`NUMERIC_MODEL.csv` 每行必须挂到矩阵条目上，孤立参数说明它没被拆解支撑。
> 3. **分区只写证据等级允许的内容**——没到 E2 的维度在该节标 ⚠️，不要把推断写成事实（见 SKILL §八）。

### 14.1 `docs/GAME_TEARDOWN.md` 结构（不增不减）

```markdown
# {参考游戏} — 产品系统拆解

> 复刻目标:{T0~T3}
> 材料:{录屏 N 段 / 截图 N 张 / 试玩 N 局 / 公开资料 N 份}
> 证据覆盖:{达到 E2+ 的维度数}/12（低于 60% 在此标 ⚠️）
> 样本覆盖:{关卡阶段 × 状态} 已覆盖 N/15 格，缺:{...}
> 拆解日期:{日期} | 版本:v{N}

## 0. 一页摘要（game-blueprint 直接消费）
- 复刻档位:{T0~T3}(须与文档头部"复刻目标"一致)
- 决定性变量(Top 3-5)：{变量 | 原值/区间 | 敏感度 | 证据}
- 必复刻清单(≤8)：{...}
- 可替换清单：{...}
- 禁止复制清单 + 替代方向：{X → 替代}
- 灰盒 MVP 一句话：{...}
- 拆解盲区：{O3 项 / E0-E1 项}

## 1. 产品定位与复刻目标
| 项 | 结论 | 证据 | 三色 |
|---|---|---|---|
| 平台 / 单机联机 / 目标用户 / 单局时长 / 复刻档位 / MVP 范围 / 成功判据 | ... | ... | ... |

## 2. 核心玩法循环
- 三时间尺度表（30 秒 / 5 分钟 / 1 小时）
- 循环图（Mermaid，含"操作 → 反馈 → 状态变化 → 新可用操作"闭环）
- 失败与重试成本表
- **瓶颈资源表**（因何失败 / 上限 / 单次占用 / 释放条件 / 扩容闸门）
- 乐趣来源权重

## 3. 规则与系统
| 系统 | 输入 | 状态 | 规则 | 输出 | 边界条件 | 判定基准 | 三色 | 证据 |
|---|---|---|---|---|---|---|---|---|
（判定基准：中心点/包围盒/多边形/人工配置；缺此项视为未拆清）

## 4. 数值与经济
- 关键公式（公式族 + 反解过程 + 回测误差）
- 数值表 → 见 `docs/NUMERIC_MODEL.csv`
- 经济闭环：产出/消耗/沉淀
- 敏感度 Top3 及理由

## 5. 内容与关卡
| 关卡 | 时长 | 对象/波次 | 新增机制 | 难度峰值 | 教学点 | 分支因子 | 死路率 |
|---|---|---|---|---|---|---|---|
+ 内容投放节奏 + 教学关设计 + **解空间指标** + 内容产能来源

## 6. 交互与 UI/UX
- 页面流程图（Mermaid）
- 交互状态机（进入/空/满/错误/退出）
- **可交互判定**：哪些对象可见但不可操作（证明独立判定层）
- 反馈清单：顿帧/位移/闪白/飘字/音效/震动/动画时长 + 操作路径长度

## 7. 表现层（全部默认 S）
- 风格坐标系（色相/明度/饱和/比例/线宽/镜头）
- 动画节奏与特效层级
- 音频触发点（何时响、响多久、多响）
- 叙事结构（只学结构，不学文本）

## 8. 技术架构（行为等效，不还原）
| 可观测行为 | 复刻侧选型 | 理由 | 可观测性 |
|---|---|---|---|
+ 状态模型（三套状态机 + 四维分离 + 残留态）
+ 逻辑与表现分离方式

## 9. 数据与工具链
- 配置表清单（表名/字段/被谁消费/谁是权威源）
- 编辑器需求 / 埋点 / 调试命令 / 构建与热更
- 内容产能管线（手工 / 参数化 / 求解器筛选）

## 10. 测试与调优
- 功能用例（从规则边界反推，**每条对应一个 M 结论**）
- 确定性用例（重置 ≥10 次状态一致 / 动画中点击 / 快速连点）
- 平衡测试（高敏感参数落在原作区间）
- 可玩性测试（新手 3 分钟能否懂）
- 回归清单（改哪个参数会破坏哪个系统）

## 11. 合规与伦理
- X 清单 + 替代方案
- 换皮混淆自检（命中条数）
- 风险评级 + 发布前待法务确认项

## 12. 运营与商业化（仅 T3，否则写"不适用"）
付费点（按"解决哪种失败风险"归类）/ 活动节奏 / 留存与转化指标 / 是否复刻及理由

## 13. 灰盒 MVP 范围
必进 / 简化 / 占位 / 延后 四张清单 + 一句话 MVP 定义 + 确定性验收项

## 14. 拆解盲区与待验证清单
| 结论 | 当前等级 | 为什么不确定 | 验证方法 | 成本 |
|---|---|---|---|---|

## 15. 修正史
| 版本 | 原假设 | 被什么推翻 | 修正为 | 连带影响 |
|---|---|---|---|---|
```

### 14.2 `docs/TEARDOWN_MATRIX.json`

结构见 `references/teardown-matrix.schema.json`。要点：

- 顶层含 `source_game`、`tier`、`evidence_coverage`、`sample_coverage`、`dimensions_covered`、`differentiation`、`mvp`、`items`、`open_questions`、`revisions`
- `items[]` 每条含：`id`、`dimension`（1~12）、`name`、`class`（M/S/X）、`kind`（observed/inferred/design）、`depth`（L1~L3）、`observability`（O1~O3）、`evidence`（E0~E3）、`falsifier`、`source`、`sensitivity`、`value_or_range`、`in_mvp`、`replacement`（X 必填）
- JSON 必须可被 `ConvertFrom-Json` 解析（工作台校验项）

### 14.3 `docs/NUMERIC_MODEL.csv`

列固定：`id,matrix_id,parameter,value_or_range,unit,formula,evidence,source,sensitivity,notes`

- `matrix_id` 回指 `TEARDOWN_MATRIX.json` 的条目 ID（如 `D4-03`），**每个数值参数必须挂到一条矩阵条目上**，孤立的参数说明它没被拆解支撑
- `value_or_range` 用区间写法（`1.2~1.5`），单点值需 E3
- 一行一个参数，不合并单元格
- 可直接拖进 Excel/Sheets 做敏感度表

```csv
id,matrix_id,parameter,value_or_range,unit,formula,evidence,source,sensitivity,notes
N001,D4-01,base_hp,100~120,hp,,E2,"录屏第1关3次均值",high,"第1关小怪"
N002,D4-02,damage_formula,atk*k-def*m,formula,k=1.0/m=0.5,E1,"控制变量实测6点拟合",high,"回测误差18%,待补样本"
N003,D2-03,level_duration,95~130,s,,E2,"12局逐局计时",high,"取成功局区间"
```
