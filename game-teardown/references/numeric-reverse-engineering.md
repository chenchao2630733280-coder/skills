# 数值反解手册（从可观测现象到可调参数）

复刻"看着像、玩着不像"，九成出在数值与节奏。本文件给一套**可复算**的数值反解方法与公式族假设，配合 `docs/NUMERIC_MODEL.csv` 使用。

> **底线**：所有公式都是**假设**，必须用观测数据回测；回测不过就标 E0/E1 进待验证清单，不许当结论写。

---

## 一、四种采集方法

### 1. 帧测法（适合时长/频率/节奏）
- 录屏 60fps，逐帧定位事件起点（受击闪白、飘字出现、音效波形起点）
- 测：单次动画时长、两次攻击间隔、波次间隔、加载时长、反馈延迟
- 样本：同一动作 ≥5 次取区间；不同关卡各 ≥3 次
- 输出：`value_or_range`（区间）+ E2，source 写"帧号区间 + 样本数"

### 2. 控制变量实测（适合公式形状）
- 只在能复现同一局面时可用（固定关卡、固定敌人、固定装备）
- 每次只改一个变量（攻击力 +1 档），记录结果变化
- 判定：结果线性 → 加算；结果按比例 → 乘算；有拐点 → 分段/阈值
- 样本：每个变量 ≥3 个取值点，才能判断形状（2 点永远能连成直线）

### 3. 区间采样（适合概率与分布）
- 重复同类事件 ≥30 次，统计频率与极值
- 掉落：记录"第几次出"（判断是否有保底：出现间隔上限）
- 暴击/闪避：频率 → 概率量级（不要写成精确 %，写 `20%~30%`）
- 输出：频率 + 样本量 + 置信说明

### 4. 公式族反解（适合从结果推形式）
先假设一个公式族，再用观测点拟合，能解释全部观测才算通过。

```
候选族（按复杂度递增，优先选简单能解释的）
伤害 = atk × k − def × m                    （线性减伤）
伤害 = atk × k × (1 − def / (def + C))      （递减减伤，C 为常数）
伤害 = (atk − def) × k × random(0.9, 1.1)   （浮动）
伤害 = atk × k × crit? × element? × armor?  （乘算链）
```

**奥卡姆约束**：能用 2 参数解释的，不要上 4 参数。参数越多越容易过拟合单局观测。

## 二、反解六步流程

1. **锁定可测场景**：固定关卡/固定敌人/固定装备，确保可重复
2. **记录原始观测**：每次的输入、输出、随机结果，写进临时表
3. **判断形状**：改一个变量，看输出是等差、等比还是有拐点
4. **选公式族**：从简单族开始，拟合参数
5. **回测**：用**未参与拟合**的观测点验证；误差 >20% 视为不成立
6. **定级**：回测通过且样本 ≥10 → E2；有官方数据交叉验证 → E3；否则 E1/E0

## 三、常见公式族（假设库，不是结论）

| 子系统 | 常见形式 | 判断线索 |
|---|---|---|
| 伤害 | `atk×k − def×m` / `atk×k×(1−def/(def+C))` | 防御收益是否递减（高防时伤害是否趋零） |
| 命中/闪避 | `hit/(hit+evade)` 或 直接差值 | 高闪避是否出现"完全打不中" |
| 暴击期望 | `dmg×(1+p×(critMult−1))` | 暴击是否为独立乘区 |
| 成长 | 线性 / 指数 `base×r^lv` / 分段（每 10 级跃升） | 相邻等级差值是否恒定 |
| 经验曲线 | `a×lv^2+b×lv+c` | 升级所需时间是否递增、平台期在哪 |
| 掉落 | 权重轮盘 + 保底计数 | 稀有物出现间隔是否有上限 |
| 经济 | 产出速率 − 消耗速率 = 沉淀 | 玩家资源是越来越多还是长期紧平衡 |
| 体力/冷却 | `cap` + `rate×Δt`，含溢出惩罚 | 是否鼓励"卡点上线" |
| 难度缩放 | 敌人属性 × `(1+α×progress)` | 后期是否靠堆数量而非质量 |
| 抽卡 | 基础概率 + 软保底递增 + 硬保底 | 概率是否随未出次数上升 |

**记录要求**：每个公式写清"适用区间"（如 `lv 1~20`），越界即失效。

## 四、敏感度分析（决定调参方向）

对每个高敏感参数做单参数扰动：

```
把参数调 ±10%（或 ±1 档），看三个指标变化：
A. 单局时长
B. 失败率
C. 单局收益
变化 >15% → high 敏感；5%~15% → mid；<5% → low
```

规则：
- **只给 high 参数做 L3 公式**，mid/low 用区间即可
- low 参数允许自由改（正好做差异化）
- 调参顺序：先 high 再 mid，**永不并发调多个**（否则无法归因）

## 五、CSV 模型结构（固定列）

```csv
id,matrix_id,parameter,value_or_range,unit,formula,evidence,source,sensitivity,notes
N001,D4-01,base_hp,100~120,hp,,E2,"录屏第1关3次均值",high,"第1关小怪"
N002,D4-02,damage_formula,atk*k-def*m,formula,"k=1.0,m=0.5",E1,"控制变量实测6点拟合",high,"回测误差18%,待补样本"
N003,D4-05,crit_rate,0.15~0.25,ratio,,E2,"50次攻击统计",mid,
N004,D5-02,levelup_exp,lv^2*80,exp,,E1,"公开wiki+实测2点",mid,"仅验证到lv12"
```

约束：
- `matrix_id` 回指 `TEARDOWN_MATRIX.json` 条目（如 `D4-01`）；**孤立参数说明它没被拆解支撑**，必须补拆或删除
- 一行一个参数；`value_or_range` 用 `a~b`，单点值必须 E3 并在 `notes` 说明
- `formula` 列只写形式，不写具体数值（数值放 `value_or_range`）
- `source` 必须可复查：帧号 / 样本数 / 链接 / 实测次数
- 不合并单元格、不加小计行（否则脚本与透视表会踩坑）

## 六、误差与置信

| 场景 | 最低样本 | 允许的表述 |
|---|---|---|
| 时长/间隔 | 5 次 | `1.2~1.5s` |
| 概率 | 30 次 | `20%~30%`，不写 `23.7%` |
| 公式形状 | 3 个取值点 | `线性/递减/分段` + 参数区间 |
| 曲线拐点 | 跨拐点各 3 点 | `lv10 附近有跃升` |
| 经济闭环 | 完整一轮循环 ×3 | 定性 + 量级（`产出约为消耗 1.5 倍`） |

**低样本禁令**：1~2 次观测不得写成结论；只能写"疑似"，等级 E0。

---

## 七、七个常见陷阱

1. **动态难度**：后台按表现调参 → 同一关卡不同表现下数值不同，必须多次不同表现采样
2. **伪随机**：种子固定或补偿机制（连输后必赢）→ 频率统计会失真，需记录序列而非只记频率
3. **版本漂移**：玩家讨论的数值是旧版本，你看到的是新版本 → 记录版本号与日期
4. **平台差异**：移动端与 PC 端数值/帧率不同（尤其射击、跑酷）
5. **取整与时序**：`floor`/`round` 会让公式看起来"有噪声"，先测单点再拟合
6. **隐藏加成**：装备/天赋/连击/环境加成未识别，导致公式整体偏移
7. **观测偏差**：只录高光局 → 数值偏乐观；必须含失败局

## 八、验收标准

数值模型可用，需同时满足：

- [ ] 所有 high 敏感参数有 `value_or_range` + `evidence ≥E2` + 可复查 `source`
- [ ] 每个公式至少用 3 个**未参与拟合**的观测点回测，误差 ≤20%（超差标 E1）
- [ ] 经济闭环能定性解释：产出/消耗/沉淀三者的量级关系
- [ ] 有"哪个参数一改就崩"的敏感度清单（≥3 项）
- [ ] 无单点精确值（除非 E3 且有公开依据）
- [ ] CSV 无合并单元格，列名与规范一致
