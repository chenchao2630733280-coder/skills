# 移动端产品界面设计规范

本规范把优秀移动端产品中的共性做法抽象为可复用的页面结构、组件规则和决策逻辑。它不绑定具体城市、平台或业务，也不允许把分析用截图直接复制到生成结果中。

## 1. 设计结论

优秀移动端页面并不是“把 PC 页面缩窄”，而是围绕单手操作、任务优先级和信息渐进披露重新组织内容。可复用的核心特征如下：

1. **密而不乱**：首页可以承载较多入口，但必须通过大区块、卡片背景、标题、留白和颜色分层建立秩序。
2. **任务先于装饰**：搜索、常用服务、订单、余额、到站时间、结算等高频任务应在首屏直接可达。
3. **一屏一主任务**：列表页突出查找与选择，详情页突出理解与行动，购物车突出选择与结算，个人页突出状态和快捷入口。
4. **轻容器、强层级**：优先使用白色或浅色卡片、柔和页面底色、少量强调色；避免大量边框和高强度阴影。
5. **上下文连续**：筛选展开、分类切换、数量修改等操作尽量保持当前页面上下文，不轻易跳转到全新页面。
6. **视觉资产服务于内容**：图片用于表达商品、景点、专家、活动等真实对象；无项目资产时用渐变、色块、图标和骨架占位，不伪造或复制参考截图。

## 2. 页面原型选择

生成移动端页面前，先判断页面属于哪一种原型。不要机械套用同一套“标题栏 + 卡片列表”。

| 原型 | 适用场景 | 首屏结构 | 主操作 |
|---|---|---|---|
| 综合入口首页 | 政务、生活、文旅、园区、城市服务 | 顶部环境/频道切换 → 搜索或运营位 → 服务宫格 → 内容模块 | 进入服务、搜索、切换频道 |
| 内容发现首页 | 旅游、资讯、活动、推荐 | 搜索 → 主题运营位 → 快捷分类 → 推荐内容 | 浏览、搜索、进入详情 |
| 分类检索页 | 商品、服务、知识库 | 搜索 → 一级分类 → 二级分类/排序 → 结果列表 | 筛选、排序、加购/选择 |
| 图文列表页 | 景点、专家、活动、新闻 | 顶部栏 → 本地 Tab/筛选 → 图文列表 | 进入详情、收藏、预约 |
| 沉浸详情页 | 景点、商品、服务详情 | 媒体区 → 核心信息 → 标签/位置/评价 → 分段详情 | 购买、预约、导航、收藏 |
| 交易任务页 | 购物车、订单、结算、售后 | 页面标题 → 分组内容 → 状态与金额 → 固定操作栏 | 结算、支付、取消、联系商家 |
| 个人中心页 | 账户、订单、权益、设置 | 个性化头部 → 状态快捷卡 → 分组菜单 | 查看状态、进入账户能力 |
| 公共账户页 | 公积金、社保、医保、钱包 | 机构身份 → 账户概览 → 核心办理入口 → 信息查询宫格 | 查询、提取、办理、授权 |
| 实时信息页 | 公交、排队、预约时段、物流 | 场景化头部 → 搜索 → 最近/当前对象 → 实时列表 | 查看实时状态、展开详情 |

## 3. 视觉语言

### 3.1 页面底色与容器

- 页面底色默认使用 `#F5F7F6` 或项目浅色背景，内容卡片使用白色。
- 卡片默认圆角 12px；小型控件 8-10px；胶囊标签使用全圆角。
- 卡片之间留 10-12px，页面左右边距 12-16px。
- 卡片优先使用边界对比和留白，不默认使用明显投影。仅悬浮卡、叠层卡、底部操作栏允许轻阴影。
- 首页可使用浅色渐变作为顶部氛围层，但渐变不得降低文字对比度。

### 3.2 颜色角色

- 主色只承担导航活动态、主按钮、关键数字和选中状态，不应铺满所有模块。
- 促销价、错误、未处理提醒可使用红色；成功、可用、实时到站可使用绿色；警告和待处理可使用橙色。
- 状态不能只靠颜色表达，必须同时提供文字、图标或位置关系。
- 运营模块可使用辅助色，但同一屏同时出现的高饱和色块建议不超过 3 组。

### 3.3 字体层级

建议层级：

- 页面标题：18-20px / 600
- 模块标题：16-17px / 600
- 条目标题：15-16px / 500-600
- 正文：14px / 400
- 辅助信息：12-13px / 400
- 价格、余额、到站时间等关键数字：18-24px / 600-700，使用等宽数字

标题最多两行，列表标题优先一行省略；辅助信息不要使用过浅灰色。

## 4. 导航与页面骨架

### 4.1 三层导航模型

移动端最多同时出现以下三层中的两层：

1. **全局频道层**：例如“政务 / 生活”，用于切换完全不同的一级内容域。
2. **页面局部层**：例如“全部 / 自然风光 / 艺术展览”，用于当前页面内部筛选。
3. **底部主导航**：4-5 个长期稳定的一级目的地。

禁止在同一页面同时堆叠频道切换、两行局部 Tab、底部 Tab 和面包屑。二级详情页通常只保留顶部返回栏。

### 4.2 顶部栏

- 普通二级页高度 44-48px，左右操作区至少 44px，标题视觉居中。
- 搜索型页面可使用“返回 + 搜索框 + 搜索按钮”的组合，搜索框高度 36-40px。
- 一级首页可以不显示传统标题栏，改为天气/定位、频道切换、搜索和消息组成的上下文头部。
- 顶部栏可按页面需要 sticky，但不要让运营位或大图被多层固定栏挤压。

### 4.3 底部主导航

- 仅在 4-5 个稳定一级入口存在时生成。
- 高度 52-56px，加 `env(safe-area-inset-bottom)`。
- 图标 22-24px，标签 11-12px，选中态使用主色。
- 可有一个中心强化入口，但它必须是真正高频且跨模块的核心能力；不可仅为装饰。
- 二级页、详情页、全屏表单、结算页可隐藏底部导航，避免与固定主操作冲突。

## 5. 首页与综合入口

### 5.1 首屏顺序

综合入口首页推荐：

1. 上下文头部：天气、定位、频道、搜索、消息中的必要项；
2. 运营位或核心通知：单张主视觉，支持轮播但默认只展示一个主焦点；
3. 高频服务宫格：首屏展示 8-15 个入口；
4. 专题或权益模块：2-4 张不同尺寸卡片；
5. 内容列表：活动、新闻、推荐、待办等；
6. 底部主导航。

### 5.2 服务宫格

- 4 列适合名称较长、图标强调的公共服务；5 列适合短名称和高密度入口。
- 图标建议 28-36px，文字 11-13px，单元最小高度 64px。
- 一屏服务入口超过 15 个时，应提供“全部”入口或分页，不继续无限增加行数。
- 红点、优惠角标、待办数量必须靠近对应图标，不遮挡主图形。
- 图标风格、描边粗细、圆角和色彩饱和度保持一致。

### 5.3 运营位

- 默认比例约 2.6:1 到 3.2:1，圆角 10-12px。
- 运营位只保留一个主标题、一个副标题、一个行动点；避免把完整海报文字原样塞入小屏。
- 无真实运营素材时，生成 CSS 渐变、几何装饰和文字排版，不复制任何参考图。
- 轮播点只在确有多张内容时生成，且不自动高速轮播。

### 5.4 模块化内容卡

- 使用不对称拼贴卡时，必须有明确阅读顺序：大卡承载主主题，小卡承载补充主题。
- 同一模块内卡片的标题位置、内边距和圆角保持一致。
- “更多”放在模块标题右侧；整张卡可点击时不再重复小箭头。

## 6. 搜索、分类与筛选

### 6.1 搜索框

- 搜索框是任务入口，不是装饰。占位文案要描述可搜索对象，例如“搜索商品名称”“搜索线路或站点”。
- 页面首要任务是搜索时，搜索框应接近全宽；普通首页可使用紧凑搜索入口。
- 搜索按钮可内嵌在输入框右侧，但与输入内容用间距或细分隔线区分。
- 搜索结果为空时提供修改关键词、清空筛选或热门建议。

### 6.2 分类层级

分类检索页推荐三段式结构：

1. 顶部横向一级分类，使用图标或短标签；
2. 排序/筛选条，最多 4 个高频条件；
3. 二级分类和结果列表。

二级分类较多时可使用左侧窄栏，右侧显示结果。左栏宽度建议 76-92px，选中项通过主色文字、浅色背景或左侧 3px 指示条表达，不同时叠加多种强调。

### 6.3 上下文展开层

分类“全部”或筛选展开时：

- 展开层从触发区域下方出现，保留顶部搜索和分类上下文；
- 使用半透明遮罩压暗下方内容；
- 展开层内部采用 4-5 列图标宫格或标签网格；
- 选择后立即关闭或提供明确“完成”；
- 不把简单分类选择做成全屏新页面。

## 7. 列表与详情

### 7.1 图文列表

- 缩略图建议 88-112px，圆角 8-10px；内容区至少包含标题、一个价值信号和一组辅助信息。
- 价值信号可为评分、价格、距离、到站时间、专家职称、活动状态等，不应全部同时出现。
- 标签控制在 1-3 个，使用浅色胶囊；标签不替代正文说明。
- 距离、销量、时间等元信息放在底部或右侧，使用 12-13px。
- 列表可用分隔线或卡片间距，二者择一，不要同时强化。

### 7.2 商品列表

- 图片与文字组成稳定的横向条目，价格靠近标题和促销信息。
- “加入购物车”使用图标按钮或小型主色按钮，触控区域仍需 44px。
- 促销信息最多一行，不与商品标题争夺主层级。
- 商品列表中的价格统一格式；整数和小数视觉基线一致。

### 7.3 沉浸详情

- 媒体区可以靠近顶部，但系统返回、分享、收藏仍需可见且有对比度。
- 核心信息区依次展示：标题 → 评分/状态 → 地址/规格 → 价格或主要行动。
- 详情正文采用纵向分区，分区标题固定样式；长内容支持折叠/展开。
- 位置、电话、导航等并列快捷动作适合使用图标 + 短标签。
- 有购买或预约行为时使用底部固定操作栏，并为内容预留底部空间。

## 8. 交易与订单

### 8.1 购物车

- 按商家或业务主体分组，每组包含主体名称、可选标签和商品条目。
- 选择框与条目内容保持垂直对齐；整行可点击切换选择时仍保留可识别控件。
- 数量步进器按钮至少 40×40px，禁用态清晰。
- 底部结算栏固定在底部导航之上，包含全选、合计和主按钮；合计与按钮在视觉上最突出。
- 当底部主导航存在时，结算栏与主导航分层，禁止互相遮挡。

### 8.2 订单列表

- 顶部状态 Tab 只保留常用状态，使用短下划线或主色文字表示活动态。
- 订单卡以商家/业务主体为标题，状态置于右上，商品内容置中，金额和操作置底。
- 已取消、已完成等弱状态降低强调，但文字仍保持可读。
- 每张订单卡最多展示 1 个主操作和 1 个次操作，其余收纳到“更多”。

### 8.3 固定操作栏

- 使用 `position: sticky` 或 `fixed` 时必须计算安全区和底部导航高度。
- 主按钮高度 44-48px；双按钮时主次比例建议 2:1。
- 未满足条件的按钮必须给出禁用原因或在点击后明确提示。

## 9. 个人中心与公共账户

### 9.1 个人中心

- 顶部可以使用浅色渐变或品牌氛围色，展示头像、名称和少量身份信息。
- 订单状态快捷卡可轻微叠压在头部与页面之间，形成清晰层级。
- 快捷状态建议 4-5 个，包含图标、名称和可选数量徽标。
- 通用服务使用分组列表，行高 52-56px，左图标、中文案、右箭头。
- 页面留白可以较多，不要用无关推荐内容填满个人页。

### 9.2 公共账户

- 首屏先建立机构可信度，再展示账户信息和办理能力。
- 余额、账号等敏感信息默认脱敏，并提供明确的显示/隐藏按钮。
- 核心办理动作使用高识别度主按钮，例如“提取”“查询明细”“立即授权”。
- 次级能力放入 2 列信息卡或 4 列服务宫格。
- 使用正式、克制的图标和颜色，减少促销式视觉。

## 10. 实时信息页面

- 实时页面的主要对象是“时间变化”，因此更新时间、预计到达、状态和异常要优先于装饰图片。
- 线路/站点列表中，线路号或对象名为主标题；到达时间使用大号数字；方向、站距、更新时间为辅助信息。
- 展开详情保持在当前列表内，用折叠区展示站点序列、时间轴或步骤，不强制跳页。
- 实时状态既使用颜色，也使用文字和图标；离线或数据延迟必须明确提示。
- 搜索框应支持对象类型提示，例如线路、站点、车次、预约号。

## 11. 组件尺寸建议

| 组件 | 建议尺寸 |
|---|---|
| 顶部栏 | 44-48px |
| 搜索框 | 36-40px |
| 主按钮 | 44-48px |
| 普通列表行 | 52-64px |
| 服务宫格单元 | 64-80px |
| 底部主导航 | 52-56px + 安全区 |
| 图文列表缩略图 | 88-112px |
| 卡片圆角 | 12px |
| 控件圆角 | 8-10px |
| 页面边距 | 12-16px |
| 模块间距 | 12-16px |
| 卡片内边距 | 12-16px |

## 12. 状态、动效与反馈

- 首屏数据加载使用骨架屏，骨架结构与真实内容结构一致。
- 列表加载更多使用底部 loading，不用全屏遮罩阻断浏览。
- 操作成功使用轻提示；高风险操作使用确认对话框并说明影响。
- 展开层、抽屉和底部面板使用 180-240ms 缓动，遵循 `prefers-reduced-motion`。
- 网络错误、数据过期、权限不足、空结果、售罄、禁用等状态按业务需要实现。

## 13. 可访问性

- viewport 使用 `width=device-width, initial-scale=1, viewport-fit=cover`，不得禁止缩放。
- 可点击区域至少 44×44px；相邻小按钮间距至少 8px。
- 图标按钮必须提供 `aria-label`；图片必须提供准确 `alt` 或在纯装饰时留空。
- 固定底栏必须为内容添加等高底部 padding。
- 颜色对比不足的浅色背景上使用深色文字；辅助文本不低于 12px。
- 金额、时间、数量等变化信息使用 `aria-live` 或明确反馈。

## 14. 资源与版权规则

1. 分析截图只用于提炼结构和原则，**不得复制、裁切、压缩或打包进 Skill**。
2. 不得复刻截图中的品牌 Logo、人物、商品图、广告图、专属插画和文案。
3. 用户提供且明确允许用于最终项目的资产，可放入项目输出目录；否则使用本地 SVG、CSS 渐变、几何图形或中性占位图。
4. 示例 HTML 不依赖外部 CDN，不使用远程图片，不把截图转为背景图。
5. 生成结果应表现为同一设计语言下的新页面，而不是对某一张截图的像素级复制。

## 15. 反模式

- 在移动端直接保留 PC 的多列表格、面包屑和密集工具栏。
- 每个页面都强制出现顶部栏、局部 Tab、底部 Tab 和固定按钮。
- 用大量彩色卡片制造“丰富感”，导致没有主次。
- 服务入口超过 15 个仍无“全部”或搜索。
- 运营位文字过多，用户无法在 2 秒内理解主信息。
- 把筛选、分类、数量调整等轻操作拆成多层跳转。
- 固定底栏遮住最后一条内容或与系统安全区冲突。
- 用 Emoji 作为正式业务图标。

## 16. 生成决策流程

1. 根据 PRD 判断页面核心任务和用户进入路径。
2. 从第 2 节选择一个主原型，必要时组合一个辅助原型。
3. 确定是否需要全局频道、局部 Tab、底部主导航；最多同时保留两层。
4. 确定首屏唯一主任务，并把它放在首屏上半区。
5. 选择内容密度：`comfortable / standard / compact`。公共服务首页可 compact，表单和账户页优先 standard。
6. 从 Token 生成页面壳层和组件，不从参考截图取像素或资源。
7. 检查加载、空、错误、禁用和固定底栏安全区。
8. 使用 `examples/mobile-pattern-demo.html` 验证抽象设计语言，而不是对照任何图片。
