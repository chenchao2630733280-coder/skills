# 数值与经济系统设计原则

> **核心驱动**:数值服务体验,产出消耗闭环维持经济健康。
> **与其他原则的关系**:本原则是通用原则(第二层),跨品类适用。与 `monetization` 原则3(不卖变强)互补:本原则管数值层,monetization 管变现层。
> **单一来源**:产出消耗闭环、F2P数值平衡的完整定义在本文件。`value-reveal` 原则4(日经济)引用本文件的闭环概念。

---

## 一、适用判定

| 判定信号 | 说明 |
|---|---|
| 有角色/装备/属性数值 | 需要数值平衡 |
| 有货币/资源系统 | 需要经济控制 |
| 有成长曲线(升级/强化) | 需要曲线设计 |
| 有产出与消耗(打怪掉落/升级消耗) | 需要产出消耗平衡 |

**命中任意一条 → 适用本原则**。几乎所有有数值系统的游戏都适用。

---

## 二、五条核心原则

### 原则 1:明确平衡目标,数值服务于体验

**原理**:数值平衡不是"所有选项等强",而是"数值服务于想要的体验"。跑酷要"越来越快但不失控",RPG 要"前期爽后期肝",竞技要"公平对称"。先定体验目标,再调数值。

**反模式**:追求"绝对平衡"(所有武器等强)无差异化;数值与体验脱节;照搬其他游戏数值。

**设计要求**:
- **先定体验目标**(爽快/硬核/休闲/竞技),再定数值方向
- **差异化平衡**(不同选项有不同优势场景,而非等强)
- **数值可调预留**(留调参空间,便于上线后调整)
- **有明确的平衡指标**(如"通关率60%"/"平均存活10分钟")

**检查项**:
- [ ] 有明确的体验目标
- [ ] 数值方向与体验目标一致
- [ ] 选项有差异化(非等强)
- [ ] 有平衡指标(如通关率/存活时长)
- [ ] 数值参数集中管理(便于调参)

---

### 原则 2:成长曲线遵循"边际递减+阶梯跃升"

**原理**:纯线性成长会无聊(每级一样),纯指数成长会失控(后期数值爆炸)。健康曲线是"边际递减(每级提升越来越少)+ 阶梯跃升(每N级/转职有大跃升)"。

**反模式**:纯线性(每级+10攻击)无聊;纯指数(每级×1.1)失控;无阶梯跃升缺少阶段感。

**设计要求**:
- 基础成长**边际递减**(每级提升递减,如 10/9/8/7...)
- 每 N 级有**阶梯跃升**(转职/突破/觉醒,数值+外观双提升)
- 成本曲线**指数上升**(升级所需经验指数增长,控制升级速度)
- 收益与成本**匹配**(高级别提升小但成本大,制造稀缺感)

**曲线示例**:
```
线性(❌无聊):  10/20/30/40/50/60/70...
指数(❌失控):  10/11/12.1/13.3/14.6...
健康(✓):     10/19/27/34/40/45/49... → 转职跃升至 80
成本:          100/220/480/1050/2300/5000...(指数)
```

**检查项**:
- [ ] 成长曲线边际递减
- [ ] 有阶梯跃升节点
- [ ] 升级成本指数上升
- [ ] 收益与成本匹配

---

### 原则 3:产出与消耗闭环,防止通胀/通缩

**原理**:经济系统的健康在于**产出与消耗的动态平衡**。只产出不消耗→通胀(资源贬值);只消耗不产出→通缩(玩家卡进度)。必须有闭环:产出→消耗→产出更多。

> **单一来源**:产出消耗闭环概念在本文件定义。`value-reveal` 原则4(日经济节奏)的"卖成品回收资金→付房租→买新石头"是本闭环的具体应用。

**反模式**:产出>>消耗(通胀);消耗>>产出(通缩);单一货币无沉淀;无消耗锚点。

**设计要求**:
- **多货币分层**(金币/钻石/专属货币),各管各的,防止单一通胀
- **强制消耗锚点**(升级/修复/房租/维护),保证持续消耗
- **稀缺资源控制**(高级材料限量产出,保值)
- **消耗产出动态调整**(根据服务器数据调产出率)

**闭环示例**:
```
打怪产出金币 → 金币升级装备 → 装备更强打更难的怪 → 产出更多金币
       ↑                                              │
       └──────────────────────────────────────────────┘
(闭环:产出驱动消耗,消耗驱动产出)
```

**检查项**:
- [ ] 有 ≥2 种货币(主货币+稀缺货币)
- [ ] 有强制消耗锚点(升级/修复/房租)
- [ ] 稀缺资源限量产出
- [ ] 产出与消耗闭环(非单向)

---

### 原则 4:大数值压缩,避免数值膨胀

**原理**:数值膨胀到亿级时,玩家失去感知(1亿和1.1亿没区别)。用**数值压缩**(K/M/B单位、科学计数法、等级替代数值)或**重置机制**(转生/赛季重置)控制数值规模。

**反模式**:数值无限膨胀(后期伤害上亿);无重置机制(新玩家无法追赶);多种数值并行(计算复杂看不懂)。

**设计要求**:
- **数值压缩**:用 K/M/B/T 单位,或科学计数法(1.2M 伤害)
- **转生/赛季重置**:满级后重置,获得永久加成,重新开始
- **数值维度精简**:核心数值 ≤5 种(攻击/生命/防御/速度/暴击)
- **伤害数字可视化**:大数字用更大字号+颜色,强化感知

**重置机制示例**:
```
转生前:等级100,攻击10000
转生:重置等级为1,获得"转生加成"+10%永久攻击
转生后:等级1,攻击110(基础100 × 1.1加成)
再次到100级:攻击11000(超过上次)
多次转生:加成累积,数值可控但持续成长
```

**检查项**:
- [ ] 数值有压缩(K/M/B)或重置机制
- [ ] 核心数值维度 ≤5 种
- [ ] 大数值有可视化强化
- [ ] (长线游戏)有转生/赛季重置

---

### 原则 5:F2P 平衡,免费可玩付费加速

**原理**:F2P 游戏的数值平衡要让免费玩家"能玩通(慢)",付费玩家"玩得快(不碾压)"。关键在**付费买效率而非买能力**:付费缩短达成时间,但不解锁独占能力。

> **单一来源**:F2P 数值平衡在本文件定义。`monetization` 原则3(不卖变强)管变现层"卖什么",本原则管数值层"差距多大"。

**反模式**:免费卡死(数值门槛必须付费);付费碾压(数值差距10倍);付费独占能力。

**设计要求**:
- **免费可达上限**:所有数值上限免费玩家可达成(只是更慢)
- **付费买效率**:付费加速(经验+50%/资源+50%),非解锁
- **数值差距可控**:付费与免费数值差距 ≤2-3 倍(非10倍)
- **时间换能力**:免费玩家用时间弥补付费差距

**平衡公式参考**:
```
免费玩家达成时间: T_free
付费玩家达成时间: T_paid
T_paid = T_free / k  (k为加速系数,通常 2-5)

例:免费玩家100小时满级,付费玩家(k=4)25小时满级
数值上限相同,只是时间差。付费买的是"省75小时"。
```

**检查项**:
- [ ] 免费玩家可达成所有数值上限
- [ ] 付费买效率(加速)非能力(解锁)
- [ ] 付费与免费数值差距 ≤2-3 倍
- [ ] 有"时间换能力"路径

## 三、协同关系

```
原则1(平衡目标) ──定义方向──→  原则2(成长曲线) ──控制成长──→
        ↓                                                    ↓
        ↓                                                    ↓
原则5(F2P平衡)  ←──免费可玩──  原则4(数值压缩)  ←──控制规模──  原则3(产出消耗闭环)
```

- **原则1** 是方向:数值服务体验
- **原则2** 是成长:边际递减+阶梯跃升
- **原则3** 是循环:产出消耗闭环防通胀
- **原则4** 是规模:数值压缩+重置防膨胀
- **原则5** 是公平:F2P 免费可玩付费加速

**第一性原理**:
> 数值不是冰冷的数字,而是体验的载体。先定体验目标,再调数值方向;用成长曲线制造阶段性成就,用产出消耗闭环维持经济健康,用数值压缩保持感知清晰,用 F2P 平衡保证生态。五者协同,数值才"活"。

## 四、生成蓝图时的应用流程

### Step 1:确定数值体系

| 维度 | 内容 |
|---|---|
| 体验目标 | 爽快/硬核/休闲/竞技 |
| 核心数值 | ≤5 种(如攻击/生命/防御/速度/暴击) |
| 货币体系 | 主货币(金币)+ 稀缺货币(钻石)+ 专属货币 |
| 成长曲线 | 边际递减+阶梯跃升 |
| 消耗锚点 | 升级/修复/房租/维护 |

### Step 2:建立产出消耗表

| 资源 | 产出途径 | 消耗途径 | 日产出估算 | 日消耗估算 |
|---|---|---|---|---|
| 金币 | 打怪/任务 | 升级/购买 | {N} | {N} |
| 钻石 | 成就/付费 | 稀有道具 | {N} | {N} |
| 经验 | 战斗 | 升级 | {N} | {N} |

### Step 3:填写数值表到 PRD

在 PRD 的"2.3 数值设计"章节填写:
- 核心数值基础值与成长公式
- 货币产出与消耗表
- 成长曲线(等级1/10/50/100的数值)
- F2P 平衡(免费达成时间 vs 付费达成时间)

### Step 4:质量自检

对照五原则检查项,确认数值体系健康。缺失项标注到"9. 关键技术风险"。

## 五、常见数值陷阱速查

| 陷阱 | 症状 | 根因 | 修复 |
|---|---|---|---|
| 通胀 | 资源堆积无用 | 产出>>消耗 | 增加消耗锚点/减少产出 |
| 通缩 | 玩家卡进度 | 消耗>>产出 | 增加产出/降低消耗 |
| 数值膨胀 | 后期数字上亿 | 指数成长无重置 | 加转生/赛季重置 |
| 无差异 | 所有选项等强 | 追求绝对平衡 | 差异化平衡(场景优势) |
| P2W | 付费碾压免费 | 卖数值变强 | 卖效率/外观,不卖能力 |
| 无聊 | 成长无感 | 纯线性成长 | 边际递减+阶梯跃升 |
| 看不懂 | 多数值并行 | 维度过多 | 精简到 ≤5 种核心数值 |
| 卡死 | 数值门槛必须付费 | 免费路径缺失 | 保证免费可达成上限 |
