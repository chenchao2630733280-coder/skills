# 阶段判定 · 交付时间 · 进展描述 规范

## 一、阶段判定表（按客观证据判定，不按感觉）

| 阶段 | 判定证据（满足任一即可判定） | 常见误判 |
|------|--------------------------|---------|
| 方案阶段 | 在做需求调研/竞品分析；PRD 在写或在评审；方案未定稿 | 有 PRD 草稿就算「方案阶段」，别算「设计中」 |
| 设计中 | 原型/UI/交互稿在产出中；设计评审未通过 | 「方案已定但还没画稿」仍属方案阶段 |
| 设计完成待开发 | 设计稿定稿并交付研发；研发未开工/未排期 | 研发已动手就别停在这，应判「开发中」 |
| 开发中 | 代码在写；接口在实现；本地自测中 | 提测后仍写 bug 修复也算开发中，除非已正式提测 |
| 测试中 | 已提测；测试在执行用例；bug 在修复轮次 | 研发自测不算测试中 |
| 测试完成待上线 | 测试报告已出且通过；等发布窗口/等审批 | 还有 P0/P1 bug 未关 → 仍是测试中 |
| 代码上线 | 已发布生产或灰度；线上验证中 | 只发了预发/沙箱不算上线 |
| 延期 | 已过原定交付时间仍未交付，或已明确将无法按时交付 | 正在按计划做的不算延期 |

**并存规则**：`延期` 可与其它阶段并存（如「开发中（原定 9-20，现 9-27）」）。
除延期外，同一项目/功能**只取一个最靠后的阶段**，不重复列。

**「最靠后」原则**：一个功能同时有设计收尾和开发开工 → 取「开发中」（阶段是推进的，不是并列的）。

## 二、阶段名映射（自造词 → 白名单）

| 常见自造说法 | 映射到 |
|-------------|--------|
| 研发中 / 编码中 / 实现中 | 开发中 |
| 待评审 / 调研中 / 需求中 | 方案阶段 |
| 画图中 / 出稿中 / UI 中 | 设计中 |
| 待排期 / 设计好了还没做 | 设计完成待开发 |
| 提测了 / 测试轮次中 | 测试中 |
| 待发布 / 待发版 / 待上生产 | 测试完成待上线 |
| 已发布 / 已上线 / 已发版 | 代码上线 |
| 滞后 / 顺延 / 推后 | 延期 |

## 三、交付时间写法

| 情况 | 写法 | 示例 |
|------|------|------|
| 有明确日期 | `（YYYY-MM-DD）` | `开发中（2026-10-10）` |
| 只有月份 | `（10月底）` | `开发中（10月底）` |
| 只有周次 | `（10月第2周）` | `测试中（10月第2周）` |
| 一个时间段 | `（YYYY-MM-DD~YYYY-MM-DD）` | `开发中（2026-09-20~2026-10-10）` |
| 已上线（写上线日） | `（YYYY-MM-DD）` | `代码上线（2026-09-15）` |
| **没有排期** | **括号整体省略** | `方案阶段：完成业务调研，待确认排期` |

**禁止**：`（）`、`（待定）`、`（TBD）`、`（暂无）`、`（未定）`。

## 四、延期行写法（唯一必须带两个时间的阶段）

```
延期（原定 2026-09-20，现 2026-09-27）：依赖的 OCR 服务联调阻塞，等待对方排期
延期（原定 2026-09-18，待定）：第三方资质接口未返回，新时间待对方确认
```

- 新时间未定也要写「原定 X，待定」，不能只写「延期」两字。
- 与主体阶段并存时，先写主体阶段行，再写延期行。

## 五、进展描述写法

### 5.1 要素（至少含 2 项）

`动作`（做了什么）+ `产出物/量化`（产出什么、完成度多少）+ 可选 `阻塞/下一步`。

### 5.2 正例 ✅

- `完成需求调研与竞品分析，输出 PRD v1.0 待周三评审`
- `订单模块 12 个接口完成 8 个，剩余联调待测试环境就绪`
- `一轮测试 41 用例通过 36，5 个边界用例修复中，预计周四回归`
- `多租户定价模型评审通过，设计稿已交付研发，待排期`
- `灰度 10% 发布，无异常告警，明日扩至 50%`

### 5.3 反例 ❌（这些一律重写）

| 反例 | 问题 |
|------|------|
| `正常推进` | 零信息量 |
| `按计划进行中` | 零信息量 |
| `开发工作中` | 无动作无产出 |
| `无异常` | 只有状态没有进展 |
| `持续跟进` | 不可验证 |
| `已完成大部分` | 未量化 |

### 5.4 量化偏好

- 任务数：`12 个接口完成 8 个`
- 百分比：`前端页面完成 70%`（仅在确知时使用）
- 用例数：`41 用例通过 36，剩 5 个 P1`
- 文档版本：`PRD v1.0 / 设计稿 v2.3`
- 日期锚点：`预计周四回归`

## 六、类型 B（多功能）排序规则

同一项目下的功能行按**阶段推进度**排序，便于阅读：

```
方案阶段 → 设计中 → 设计完成待开发 → 开发中 → 测试中 → 测试完成待上线 → 代码上线 → 延期
```

即：越靠后的阶段排越后面；`延期` 永远排最后（作为风险提示）。
