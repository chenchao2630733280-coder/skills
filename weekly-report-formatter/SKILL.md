# weekly-report-formatter — 项目周报格式化

把零散的项目进展信息（口述要点、文档、task-board、git log、工作区日志）整理成**固定格式的周报**，
核心是三件事：**阶段判定准确**、**交付时间不臆造**、**进展描述有信息量**。

- **只整理不决策**：本 skill 不判断项目该不该延期、要不要加人，只如实格式化已有事实。
- **信息不足就问**：宁可留空或追问，也不编造交付时间和进展。
- **格式强约束**：输出必须能过 `scripts/validate_report.py`，否则不算交付。

## 一、何时调用

1. 用户明确要「整理周报 / 写周报 / 进度汇报」。
2. 用户给出一批项目进展素材，要求「按格式整理」。
3. 周期性汇报场景（每周五、月末），需要把多个项目当前状态汇总成统一格式。

> 若用户只是想聊某个项目的进展（不要正式周报），直接回答即可，不必走本 skill。

## 二、输出格式规范（核心，不可改）

### 2.1 类型 A — 单一系统，按整体项目描述

```
项目A
2026年9月18日：
方案阶段（2026-09-25）：完成需求调研与竞品分析，输出 PRD v1.0 待评审
开发中（2026-10-10）：订单模块 12 个接口完成 8 个，联调待测试环境就绪
```

### 2.2 类型 B — 拆分多子功能，按功能分别描述

```
项目B
2026年9月18日：
功能a：方案阶段：完成业务调研，方案待周三评审
功能b：开发中（2026-09-30）：前端页面完成 70%，接口已联调
功能c：测试中（2026-09-28）：一轮测试 32 个 bug，剩余 5 个 P1
功能d：延期（原定 2026-09-20，现 2026-09-27）：依赖第三方资质接口未返回
```

### 2.3 格式硬规则

| # | 规则 | 说明 |
|---|------|------|
| R1 | **日期行独立一行**，只写一次 | 每个项目块首行 `YYYY年M月D日：`，不重复出现在每条进展里 |
| R2 | 日期**必须实时获取**，禁止硬编码 | Windows：`Get-Date -Format "yyyy年M月d日"`；Unix：`date +"%Y年%-m月%-d日"` |
| R3 | 阶段名**必须**取自第八节白名单 | 不自造「研发中」「待评审」等词 |
| R4 | **有交付时间就写，没有就留空** | 留空时**连括号一起省略**，不写「（）」「（待定）」 |
| R5 | 冒号统一用全角「：」 | 时间括号用全角「（）」 |
| R6 | 类型 B 的功能名后加「：」再接阶段 | `功能a：方案阶段：描述` |
| R7 | **只写有进展的阶段**，空阶段不出现 | 不要 8 个阶段全列一遍填「无」 |
| R8 | 项目间空一行，条目间不空行 | 保持紧凑可读 |

> 类型 A 通常是 1 行（当前所处阶段），最多 2 行（如主体开发中 + 某部分延期）。
> 类型 B 每个有进展的功能一行；**本周无进展的功能整行省略**。

## 三、执行流程

```
确定报告日期 → 收集项目清单 → 逐项目判断类型(A/B) → 采集进展事实
→ 判定阶段 → 补交付时间 → 写进展描述 → 自检 → 校验脚本 → 输出
```

### 3.1 确定报告日期
用系统命令取当天日期（见 R2）。用户指定了汇报日期则以用户为准。

### 3.2 收集项目清单与素材
按优先级采集，**采不到的标「信息缺失」并追问用户**：

| 优先级 | 来源 | 取什么 |
|--------|------|--------|
| 1 | 用户本次对话给出的要点 | 直接事实 |
| 2 | 项目进度文件（如 `task-board.json`、`docs/进度.md`） | 已完成/进行中任务、阶段标记 |
| 3 | 工作区日志 `.workbuddy/memory/YYYY-MM-DD.md` | 本周实际做过的事 |
| 4 | `git log --since` | 本周提交范围（仅作佐证，不作描述主体） |
| 5 | PRD / 设计稿 / 测试用例目录 | 判断处于哪个阶段 |

> 若多个来源冲突，**以用户口述 > 进度文件 > 日志 > git**，并在描述中不露冲突，只取最新事实。

### 3.3 判断项目类型

| 判据 | 结论 |
|------|------|
| 一个系统/一个整体交付，无法切出并行子功能 | **类型 A** |
| 拆成了多个功能/模块，各自处在不同阶段 | **类型 B** |
| 整体单一但部分功能单独推进（1 个主体 + 1~2 个独立功能） | 类型 A 打底，独立功能按 B 的写法补行 |

### 3.4 判定阶段
对照 `references/stage-definitions.md` 的判定表，按**客观证据**判定，不按主观感觉。

### 3.5 补交付时间
- 有明确排期 → `(YYYY-MM-DD)`。
- 只有月份/周 → 写 `(9月底)` `(10月第2周)`，允许模糊但必须真实。
- **完全没排期 → 留空**，并在交付时把这个项目列入「待确认交付时间」清单问用户。

### 3.6 写进展描述
按 `references/stage-definitions.md` 第五节写法规范：
**动作 + 产出物 + 量化进度**，不写「正常推进」「按计划进行」。

### 3.7 自检与校验

```bash
python <skill>/scripts/validate_report.py 周报-2026-09-18.md            # 校验
python <skill>/scripts/validate_report.py 周报-2026-09-18.md --strict   # 警告也当错误
python <skill>/scripts/validate_report.py 周报-2026-09-18.md --out r.txt # 结果落文件（Windows 控制台乱码时用）
```

- exit 0 → 交付；非 0 → 按报错修完再交付。
- 无法运行脚本时，手工过一遍第九节检查清单。

## 四、输出去向

- **默认**：直接在对话里输出整理好的周报正文（用户可直接复制粘贴）。
- **用户要求落文件**：写 `<工作目录>/周报-YYYY-MM-DD.md`，编码 UTF-8。
- 信息缺失项：在周报正文后加一段「⚠️ 待补充」，逐条列出（哪个项目缺什么），**不要塞进正文里编造**。

## 五、关键约束

1. **不臆造交付时间**——这是最容易翻车的地方。没有就留空 + 进待补充清单。
2. **不臆造进展**——素材里没有的事不写；素材有歧义就问。
3. **不留空阶段占位**——「开发中：无」「测试中：暂无」这类行直接删掉。
4. **阶段名不改词**——白名单外的说法一律映射到白名单内（如「研发中」→「开发中」）。
5. **中文全角标点**——正文统一全角，日期格式除外。
6. **一个项目一段**——不跨项目合并描述，不复述上周内容。
7. **延期必须写清原定时间和新时间**——否则接收方无法判断影响面。

## 六、完整示例

```
智能客服系统
2026年9月18日：
开发中（2026-10-15）：意图识别模型接入完成，多轮对话 8 个场景已跑通 6 个，会话管理接口自测通过
延期（原定 2026-09-20，现 2026-09-27）：知识库导入依赖的 OCR 服务联调阻塞，等待对方排期

工惠通工会福利平台
2026年9月18日：
员工标签模块：开发中（2026-09-24）：Excel 导入扩展列方案已实现，字段映射与校验规则开发中
额度混合支付：测试中（2026-09-26）：一轮测试 41 用例通过 36，5 个边界用例修复中
结算账期配置：方案阶段：企业自定义账期的结算口径待财务确认
商品 SKU 独立定价：设计完成待开发（2026-10-08）：多租户定价模型评审通过，待排期
```

## 七、references 与 scripts

| 文件 | 用途 | 何时查 |
|------|------|--------|
| `references/stage-definitions.md` | 8 个阶段判定表、交付时间写法、进展描述正反例 | 3.4 / 3.5 / 3.6 步 |
| `templates/weekly-report-template.md` | 空白模板骨架 | 起草时套用 |
| `scripts/validate_report.py` | 格式校验（阶段白名单/时间格式/空描述/套话检测） | 交付前 |

## 八、阶段白名单（唯一合法值）

| 阶段 | 含义 |
|------|------|
| 方案阶段 | 需求调研、方案设计、评审中，尚未产出设计稿 |
| 设计中 | 正在做原型/UI/交互设计 |
| 设计完成待开发 | 设计定稿，已交付开发但未开工 |
| 开发中 | 编码实现中 |
| 测试中 | 已提测，测试执行中 |
| 测试完成待上线 | 测试通过，等待发布窗口 |
| 代码上线 | 已发布生产/灰度 |
| 延期 | 未按原定时间交付（**必须写明原定时间与新时间**） |

## 九、自检清单

- [ ] 报告日期是实时获取的真实日期，未硬编码。
- [ ] 每个项目块首行有且只有一个日期行。
- [ ] 所有阶段名都在第八节白名单内。
- [ ] 交付时间全部有据可查；无排期处括号已整体省略。
- [ ] 无任何「空阶段占位」行。
- [ ] 每条描述含「动作 + 产出/量化」，无「正常推进」类套话。
- [ ] 类型 B 的功能名与阶段之间用了「：」。
- [ ] 延期项都写明了原定时间和新时间。
- [ ] `validate_report.py` 通过（exit 0）。
- [ ] 信息缺失项已列入「待补充」清单，未编造。
