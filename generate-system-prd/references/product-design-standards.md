# 产品设计核心规范（PRD阶段）

本文件仅适用于产品设计与PRD阶段。页面字段、逐页布局、弹窗原型和标注由 `generate-prototype` 负责，不得在PRD阶段机械展开。

## 1. 产品决策原则

- 明确目标用户、问题、价值、范围与非目标。
- 以核心业务旅程组织功能，不以页面数量代替产品逻辑。
- 关键结论区分 `CONFIRMED / INFERRED / TBD`。
- 业务规则、权限、状态机和数据所有权必须可追溯。
- 高风险、合规、隐私与安全约束优先于普通转化和便利性。
- 已生效或需审计的数据通过版本、撤回、冲销或追加记录处理，避免静默覆盖历史。

## 2. 业务流程原则

- 每个核心旅程覆盖触发、输入、处理、反馈、后续动作和终止条件。
- 同时考虑正常、异常、权限、重复提交、并发冲突和中断恢复。
- 关键状态转换由服务端规则约束，不允许客户端任意写目标状态。
- 页面操作在PRD阶段只需要闭包到稳定的页面、弹层或命令ID；详细控件交互由原型阶段展开。

## 3. 数据模型原则

- PRD只定义概念/逻辑实体、关系、关键业务字段、敏感等级、生命周期、版本和审计要求。
- 不在技术栈未确认时固定SQL类型、索引、分区、主键策略或存储实现。
- 每个数据项有明确权威来源和维护角色。
- 敏感数据遵循最小必要访问、用途限制、期限和审计要求。

## 4. 页面信息原则

- `pages.json` 负责页面身份注册：ID、名称、路由、端侧、类型和模块。
- PRD正文只输出信息架构摘要、核心页面重点和核心旅程引用。
- 不生成固定S01-S04，不逐页复制字段、按钮、弹窗和ASCII。

## 5. 质量检查

- 章节存在不等于业务正确。
- 校验结果使用 `PASS / WARN / FAIL / NOT_REVIEWED` 并提供证据。
- 存在冲突或阻断型TBD时不得判定完全通过。
