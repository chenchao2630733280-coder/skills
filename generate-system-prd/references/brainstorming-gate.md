# PRD 前置澄清门禁（Brainstorming Gate）

本文件定义在进入 PRD 生成之前的需求澄清门槛。当关键输入缺失、未经脑暴确认或存在明显不确定性时，先使用本文件的问题模板与用户确认，再执行 `generate-system-prd` 的生成流程。**门禁阶段不撰写产品需求文档（PRD）。**

## 1. 何时启用本门禁

满足任一条件时，先澄清后生成：

- 只有一句想法，缺少产品定位、终端类型或目标用户；
- 需求中存在"智能""自动""实时"等不可验证的含糊表述；
- 关键业务流程、MVP 范围或核心业务规则尚未确认；
- 用户明确要求"先帮我理一理"而非"直接写 PRD"。

输入完整且用户明确要求直接生成时，可跳过本门禁，但需在文档开头列出"待确认假设"。

## 2. 澄清问题模板

向用户收集以下信息（已提供的跳过，缺失的标记"待确认"，不得编造）：

```markdown
1. 功能/产品名称
   []
2. 初步定义（草案概念）
   [产品大致做什么、解决什么问题]
3. 开发原因
   [业务诉求或用户痛点]
4. 终端类型与范围
   [admin_web / native_app / mobile_web / mini_program / hybrid / multi_end；完整系统或单一功能]
5. 目标用户与使用场景（可选）
   []
6. 初始用户流程（可选）
   [用户如何进入、操作和完成目标]
7. 已知约束（可选）
   [预算、工期、合规、技术依赖等]
```

## 3. 生成前必须完成的确认

1. 就产品目的、用户画像、价值、风险、边缘场景、约束条件及假设前提提出澄清问题；
2. 识别构想中的隐藏假设，请用户确认、修正或标记待验证；
3. 以资深产品经理视角评估：可行性、用户体验清晰度、问题—解决方案匹配度、风险与替代方案；
4. 上述信息确认前，不进入逐章生成；确认后按 `generate-system-prd` 的 Step 1 继续。

> 完整的脑暴方法（问题维度、假设表、方案发散、评估结构）由 `brainstorm-product-feature` Skill 提供；本文件仅是 PRD 阶段的最小澄清门槛。
