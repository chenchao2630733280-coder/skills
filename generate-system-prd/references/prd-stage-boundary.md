# PRD 阶段职责边界与校验规则

本文件优先级高于通用产品设计参考中的逐页原子设计要求。

## 1. 产品方案与页面原型分工

- PRD：范围、旅程、业务规则、状态机、逻辑数据、权限、稳定页面身份和核心动作意图。
- 原型：一个完整页面原型Markdown主文档，以及逐页字段、布局、交互、弹层、状态差异和标注。
- 系统实施：物理数据库、API、架构、索引和部署。

五个 Skill 的顺序是推荐顺序，不是强制依赖。PRD可从需求、脑暴、原型、HTML、代码或运行系统证据生成或逆向重建。

## 2. 标注

PRD 不生成或固定 S01~S04。原型阶段按真实功能区域生成任意数量的 SXX。

## 3. 数据模型

PRD 使用逻辑类型和业务约束。physicalType 默认 null；未经技术评审不得标为 CONFIRMED。

## 4. 校验结论

只允许 PASS / WARN / FAIL / NOT_REVIEWED。章节或编号存在不等于业务正确。权限安全、物理数据库、合规和专业正确性若无人工评审证据，应使用 NOT_REVIEWED。

## 5. 信息架构与原型输入去重

- 第 2.3 节只输出端、模块、页面编号范围、路由命名空间、页面数量和核心旅程。
- `output/spec/pages.json` 是页面 ID、名称、端侧、类型和完整路由的权威来源，并保存产品阶段的核心动作意图。
- 完整动作结构由 Prototype 写入 `actions.json`。
- 第 8 章只输出核心体验原则、关键页面设计重点、关键流程原型要求、特殊场景和待验证问题。
- 禁止在第 8 章生成 P01~PXX 全量逐页规格或复制第 2.3 节页面清单。
- 同一页面的路由、类型或名称出现两份完整权威定义时，交叉校验必须标记 `FAIL`；仅冗余重复时至少标记 `WARN`。

## 6. 兜底来源记录

缺失脑暴或其他上游不阻断PRD。任何逆向或最小补全必须记录到 `pipeline-context.json`，并使用 `reverseEngineered / generatedByFallback / INFERRED / TBD` 标记来源和置信度。
