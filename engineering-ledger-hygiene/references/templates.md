# 三层账本骨架模板

三份文件的骨架。按项目调整，但**分节结构与纪律注释保留**（纪律注释是防止下一轮腐烂的关键）。

---

## ① 主档 `MEMORY.md`（当前权威口径）

```markdown
# <项目名> — 项目记忆（当前权威口径）

> 工程约定 N 条见同目录 `ENGINEERING_RULES.md` —— **改任何文件前先读它**。
> 本文件只记「当前权威口径 + 不可丢的产品契约」；历史轮次的推导过程不再保留。

## 一、现状基线（权威值，YYYY-MM-DD 实测）
- <计数项>：<值>（**权威值取 `<权威脚本>`，它会重写 <产物>；审计时勿跑**）
- <快照档位>：<当前> / <起点> / <历史基线>

## 二、<核心结构 / 导航 / 模块>
<一句话结论 + 表格>

## 三、<关键口径 / 状态机 canonical>
<表：码 / 标签 / 要点>

## 四、关键产品约定
<条目，每条一个「不可丢」的契约；刻意不统一的东西在此声明>

## 五、<数据源 / 共享层>
- 唯一数据源：<文件>；各端只做投影；<投影规则>

## 六、命名与编号空间
<前缀池 + 现役区间>

## 七、已由后续轮次推翻的旧口径（勿再引用）
- ~~<旧口径>~~ ⇒ <现行口径>（推翻于 YYYY-MM-DD）

## 八、待修项（YYYY-MM-DD 只读审查发现，尚未修）
- <项>（报告：<路径>）
```

**纪律**：① 主档**不写历史推导**；② 每个计数带权威源指针；③ 「已推翻」小节只增不删（是防止旧口径复活的疫苗）。

## ② 规则账本 `ENGINEERING_RULES.md`（改前必读）

```markdown
# <项目名> — 工程约定（N 条，改文件前必读）

> 与 `MEMORY.md` 同目录。凡涉及 <编辑 / 编码 / 一致性 / 共享层 / 校验 / 文案 / UI> 的改动，先读本文件。
> 约定写法 = 一个已证实的坑 + 一条可执行判据 +（可选）来源轮次。

## A 编辑
1. <可执行判据>（例：判 CRLF 用 `crlf>0 and crlf>=lf*0.9`）—— 来源：<轮次>
2. ...

## B 编码
## C <一致性 / JSON>
## D <共享层 / 派生>
## E <扫描 / 校验>
## F <语义 / 文案>
## G <前端 / UI>
## H 环境与门禁
39. **标准门禁（N 条，全绿才可收工）**：<脚本 + 断言数>…（**以上计数为 YYYY-MM-DD 实测值；修改门禁后务必同改本行**）
```

**纪律**：
- 顶部**必有「改前必读」声明**并点名涉及范围。
- 每条是**可执行判据**，不是「注意点」。
- 涉及计数的那条，末尾**必带「改动后同改本行」**的自我提醒（M3）。
- 标来源轮次，便于追溯。

## ③ 日日志 `memory/YYYY-MM-DD.md`（append-only）

```markdown
# YYYY-MM-DD 工作日志

## <本轮主题>
- 用户指令：「<原话>」
### 做法
- <关键动作 / 命令 / 判据>
### 结论
- <发现 / 判定>
### 产出
- <文件路径 + 一句话>

（下一轮直接在此文件末尾追加新小节；**不重写旧内容**）
```

**纪律**：只追加；不记瞬态信息（临时路径 / 工具报错 / 搜索结果）；跨会话有价值的才写。

## 主档重写检查表（M1 用）

- [ ] 被推翻的口径已移入「已推翻」小节或删除，且标了日期。
- [ ] 可派生的计数已改为「权威源指针」。
- [ ] 推导过程 / 细节参数已下沉到规则账本或专题文件。
- [ ] 重写后长度留有余量（未贴上限）。
- [ ] 「不可丢的产品契约」逐条核对仍在位。
- [ ] 日志记录本次重写（压缩 X → Y，下沉 Z）。
