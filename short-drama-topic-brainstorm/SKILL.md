# Short Drama Topic Brainstorm — AI 短剧选题脑暴

本 skill 是 AI 短剧制作流水线（short-drama-forge-master）的**阶段 0（可选）**，职责是把用户的模糊想法/一句话需求结构化为短剧选题方案，供 short-drama-blueprint 消费。

**与 short-drama-blueprint 的关系**：本 skill 产出"选什么题"，blueprint 产出"怎么立项"。本 skill **不生成蓝图**，只做选题生成、多样性约束、趋势验证、评分与 Top N 推荐。

**短剧语境硬约束**（贯穿全程，所有候选必须满足）：
- 竖屏（1080x1920）、单集 1-3 分钟、总集数 60-100
- 每集结尾必须有强卡点；前 3 秒必须抓住观众

---

## 一、何时调用

满足以下任一条件即调用：
- 用户说"想做部短剧但不知道做什么 / 脑暴选题 / 找点子 / 选题方向"
- 用户有模糊想法（如"想做部爽剧"）但未明确题材/类型/受众
- short-drama-forge-master 阶段 0 路由（需求模糊时）调度到本 skill

**不要**在以下场景调用：
- 用户已有明确选题（直接走 short-drama-blueprint）
- 用户要修改已有短剧的剧本/成片（直接用 Edit/Write 或对应阶段 skill）
- 用户要做长剧/电影（本 skill 面向 60-100 集竖屏短剧）
- 纯咨询"短剧怎么做"（用对话回答）

---

## 二、输入与输出

**输入**：
- 用户的初始想法（可模糊，如"想做部爽剧"）
- 可选：约束（题材偏好/受众/集数/预算/变现目标/平台）
- 可选：用户提供的参考短剧名

**输出**（固定路径，与总纲 §八 一致，1 份文档）：
- `docs/TOPIC_PROPOSAL.md` — 选题方案（12 个候选 + Top 3-5 + 1 个推荐）

项目根目录为用户指定的短剧项目工作目录 `{project}/`。**禁止自定义输出路径**。

---

## 三、脑暴流程（6 步）

### Step 1：需求澄清

用 AskUserQuestion 确认 2-3 个关键约束（不要一次问太多）：

| 维度 | 选项 |
|---|---|
| 题材偏好 | 都市/古装/悬疑/甜宠/逆袭/战神/穿越/重生/无偏好 |
| 受众 | 女性向/男性向/全年龄/未知 |
| 集数与预算 | 60 集轻量 / 80 集标准 / 100 集重度 / 未知 |
| 变现目标 | IAA 广告 / 分账 / IP 联运 / 暂不考虑 |

用户未提供约束时，按默认假设：**无题材偏好 + 全年龄 + 60 集轻量 + IAA 为主**，并在提案中标注"基于默认假设"。

### Step 2：观看动力引擎

对每个候选选题，用四个时间尺度追问观看动力（细则见 `references/viewing-motivation.md`）：

| 时间尺度 | 核心追问 | 小满足（示例） |
|---|---|---|
| 第一集 | 观众为什么点开？前 3 秒是否被钩住？ | 开场即冲突/身份反转 |
| 前十集 | 观众为什么继续追？卡点是否密集轮换？ | 每集结尾悬念/关系升温 |
| 中段 | 主线是否疲劳？是否有新变量注入？ | 新角色登场/秘密揭晓/阵营反转 |
| 终局 | 结局是否值得追完？是否烂尾？ | 核心谜底揭晓+情绪释放 |

**规则**：任一候选至少满足"第一集 + 前十集"两个尺度的小满足，否则淘汰或补强；中段与终局为加分项（评分权重见 Step 5）。

### Step 3：趋势雷达

用 WebSearch 扫描短剧市场趋势，按四级信号分层（细则见 `references/trend-radar.md`）：

| 层级 | 定义 | 示例 |
|---|---|---|
| A 确认事件 | 已有明确爆款/官方榜单事件 | 某短剧登顶分账榜首 |
| B 周期 | 可识别的周期性规律 | 春节档战神题材回升 |
| C 上升信号 | 数据/声量上升但未确认 | 悬疑短剧话题量连续上涨 |
| D 弱信号 | 早期苗头，证据不足 | 小众题材圈层热议 |

**硬规则**：
- **禁止把预测写成确定事实**：D/C 级信号必须标注"待验证/趋势预判"，不得在推荐理由中写成"已验证爆款方向"
- 所有信号必须记录来源与时间（见 trend-radar.md 来源记录规范）
- 趋势验证失败时**跳过趋势环节，不阻断流程**（见 runtime.yaml degrade 第 1 条），提案头部标注"趋势未验证"

### Step 4：创意多样性引擎

基于变量池生成候选选题（细则见 `references/diversity-engine.md`）：

**变量池**（5 个变量）：
1. 题材：都市/古装/悬疑/甜宠/逆袭/战神/穿越/重生/职场/家庭/奇幻/科幻...
2. 主人公：身份/年龄/性格/起点处境
3. 关系：对手关系/情感关系/同盟关系
4. 观看动力：爽感/悬念/情感/逆袭/共鸣/猎奇/成长/复仇/甜宠/守护...
5. 结局：HE / 悲剧 / 反转 / 开放式 / 团灭 / 留白续季

**生成配额（硬性）**：单轮生成 **12 个候选选题**，必须：
- 覆盖 **≥6 类题材**
- 覆盖 **≥8 类观看动力**
- 同一变量取值（如同一题材/同一主人公设定）的候选 **≤30%**（12 个中最多 3 个）

**反倾向机制**：首轮生成后统计变量分布；若某变量过度集中（>30%）或某类题材/动力空置，强制用"反倾向选题"补齐——从稀疏变量取值中生成新候选并删减同质化候选，直到配额达标。

### Step 5：评分系统

每个候选按满分 **100 分**评分，**观看动力优先**（权重最高）：

| 维度 | 权重 | 说明 |
|---|---|---|
| 观看动力 | 40 | 四时间尺度满足度：第一集 15 + 前十集 15 + 中段 5 + 终局 5 |
| 题材机会 | 15 | 与趋势雷达信号匹配度（A 级信号强相关加分） |
| 差异化 | 15 | 与现有爆款/同题材的差异度（差异化锚点清晰度） |
| 可行性 | 15 | AI 制作难度（场景/角色/特效量，是否适配全 AI/图文制作） |
| 商业化 | 15 | IAA/分账适配度，付费点与广告点设计空间 |

**判定线**：≥80 强推荐；60-79 可备选；<60 淘汰。趋势未验证时"题材机会"按中性分（7-8 分）计。

### Step 6：Top N 推荐

从通过评分的候选中选 **Top 3-5 个**，按 **≥8 个维度**输出对比推荐：

1. 一句话定义
2. 题材与差异化锚点
3. 观看动力（四时间尺度满足度）
4. 趋势匹配（信号层级 + 置信度）
5. 目标受众
6. 制作可行性（AI 制作难度星级）
7. 商业化模式
8. 风险与应对
9. 综合评分

最终**推荐 1 个**，推荐理由必须含：观看动力最完整 + 差异化最清晰 + 与约束匹配。

## 五、交互约定

1. **Step 1 用 AskUserQuestion 询问约束**，不要自行假设所有约束
2. Step 2-6 自主执行，不频繁打断用户
3. 产出 TOPIC_PROPOSAL.md 后向用户简报：
   - "共脑暴 {12} 个候选（覆盖 {N} 类题材、{M} 类观看动力），通过评分 {K} 个，推荐：{一句话定义}"
   - "路径 docs/TOPIC_PROPOSAL.md，下一步可调用 short-drama-blueprint 生成立项蓝图"
4. **不要**自行调用 short-drama-blueprint，让用户确认推荐方案后再决定
5. 用户对推荐方案不满意时，根据反馈调整候选重新脑暴；**重生成最多 2 轮**，仍不满意则暂停交人工（见 runtime.yaml degrade 第 2 条）

## 六、质量检查清单

产出前自检：

- [ ] Step 1 约束已确认（或按默认假设并标注）
- [ ] 候选 ≥12 个，覆盖 ≥6 类题材、≥8 类观看动力
- [ ] 同一变量取值 ≤30%（12 个中 ≤3 个），变量分布表可见
- [ ] 反倾向机制已执行（空置取值已补齐）
- [ ] 每个候选都有四时间尺度观看动力验证（至少满足第一集+前十集）
- [ ] 每个候选都有评分（满分 100，观看动力权重最高 40）
- [ ] 趋势信号按 A/B/C/D 分层，C/D 级未写成确定事实
- [ ] 趋势数据获取失败时已标注"趋势未验证"且未阻断
- [ ] Top 3-5 个候选，≥8 个推荐维度
- [ ] 推荐理由含观看动力/差异化/约束匹配
- [ ] 短剧语境约束满足（竖屏/单集 1-3 分钟/总集数 60-100/每集强卡点）
- [ ] 文档无 TODO/占位文字
- [ ] 自检未通过项已局部重做（≤2 轮）或标注交人工
