# 趋势雷达：信号分层与来源记录规范

本文件是 short-drama-topic-brainstorm 的懒加载细则，Step 3（趋势雷达）时读取。

## 一、四级信号分层

| 层级 | 名称 | 定义 | 判定标准 | 可信度 | 文档可写作语气 |
|---|---|---|---|---|---|
| A | 确认事件 | 已发生的明确爆款/官方事件 | 有榜单数据/官方公告/多个独立信源 | 高 | "已验证/已确认" |
| B | 周期 | 可识别的周期性规律 | 历史 2+ 期同规律重现 | 中高 | "呈周期性/按惯例" |
| C | 上升信号 | 数据/声量上升但未确认 | 单平台数据上涨/话题量上升 | 中 | "呈上升趋势/待验证" |
| D | 弱信号 | 早期苗头，证据不足 | 圈层热议/单条爆款/个人观察 | 低 | "可能是方向/需验证" |

**硬规则**：
1. **禁止把预测写成确定事实**：C/D 级信号在文档中必须带"待验证/趋势预判"标注，不得出现在推荐理由的"已验证"部分
2. A 级信号可直接引用；B/C/D 级信号一律标注层级与置信度
3. 所有信号必须记录来源与时间（见 §三）
4. 评分系统"题材机会"维度只对 A 级强相关加分，C/D 级只做中性偏上参考

## 二、扫描关键词模板

- "{年份} 短剧 爆款 分账 榜单"
- "{年份} 竖屏短剧 题材 趋势"
- "{年份} 短剧 备案 题材 数量"
- "{关键词} 短剧 话题 热度"
- "{关键词} 短剧 完播率 留存"

## 三、来源记录规范

每条信号必须按以下字段记录：

| 字段 | 必填 | 说明 |
|---|---|---|
| 信号 | 是 | 一句话描述 |
| 层级 | 是 | A/B/C/D |
| 来源 | 是 | 平台/榜单/文章 URL 或名称 |
| 时间 | 是 | 观察时间（精确到月） |
| 证据 | 是 | 数据/事实（如"单月分账 X 万""话题量环比 +X%"） |
| 置信度 | 是 | 高/中/低 |
| 影响题材 | 是 | 影响的题材方向 |

**示例**：

| 信号 | 层级 | 来源 | 时间 | 证据 | 置信度 | 影响题材 |
|---|---|---|---|---|---|---|
| 某战神短剧登顶分账榜 | A | XX 平台榜单 | 2026-05 | 月分账 3000 万 | 高 | 战神/逆袭 |
| 悬疑短剧话题量连续 3 月上涨 | C | 某数据平台 | 2026-05 | 环比 +35% | 中 | 悬疑 |
| 某圈层热议"祖母复仇"题材 | D | 评论区/社群观察 | 2026-06 | 仅单条爆款 | 低 | 家庭/复仇 |

## 四、降级规则

趋势数据获取失败（WebSearch 不可用/无有效结果）时：
- **跳过趋势环节，不阻断流程**（runtime.yaml degrade 第 1 条）
- 在 TOPIC_PROPOSAL.md 头部标注"趋势状态：未验证（跳过）"
- 评分系统"题材机会"维度按中性分（7-8 分/满分 15）计，并在推荐理由中注明"未做趋势验证"
