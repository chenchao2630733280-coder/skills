# 公共情绪IP选题开采（工业化选题库）

## 版本定位

本 Skill 解决一个具体问题：**当"公共情绪IP"这个方法论的素材从几十条扩到上百条时，如何把它变成一张可排序、可查、可投产的资料库数据表。**

**字段与评分的机读契约见 `references/field-and-scoring-schema.md`**（16 字段清单、select 合法取值、评分模型、题材族群、校验清单）。建表与评分时以该文件为准，不自行发明字段名与档位取值。

它不负责"想点子"（那是 `ai-short-drama-topic-planner` / `short-drama-topic-brainstorm` 的职责），也不负责"写剧本"（那是 `short-drama-script`）。它负责**中段**：把零散素材批量转成结构化资产，并从中选样。

```text
上游：选题脑暴（想方向）→ 找到一批素材
   ↓
【本 Skill】素材 → 结构化资料库 → 投产短名单
   ↓
下游：short-drama-blueprint / short-drama-spec（单条展开）
```

**核心判断：素材收集不是资产，结构化才是。** 100 条散在文档里的素材，价值低于 50 条填满字段、可排序可筛选的表。

---

## 一、适用判断

### ✅ 适用

- 用户已有一批公共情绪素材（历史人物、现实新闻人物、文物、非遗、被改编污名的历史人物），希望规模化整理
- 要把素材做成资料库/数据表/总表，且需要**多角色字段**（情绪点、介绍、剧本等）
- 要从上百条素材里挑出"最值得做"的少数几条
- 需要给素材标注合规风险、改编路线

### ❌ 不适用

- 只有 3~10 条素材 → 直接对话输出即可，不必建表
- 需要买版权的现成作品改编（走 L1 授权逻辑，另一套流程）
- 原创悬疑/纯虚构（不依赖公共情绪）

---

## 二、五大公共情绪池（素材分类的第一维度）

**凡是"中国观众已经替你建好情绪"的东西，都是这个池子里现成的 IP。**

| 情绪池 | 已建好的情绪 | 可借方向 | 典型素材 |
|---|---|---|---|
| **意难平** | "本该如此，却偏偏没能如此" | 改命、圆梦、补笔 | 岳飞/诸葛亮/项羽/文天祥/崖山 |
| **团圆** | "盼了太多年，终于回来了" | 离散、寻亲、盼归 | 寻亲、DNA认亲、文物回家、遗骸归国 |
| **正名** | "他明明是好的，被冤枉了" | 平反、昭雪、洗冤 | 冤案平反、被小说污名者 |
| **意气** | "这口气我咽不下去" | 复仇、打脸、翻身 | 孤军、以弱胜强、以少敌多 |
| **传承** | "我替你先看着" | 师徒、守望、传艺 | 非遗传承人、守墓人、邮路、灯塔 |

**判断标准：需要解释的情绪，都不是公共情绪。**

---

## 三、借IP三层级（决定成本与风险）

| 层级 | 借什么 | 版权成本 | 合规风险 |
|---|---|---|---|
| **L1 借名** | 人物名、故事名 | 高（授权/备案） | 高（魔改争议） |
| **L2 借情绪** | 已完成众筹的集体情绪 | 零 | 中（可能撞红线） |
| **L3 借结构** | 因果骨架，换壳 | 零 | **低** |

**甜蜜点是 L3** —— 既拿到 L2 的情绪流量，又绕开 L1 的合规成本。

```text
真实历史 → 提取「情绪结构」→ 铸进架空世界 → 观众"感觉像"，但查不到人
```

**三道防线（L3 必须全做）：**
1. 名字全换（不出现任何真实人名/朝代/地名/年号）
2. 结构照搬（保留因果骨架）
3. 标注齐全（【AI生成视频】+【本作品为完全虚构的架空故事…与任何真实历史无关】）

## 四、四条建议路线（素材该走哪条路）

**这一维度是"这条素材最适合怎么讲"，与合规风险共同决定剧本写法。**

| 路线 | 定义 | 适用素材 | 写法 |
|---|---|---|---|
| **有据改笔(H)** | 历史结局与人物气节一字不改，只从史书留白处补一个虚构小人物 | 正史有载、结局不可改的重大事件 | 视角下移到驿卒/门客/书吏/家眷，主角是史书里不该出现在正文的人 |
| **圆梦架空(K)** | 换壳不换魂，真实因果保留、名号全换 | 结局太惨、直改必踩红线的事件 | 架空世界里"这次他能成"，补偿感要具体克制、有代价 |
| **现实题材** | 当代真实人物/事件，按公开报道讲 | 寻亲、守墓、非遗、冤案、文物回家 | 把新闻里的一句话展开成情绪线 |
| **原创架空** | 无公共IP来源的纯虚构设定 | 只有情绪，没有对应真实事件 | 完全虚构，但内核必须落到真实公共情绪上 |

## 五、合规风险三档（决定架空尺度）⚠️ 刚性映射

**这是最容易出错的地方：路线决定"怎么讲"，风险决定"能不能用真名"。两者必须分开判定，不可混为一谈。**

| 档位 | 尺度 | 具体做法 |
|---|---|---|
| **低·可直改** | 保留真名/真地/真机构 | 直接讲，不做化名处理 |
| **中·须架空处理** | 保留骨架与情感，**人名或地域必须模糊化/化名** | 改称"那位将军""北边那座城""当年的那个县城" |
| **高·须资质备案** | **彻底换壳**：不出现任何真实人名/朝代/地名/年号/官职/番号 | 人名地名全部虚构，只保留因果骨架，标注虚构 |

### 分档的实操判断

```text
低·可直改：
  - 非遗传承人、守墓人、邮递员等普通人
  - 文物（兵马俑/青铜器/编钟）—— 物不是人，无定性风险
  - 已由官方正式平反的案件
  - 器物工艺、仪式流程

中·须架空处理：
  - 涉及未完全定性的案件（须化名）
  - 涉及军队番号、战役细节
  - 涉及仍在世的当事人及其家属
  - 涉及宗教、民族、地域敏感的历史事件

高·须资质备案：
  - 有官方历史定论的重大历史人物（岳飞/袁崇焕/于谦/方孝孺）
  - 涉及政权更迭、政治定性的事件
  - 涉及对外战争、民族冲突
  - 涉及近代史中的争议人物
```

**⚠️ 高风险素材不是不能做，而是必须换壳。** 情绪强度往往是全表最高的（97~98），但落地周期长，选样时应降档处理。

## 六、零门槛四条准入线（素材层面的硬门槛）

对每条素材做准入检查。**一条不通过即淘汰或重构。**

| # | 准入线 | 检验方法 | 不通过的表现 |
|---|---|---|---|
| 1 | **一句话能讲完** | 给外行讲，30 秒内必须说"懂了" | 需要先介绍背景/行业/规则 |
| 2 | **开局画面可见** | 能力或处境能否直接画出来 | 必须用旁白交代设定 |
| 3 | **爽点本能可懂** | 打脸落在物理事实上（东西被拿走/人跪下/门被踹开） | 爽点依赖概念理解、数据对比 |
| 4 | **无行业术语** | 全剧不出现需要查字典的词 | 出现需注释的专业名词 |

### 金手指方向律

**金手指必须指向"改变世界的能力"，而非"看清世界的能力"。**

```text
✅ 能改变：能救、能夺、能换、能拆、能造、能锁、能放
❌ 只能看：听见死兆、算出暴雨、判断真伪、预知未来
```

**文物类素材须特别注意**：文物"被观赏"是纯感知型金手指（❌），必须转为**"复原/修复/复刻"的主动型**（✅）才成立。

## 七、三类描述字段（递进链）

**每条素材必须同时具备三层描述，形成钩子 → 信息 → 可开写的递进链。**

```text
一句话情绪点（钩子）  → 素材介绍（史实与情绪内核）→ 剧本（可开写框架）
   用户为什么点开              用户信不信            创作者能不能直接开工
```

### 7.1 一句话情绪点

- **规格**：一句话，含具体事实与数字，不写评价
- **反例**：❌"岳飞很惨" ✅"十年之功，废于一旦——十二道金牌"
- **要点**：把"差一步"写具体。越"差一步"越好，越"整体崩盘"越危险

### 7.2 素材介绍

- **规格**：84~200 字，覆盖四要素
- **四要素**：来源/时代/地点/人物 + 关键事实与数字 + 情绪内核 + 可借点

### 7.3 剧本（框架大纲颗粒度）

- **规格**：150~260 字，**必须与「建议路线」+「合规风险」一致**
- **要素**：视角人物（有具体身份与处境）+ 可见的开局画面 + 线路走向 + 情绪落点
- **⚠️ 硬约束**：`head` 里的路线与风险标签必须与表内字段**逐字一致**，不能按"素材本身最适合怎么讲"自行判定

**head 格式：**

```text
【路线】<建议路线>【处理】<合规风险> → <一句处理说明>

<空行>

<框架正文>
```

### 7.4 不要模式化

**反面案例**：186 条全部写成"开局→全剧→中途→最后一集"四段式。读起来像同一篇文章填了不同的词。

**正面做法**：条目之间结构必须错开 ——
```text
按时间线推进 / 按物件推进（马鞍、旗、碑、钱币、笔）
按单场景推进 / 按人物关系推进（岳父家下人、邻村老农）
一个长段 / 3~6 个短句段
```

## 八、规模化生产流程

### 8.1 建表（字段设计）

**最少字段集（14 个）：**

| 字段 | 类型 | 说明 |
|---|---|---|
| 编号 | text | P-001 格式，主键 |
| 公共IP素材 | text | 素材名 |
| 情绪池 | select | 五大池 |
| 情绪强度 | number | 0~100 |
| 自带流量 | select | S级·全民皆知 / A级·高认知 / B级·垂类认知 / C级·需科普 |
| 一句话情绪点 | text | 钩子 |
| 可借方向 | text | 具体怎么借 |
| 改编层级 | select | L1 借名 / L2 借情绪 / L3 借结构 |
| 建议路线 | select | 有据改笔(H) / 圆梦架空(K) / 现实题材 / 原创架空 |
| 合规风险 | select | 低·可直改 / 中·须架空处理 / 高·须资质备案 |
| 零门槛达标 | checkbox | |
| 对应本池选题 | text | |
| 备注 | text | |
| 素材介绍 | text | §7.2 |
| 剧本 | text | §7.3 |

**选样阶段追加字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| 投产优先级 | select | S 首推 / A 次推 / B 备选 / 黑马位 / 暂缓 |
| 推荐理由 | text | 为什么选它 |

**select 选项是刚性的** —— 写入值必须在 schema 中已存在，否则报 `invalid fields`。新增选项须先改字段配置。

### 8.2 批量填充（关键工程要点）

大量条目文本的填充，**不要逐条手写，用脚本 + 分批写入。**

```text
1. 先用一条命令确认表结构（字段名 + field_id + select 选项）
2. 用脚本维护一个 {编号: 内容} 字典，脚本提供三类命令：
     count          → 校验条数、字数分布、分布统计
     rows a b       → 输出第 a~b 条的更新 payload
     sample         → 打印指定编号，人工抽查
3. 分批写入（每次 1~100 条，建议 95 + 91 两批）
4. 回读全量校验
```

### 8.3 大批量文本写作（子 Agent 并行）

当需要为 100+ 条素材各写一段 200 字内容时：

```text
1. 导出上下文文件（编号 + 全部标签字段 + 已有描述）
2. 按「建议路线」拆成 3~4 组，每组一个子 Agent 并行处理
3. 每个子 Agent 只负责一条路线，prompt 里写清该路线的语义 + 风险分档映射
4. 产出为 JSON：{"编号": {"head": "...", "body": "..."}}
5. 合并脚本做逐条硬校验（见 §8.4）
```

**为什么按路线拆**：同一条路线内的写法规则一致，子 Agent 不容易串味；跨路线混在一个 Agent 里，标签对齐容易出错。

### 8.4 校验清单（每次写入后必做）

```text
□ 条数正确（总数 = 预期）
□ 编号唯一、无空值
□ 目标字段全部满填（无空）
□ 目标字段的标签与表内字段逐字一致（路线 / 风险）  ← 最容易漏
□ 其他字段未被污染（未写字段仍是原值）
□ 文本无 ASCII 直引号（用「」，否则破坏脚本解析）
□ 抽样人工复核（优先看最高分、最低分、每条路线的第一条）
```

**⚠️ 最关键的校验是"逐字比对标签"。** 条数对了不代表内容对 —— 曾经出现的真实事故：186 条剧本全部写成了同一条路线的笔法，条数完全正确，但 119 条与标签不符。

## 九、投产评分与选样

### 9.1 评分模型（满分 100）

| 维度 | 权重 | 规则 |
|---|---|---|
| 情绪强度 | 40 | ≥90 线性映射 |
| 自带流量 | 20 | S18 / A14 / B8 / C3 |
| **落地效率** | 22 | 低风险 22 / 中 14 / 高 6 |
| 层级可借 | 10 | L3 10 / L2 7 / L1 3 |
| 现实题材加成 | 8 | 真实感 + 低合规成本 |

**落地效率的权重高于直觉**：高风险素材情绪分往往最高（97~98），但须资质备案 + 换壳，实际周期长，不应占首推位。

### 9.2 ⚠️ 纯分数排序不可用

**真实教训**：186 条按分数排序后，Top 30 里挤了 6 条寻亲 + 6 条冤案 + 5 条文物回家 —— 同质化到没有参考价值。

**必须改为三层结构：**

```text
第 1 层  分数打底     → 得到候选池
第 2 层  题材族群去重 → 同一族群最多取 1~2 条，其余降备选
第 3 层  黑马位补差异 → 强制留出位置给"分数中等但结构极稀有"的选题
```

### 9.3 档位设计

```text
S 首推   8 条左右   情绪95+ / 低风险 / 题材互不重复
A 次推  10 条左右   补题材缺口，或高风险但值得投入的唯一一条
B 备选  12 条左右   同族群次优，整组打包时启用
黑马位   6 条左右   分数不高但角度独特（例：加害者替受害者申冤、荒诞史料）
```

### 9.4 黑马位的必要性

全按分数排会系统性漏掉这类选题：

```text
- 视角反转：真凶主动写"偿命申请书"，为已被枪毙的人求清白
- 荒诞史料：两个姓氏六百年不通婚
- 非人视角：以"一块土地"为主角
- 原型钩子：孙悟空的原型是谁
```

**它们的分数中等，但结构稀缺度远高于同分条目。**

## 十、常见坑（实战记录）

| 坑 | 现象 | 解法 |
|---|---|---|
| **标签漂移** | 方法论升级后，早期标注的路线标签未同步更新，导致剧本写法与标签不符 | 每轮写作前**先回读表内标签**，只按标签写，不按自己的判断写 |
| **只校验条数** | 186 条条数正确，但 119 条路线写错 | 必须**逐字比对**目标字段的标签值 |
| **ASCII 直引号** | 脚本正文里用 `"` 做引号，破坏 Python 字符串 | 正文引号一律用 `「」` |
| **多行 docstring 被误伤** | 引号修复脚本改坏了三引号字符串 | 脚本头部用 `#` 注释块，不用多行 docstring |
| **只有一条路线的笔法** | 全表读起来像同一篇文章 | 强制结构错开（时间线/物件/单场景/关系） |
| **select 写入失败** | 报 `invalid fields` | 先确认选项在 schema 中存在 |
| **翻页参数用错** | 服务端静默忽略，反复返回同一页 | 用 `start_cursor`（不是 `cursor`） |
| **字段名用错** | 批量更新报错 | record 结构是 `{"record_id": ..., "properties": {...}}` |
| **纯分数排序同质化** | Top 30 全是同一族题材 | 加题材去重 + 黑马位（§9.2） |

## 十一、执行流程

```text
1. 判断适用性（§一）——素材是否够多、是否需要建表
2. 素材分类：按五大情绪池（§二）归类
3. 逐条判定「改编层级」（§三）+「建议路线」（§四）+「合规风险」（§五）
4. 零门槛准入检查（§六），不通过者淘汰或重构
5. 建表并设计字段（§8.1）
6. 批量填充三类描述字段（§7 + §8.2/8.3）
7. 回读校验（§8.4）——重点是标签逐字比对
8. 投产评分（§9.1）+ 题材去重选样（§9.2/9.3/9.4）
9. 回写「投产优先级」+「推荐理由」
10. 交接下游：单条展开走 short-drama-blueprint / short-drama-spec
```

## 十二、标准输出

```text
一、素材池概览
   总条数 / 五大情绪池分布 / 路线分布 / 风险分布 / 层级分布

二、结构化资料库
   表名 / 表地址 / 字段清单 / 填充率

三、样本（抽样展示递进链）
   一句话情绪点 → 素材介绍 → 剧本

四、投产短名单
   S 首推（含推荐理由）
   A 次推
   黑马位
   B 备选

五、合规提示
   高风险条目清单 + 所需动作（换壳/化名/备案）

六、下一步建议
   推荐先启动的 1~3 条 + 理由
```
