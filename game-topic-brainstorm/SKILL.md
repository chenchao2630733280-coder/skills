# Game Topic Brainstorm — 游戏选题脑暴

本 skill 是 AI 游戏生成流水线的**阶段 0**(在 game-blueprint 之前),职责是帮用户从0到1结构化脑暴选题,输出可执行的选题方案供 game-blueprint 消费。

**与 game-blueprint 的关系**:本 skill 产出"选什么题",game-blueprint 产出"怎么做"。本 skill **不生成蓝图**,只做选题验证。

**设计原则复用**:本 skill 不重复定义设计原则,直接引用 `../game-blueprint/references/` 下的原则文件做选题验证。

---

## 一、何时调用

满足以下任一条件即调用:
- 用户说"想做游戏但不知道做什么/脑暴选题/找点子/选题方向"
- 用户有模糊想法(如"做个小游戏")但未明确核心玩法
- game-forge-master 调度到选题阶段

**不要**在以下场景调用:
- 用户已有明确玩法需求(直接走 game-blueprint)
- 用户要修改已有游戏(直接 Edit/Write)
- 纯咨询"游戏怎么做"(用对话回答)

---

## 二、输入与输出

**输入**:
- 用户的初始想法(可模糊,如"做个休闲小游戏")
- 可选:用户的约束(平台/题材偏好/工程量预算/变现目标)
- 可选:用户提供的参考游戏名

**输出**(固定路径,1 份文档):
- `docs/TOPIC_PROPOSAL.md` — 选题方案(Top 3-5 候选 + 1 个推荐)

---

## 三、脑暴流程(6步)

### Step 1:需求澄清

用 AskUserQuestion 确认 2-3 个关键约束(不要一次问太多):

| 维度 | 选项 |
|---|---|
| 工程量预算 | 超休闲(1-2周)/ 混合休闲(3-6周)/ 中重度(6周+) |
| 变现目标 | IAA为主 / IAA+IAP混合 / 暂不考虑 |
| 题材偏好 | 现代休闲 / 国风 / 怪谈 / 萌系 / 无偏好 |
| 平台 | 微信小游戏 / 抖音小游戏 / H5 / 多端 |

用户未提供约束时,按默认假设:**超休闲 + IAA为主 + 无题材偏好 + 微信小游戏**。

### Step 2:品类定位

读取 `../game-blueprint/references/design-principles-overview.md` §二 品类决策树,根据用户的工程量预算初判品类:

| 工程量 | 倾向品类 | 原因 |
|---|---|---|
| 超休闲(1-2周) | 即时反馈类-超休闲模式 | 短反馈+裂变,工程量小 |
| 混合休闲(3-6周) | 即时反馈类-混合休闲模式 / 价值揭示类 | 有 meta 深度,工程量中 |
| 中重度(6周+) | 价值揭示类 / 思考顿悟类 / 复合 | 系统复杂,工程量大 |

品类定位是**初判**,Step 4 验证时可能调整。

### Step 3:赛道扫描

用 WebSearch 搜索当前市场机会,关键词模板:
- "{年份} 微信抖音小游戏 蓝海赛道 爆款品类"
- "{年份} 混合休闲 出海 机会品类"
- "{年份} 超休闲 新爆款 玩法趋势"

扫描结果整理为赛道表:

| 赛道 | 状态(蓝海/红海/上升期) | 机会点 | 风险 | 适配品类 |
|---|---|---|---|---|
| ... | ... | ... | ... | ... |

### Step 4:脑暴发散(5种方法)

基于赛道表 + 品类定位,用以下5种方法生成候选点子(每种方法至少产出1个候选):

#### 方法A:赛道×品类矩阵法
横轴赛道 × 纵轴品类,交叉点找机会。
```
         即时反馈  价值揭示  思考顿悟
排序      ✓红海    ✓开箱排序  ?
物理      ✓蓝海    ?         ✓物理解谜
放置      ✓稳定    ✓寻宝     ?
```
交叉点"✓"代表有机会,"?"代表可探索,"✗"代表不匹配。

#### 方法B:玩法变体法
在验证过的玩法上做"加减乘除":
- **减**:三消-交换=点击消除(2048)
- **加**:排序+计时=紧张感排序
- **乘**:跑酷×肉鸽=每局随机技能
- **除**:MOBA除以5人=单人英雄闯关

#### 方法C:题材换皮法
成熟玩法 + 新题材:
- 消除 + 怪谈 = 阴阳师消除
- 跑酷 + 国风 = 水墨跑酷
- 开箱 + 考古 = 文物鉴定

#### 方法D:机制叠加法
核心玩法 + 一个新机制(只加一个,不贪多):
- 排序 + 物理碰撞 = 物理排序
- 割草 + 价值揭示 = 打怪掉宝开箱
- 放置 + 解谜 = 放置推导

#### 方法E:反向设计法
从目标体验倒推玩法:
- 目标"解压" → 切割/破坏/挤压 → 物理沙盒
- 目标"赌徒心理" → 开窗揭示 → 赌石/开箱
- 目标"创造成就" → 造物定制 → 经营+合成

**产出**:5种方法各至少1个候选,合计 5-10 个候选点子。

### Step 5:原则验证

对每个候选,按品类读取对应原则文件,用原则的检查项验证:

| 品类 | 读取原则文件 | 验证用原则 |
|---|---|---|
| 即时反馈类 | `../game-blueprint/references/design-principles-instant-feedback.md` | 超休闲六原则 / 混合休闲五原则 |
| 价值揭示类 | `../game-blueprint/references/design-principles-value-reveal.md` | 价值揭示四原则 |
| 思考顿悟类 | `../game-blueprint/references/design-principles-puzzle.md` | 解谜六原则 |

每个候选填写验证表:

| 候选 | 原则1 | 原则2 | ... | 命中数 | 结论 |
|---|---|---|---|---|---|
| 候选A | ✓ | ✓ | ... | 6/6 | 通过 |
| 候选B | ✓ | ✗ | ... | 4/6 | 需补机制 |
| 候选C | ✗ | ✗ | ... | 2/6 | 淘汰 |

**筛选标准**:
- 原则命中 ≥80% → 通过,进入 Step 6
- 命中 60-80% → 标注"需补机制",可选进入 Step 6
- 命中 <60% → 淘汰

### Step 6:差异化锚点

对通过验证的候选,各找**一个**差异化锚点(不贪多):

| 差异化类型 | 说明 | 示例 |
|---|---|---|
| 题材换皮 | 成熟玩法+新题材 | 消除+怪谈 |
| 规则变体 | 核心规则微创新 | 三消→物理碰撞合成 |
| 反馈升级 | 强化正反馈密度 | 满屏特效+连击爆炸 |
| 机制叠加 | +一个新机制 | 排序+隐藏对象 |
| 社交绑定 | 强化裂变 | 省份排行榜+好友挑战 |

**关键**:一个清晰的"人无我有"比五个模糊创新更有效。差异化锚点需可在一句话内说清。

## 四、输出文档结构

`docs/TOPIC_PROPOSAL.md` 严格按以下结构产出:

```markdown
# 游戏选题方案

> 生成时间:{日期}
> 约束:{工程量/变现/题材/平台}

## 1. 候选方案清单(Top {N})

### 候选1:{一句话定义}
- **品类**:{即时反馈-超休闲 / 价值揭示 / ...}
- **核心玩法**:{30字以内}
- **差异化锚点**:{一句话}
- **原则验证**:{命中数/总数}
- **工程量**:{★~★★★★★}
- **市场机会**:{蓝海/上升期/红海}

### 候选2:...
### 候选3:...

## 2. 推荐方案

**推荐候选{N}:{一句话定义}**

### 推荐理由
1. {原则验证最完整}
2. {市场机会最佳}
3. {工程量与约束匹配}
4. {差异化锚点清晰}

### 核心玩法循环(草案)
{3-5句描述玩家从开始到结束的完整循环}

### 核心机制清单(草案)
| 机制 | 说明 | 对应原则 |
|---|---|---|
| ... | ... | 原则X |

### 风险与应对
| 风险 | 应对 |
|---|---|
| ... | ... |

## 3. 下一步建议
- 确认推荐方案后,调用 game-blueprint 生成详细蓝图
- 如需调整候选,标注修改方向后重新脑暴
```

## 五、交互约定

1. **Step 1 用 AskUserQuestion 询问约束**,不要自行假设所有约束
2. Step 2-6 自主执行,不频繁打断用户
3. 产出 TOPIC_PROPOSAL.md 后向用户简报:
   - "共脑暴 {N} 个候选,通过验证 {M} 个,推荐:{推荐方案一句话定义}"
   - "路径 docs/TOPIC_PROPOSAL.md,下一步可调用 game-blueprint 生成蓝图"
4. **不要**自行调用 game-blueprint,让用户确认推荐方案后再决定
5. 用户对推荐方案不满意时,根据反馈调整候选重新脑暴(不重复整个流程,只调整 Step 4-6)

---

## 六、质量检查清单

产出前自检:

- [ ] Step 1 约束已确认(或按默认假设并标注)
- [ ] Step 3 赛道表含 ≥5 个赛道
- [ ] Step 4 至少 5 个候选(5种方法各至少1个)
- [ ] Step 5 每个候选都有原则验证表
- [ ] Step 6 通过验证的候选都有差异化锚点
- [ ] 推荐方案的原则命中 ≥80%
- [ ] 推荐方案有清晰的一句话差异化锚点
- [ ] 推荐方案的核心玩法循环可被 AI 实现(非依赖复杂物理/网络/后端)
- [ ] 文档无 TODO/占位文字
- [ ] 候选清单含 Top 3-5 个(不少于3,不多于5)

## 七、与其他 skill 的关系

```
[本 skill] 选题脑暴
    ↓ 产出
docs/TOPIC_PROPOSAL.md
    ↓ 供消费
game-blueprint 生成蓝图(读取推荐方案)
    ↓ 产出
docs/GAME_BLUEPRINT.md
    ↓ 继续
game-spec → game-art-spec → ...
```

**关键约束**:
- 本 skill 不生成蓝图(职责边界)
- 本 skill 不重复定义设计原则(引用 game-blueprint)
- 本 skill 的产出是 game-blueprint 的输入(契约化交接)
- 用户确认推荐方案后,game-blueprint 读取 TOPIC_PROPOSAL.md 的"推荐方案"章节作为输入
