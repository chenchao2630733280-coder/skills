# 跨文件精确批量改写手术 (batch-rewrite-surgery)

## 一、定位与职责

本 skill 专职**跨文件、多处的精确文本改写**：把旧口径/旧标识/旧语义在 N 个文件里统一替换为新口径，并**证明没有一处漏改、没有一处误伤**。

**适用**：批量改名、术语统一、删除某条语义链路、回退上一次改名、把 X 全部改成 Y。
**不适用**：改代码结构（走 `refactor`）、改功能行为（走对应功能流程）、单文件少量改动（直接编辑）。

**核心原则：一次改对。**
跨文件批量改写最大的风险不是「改不动」，而是「**改错了却看不出来**」：

| 失效模式 | 表现 |
|---|---|
| **漏改** | 部分文件没改到（活文件集划错 / 白名单漏项） |
| **误伤** | 不该改的同名词被改（同词不同义） |
| **半截码** | 只改了可见文案，函数名/元素 id/键名没改 |
| **静默失效** | 下游校验器/扫描器仍认旧词 ⇒ 检查空转、永不报警（**最危险**） |
| **静默回退** | 整文件被行尾/编码归一化改写，表面字节数变化被误判为正常 |
| **半途中断** | 脚本跑到一半崩了，前半已落盘、后半失配 |

职责边界：
- ✅ 负责：侦查盘面、界定范围、生成落盘脚本、dry 验证、逐字节反向校验、收口核对。
- ❌ 不负责：决定口径该怎么改（**新旧口径必须由用户给定**）、重构、功能变更。

## 二、五道防线（缺一不可）

| # | 防线 | 防的是什么 | 关键动作 |
|---|------|-----------|---------|
| D1 | **侦查与范围界定** | 漏改 / 改错范围 | 全仓 grep 旧口径并计数；逐处判「同词不同义」；显式定义**活文件集** |
| D2 | **落盘脚本化** | 不可复现、不可回滚、手滑 | 生成 `apply_*.py`（带 `--dry`），同文件全部替换在**一次** `load`/`save` 内完成 |
| D3 | **失配与护栏** | 半途中断 / 大块删除被误拦 | 失配**批量收集**（不首处即崩）；缩减护栏**按文件**放宽；EOL/编码归一化 |
| D4 | **反向 diff 校验** | 静默误伤（整文件被归一化改写） | 「改前快照 + 预期变换 == 当前磁盘」**逐字节**相同 |
| D5 | **收口 grep 闭环** | 漏改、半截码、连带误伤 | 旧口径 = 0；新口径到位；**未涉及项仍在位** |

### D1 侦查与范围界定

1. **全仓 grep 旧口径**，按文件统计命中次数（不是只看「有/没有」）。
2. **逐处判语义**：同一个词可能有多重含义，必须逐处决定改不改。典型三类：
   - **要改**：该语义的目标载体（状态码对应的显示标签、函数名、元素 id、键名）。
   - **不改**：业务动作短语、搭建/流程节点名、与本次无关的同形词。
   - **要看语境改**：既是标签又是动作的描述句 —— 拆开分别处理。
3. **显式定义活文件集**（这条最容易出事）：

   | 归类 | 处置 |
   |---|---|
   | 当前交付物（站点 / 文档 / spec / 门户） | ✅ 改 |
   | 活动的校验脚本 / 扫描器 / 门禁 | ✅ 改（**漏了它们 = 校验静默失效**） |
   | 归档目录（如 `docs/archive/`） | ❌ 一律不改 |
   | 历史落盘脚本（历次 `bNN_*.py`） | ❌ 不改（是运行记录，含旧词属正常） |

### D2 落盘脚本化：dry-run 三纪律

1. **dry 不写盘** ⇒ 同一文件的所有替换**必须在一次 `load`/`save` 内**（二次 `load()` 会丢掉前一趟的内存改动）。
2. **dry 下不跑「落盘后应满足」的断言** ⇒ 用 `if not DRY:` 门控。
3. **终检一律读内存文本**，不读磁盘 —— 否则 dry 模式永远失败。
4. **真跑中断后不要直接重跑**：前半段已落盘，旧串已不存在 ⇒ 会大面积失配。先判定已落盘范围再续。

### D3 失配批量收集与护栏

- **失配批量收集**：不要 `assert count == 1` 首处就崩。把失配收集进 `MISS` 列表，循环结束后统一打印 + `SystemExit('存在原文失配，未落盘')`。**一次拿到全部失配**，不必跑 N 轮 dry。
- **缩减护栏**：整块删除会触发 `save()` 的缩减比例护栏 ⇒ 按文件放宽（如 `MIN_RATIO = {...}`）。**但先确认不是 EOL 归一化误报**（见下）。
- **EOL 归一化陷阱**：`load()` 归一到 `\n` 后 `n0` 是 LF 长度、`nb` 是**还原后的**行尾长度 ⇒ CRLF 文件看起来「涨了 N 字节」，恰等于行数，**不是内容膨胀**，别据此调护栏。
- **判行尾不能靠计数比较**：纯 CRLF 时 `\r\n` 计数与 `\n` 计数**恒相等** ⇒ 用 `crlf > 0 and crlf >= lf * 0.9`。
- **字节级替换天然保行尾**；逐行重写才需要显式还原行尾。
- **不信工具链回显**：部分本机工具链会在 I/O 两侧改写内容（实测连**词**都会被改）⇒ 核对一律用 `repr()` / `ord()`，**以脚本内打印为准**。

### D4 反向 diff 逐字节校验（黄金判据）

改完后：**拿改前快照，对每个文件施加同一组预期替换，结果必须与当前磁盘逐字节相同。**

这是**唯一**能证明「没有文件被行尾/编码归一化悄悄改写整份」的手段 —— 普通的
「旧词计数为 0」既证明不了误伤，也证明不了没被整文件重写。

- **派生件例外**：含内容 hash 的派生件（如构建报告）**不能用文本变换比对**，必须单列判据：
  ① hash 变化集合**恰等于**预期集合；② 全量 hash 与磁盘实算一致。

### D5 收口 grep 闭环

四查，缺一不可：

1. 旧口径全仓 = **0**
2. 新口径在各目标位置**到位**（按位置计数，不是只看存在）
3. **未涉及项仍在位**（尤其是「部分回退」场景：用户只回退 A 项时，必须显式断言 B 项的新改动没被连带清掉）
4. 活动校验脚本/门禁的旧口径断言已同步（否则其检查空转）

## 三、标准流程

```
0 需求确认：用户给定「旧口径 → 新口径」（或「要删的语义」）
1 侦查：全仓 grep + 逐处判语义 + 定活文件集          → 输出「盘面清单」
2 生成脚本：apply_*.py（DRY + load/save + sub1 收集 + MIN_RATIO） → references/rewrite-script-template.py
3 dry 连跑：读内存文本核对，逐条确认命中数
4 落盘：先刷改前快照（见 snapshot-guard），再执行
5 校验：verify-*.py 做反向 diff（D4）
6 收口：四查（D5）
7 门禁：跑目标项目既有校验脚本，全绿
8 复述：给出「文件 / 处数 / 语义判定理由」变更清单
```

## 四、语义类改写的附加约束（状态 / 标签 / 链路）

当改写对象是**状态名、显示标签、或整条流转链路**时，除五道防线外还需：

1. **先判拓扑是否也变**：把用户口述的链条与现有实现**逐态比对**。
   若结论是「拓扑一致、只差显示标签」⇒ 改动面从「改状态机」收敛为「纯文本替换」，风险直降。
2. **改名 ≠ 改状态**：改一个显示标签，不等于改状态机拓扑。**先判定，再动手**。
3. **标签→码 的映射表必须同步扩容**：若下游扫描器/校验器靠一张「标签 → 状态码」的缩表认状态，改标签却不同步该表 ⇒ **一致性检查静默跳过**（永远绿，永远没查）。
4. **映射处要清点全**：同一份标签表可能在多处副本（含跨端共享块）里各存一份，逐处同改 + 加等价断言。
5. **改「语义」而非只改「文案」**：中文标签 + 表单字段 + 函数名 + 元素 id + 键名 + 二次确认文案 + 成功提示 + 文档流程说明 —— 成套改，别留半截旧码。
6. **语义放宽必须补回被放宽的校验**：把「只改姓名」放宽为「可改手机号」⇒ 必须补格式校验 + 唯一性校验 + **排除自身**。
7. **表单里的展示值 ≠ 表单值**：列表展示掩码/格式化值，编辑框必须回填原始值。

## 五、产出契约

| 产出 | 说明 |
|---|---|
| `rewrite-plan.md` | 盘面清单：活文件集、命中分布、逐处语义判定表（文件 / 原串 / 改否 / 理由） |
| `apply_<topic>.py` | 落盘脚本（带 `--dry`，失配批量收集，按文件护栏） |
| `verify_<topic>_diff.py` | 反向 diff 校验脚本（D4），退出码 0/1 |
| `rewrite-report.md` | 变更清单（文件 / 处数）+ 四查结果 + 门禁结果 + 残留风险 |

## 六、质量检查清单

- [ ] 新旧口径由用户明确给定，未被自行推断。
- [ ] 活文件集已显式声明，归档目录与历史脚本已排除。
- [ ] 每一处命中都做过「同词不同义」语义判定并记录理由。
- [ ] 落盘脚本带 `--dry`，且同文件全部替换在一次 `load`/`save` 内。
- [ ] 失配为**批量收集后统一报出**，不是首处即崩。
- [ ] 缩减护栏的放宽有依据（且已排除 EOL 归一化误报）。
- [ ] **反向 diff 逐字节校验通过**（派生件走 hash 判据）。
- [ ] 四查全过：旧口径 0 / 新口径到位 / 未涉及项仍在位 / 校验脚本断言已同步。
- [ ] 目标项目既有门禁全绿。
- [ ] 变更清单已复述（文件 + 处数 + 语义理由）。
