# 跨文件批量改写 · 陷阱速查（12 类）

> 每类都给了「症状 → 根因 → 判据/修法」。全部为实测所得，非理论推演。

## 一、编辑与脚本类

### 1. `--dry` 陷阱（最高频）
- **症状**：dry 跑得好好的，真跑后结果不对；或同一文件第二趟替换全失配。
- **根因**：dry 不写盘 ⇒ 若在同一文件上做**两次** `load()`，第二次读到的是磁盘旧内容，前一趟的内存改动被丢弃。
- **修法**：同文件的所有替换**必须在一次 `load`/`save` 内**完成。
- **附带纪律**：dry 下**不得跑**「落盘后应满足」的断言（用 `if not DRY:` 门控）；终检一律读**内存文本**。

### 2. 真跑中断后直接重跑
- **症状**：脚本崩在半途，重跑后大面积「原文失配」。
- **根因**：前半段已落盘，旧串已不存在。
- **修法**：先判定已落盘范围（看命中日志 / 对比快照），再决定续跑或从快照回滚。

### 3. 首处失配即崩
- **症状**：跑 5 轮 dry 才把失配改完。
- **修法**：`assert count == 1` 改为**收集到 `MISS`**，循环后统一打印 + `SystemExit`。**一次拿到全部失配**。

### 4. 缩减护栏误拦
- **症状**：整块删除时 `save()` 报「缩减异常」。
- **修法**：按文件放宽允许比（`MIN_RATIO = {...}`）。**但先确认不是第 5 类（EOL 误报）**。

### 5. EOL 归一化假膨胀
- **症状**：CRLF 文件改完「涨了 N 字节」，看起来像内容被追加。
- **根因**：`load()` 归一到 `\n` 后记录的 `n0` 是 **LF 长度**，而 `nb` 是**还原行尾后**的长度 ⇒ 差 ≈ 行数。
- **修法**：**识别为归一化所致，不要据此调护栏**；并用第 12 类（反向 diff）证明文件没被整份改写。

### 6. 行尾判定写错
- **症状**：`\n` 锚点全部命中 0。
- **根因**：纯 CRLF 文件里 `\r\n` 计数与 `\n` 计数**恒相等** ⇒ `count(b'\r\n') > count(b'\n')` 判据永远为假。
- **修法**：用 `crlf > 0 and crlf >= lf * 0.9`。**字节级替换天然保行尾**，逐行重写才需还原。

### 7. 工具链回显改写
- **症状**：脚本打印/回显的内容与你写的不一样，导致核对误判。
- **根因**：部分本机工具链在 I/O 两侧改写内容，实测**连词都会被改**。
- **修法**：核对一律 `repr()` / `ord()`，**以脚本内打印为准，不信回显**。

### 8. 块尾锚点越界
- **症状**：删了 A 块，B 块里残留旧代码，脚本却不报错。
- **根因**：`block(text, start, end, …)` 的 `end` 落在目标块之外时，会命中**较近的同形收尾**。
- **修法**：删行号区间必须**降序**，且每段删除前先 `assert` 该段首尾特征。

## 二、范围与语义类

### 9. 同词不同义（误伤主源）
- **症状**：改完后业务文案变得不通顺，或流程节点名被换成标签名。
- **修法**：逐处判语义并记录理由。固定三类：**要改**（目标载体）/ **不改**（动作短语、节点名、无关同形词）/ **按语境拆开处理**。

### 10. 活文件集划错 ⇒ 校验静默失效（最危险）
- **症状**：所有门禁全绿，但门禁其实还在认旧词、根本没在查。
- **根因**：只改了交付物，没改**活动校验脚本/扫描器**里的旧口径。
- **修法**：把活动校验脚本纳入活文件集显式同改；并让每个校验器打印**「已比对 N 项」**，`N=0` 或明显偏小即刻排查。
- **另一类**：下游靠「标签 → 码」缩表认状态 ⇒ **改标签必须同步扩容该表**，否则一致性检查静默跳过。

### 11. 半截码
- **症状**：界面文案改了，但函数名/元素 id/键名还是旧词；残留代码被后人误用。
- **修法**：语义成套改 —— 中文标签 + 字段名 + 函数名 + 元素 id + 键名 + 弹窗标题 + 二次确认文案 + 成功提示 + 文档说明，一次到位。

## 三、验证类

### 12. 缺少反向 diff ⇒ 静默误伤
- **症状**：旧词计数为 0，看起来改干净了，但某个文件被整份重写（行尾/编码/空白归一化）。
- **修法**：**反向 diff 逐字节校验** = 拿改前快照 + 同一组预期替换 ⇒ 结果须与当前磁盘**逐字节相同**。
- **派生件例外**：含内容 hash 的派生件不能用文本变换比对（hash 必须重算）⇒ 单列判据：① hash 变化集合**恰等于**预期集合 ② 全量 hash 与磁盘实算一致。

## 附：部分回退的单列断言

用户只要求回退 A 项时，**必须显式断言 B 项的新改动仍在位** —— 全局替换型回退极容易把不该动的另一条改名一起清掉。

```python
MUST_KEEP = [
    ('site/pc/sidebar.js', '新标签B', 3),   # 期望仍出现 3 次
    ('site/mobile/bar.js',  '新标签B', 1),
]
```
