# 移除元素后不要重建数组,要就地压实

## 现象

列表里删掉若干元素后需要重排。两种写法看着等价：

```ts
// ❌ 重建:filter 返回新数组
arr = arr.filter(a => a.alive);

// ✅ 就地压实:保序、保身份
let w = 0;
for (let i = 0; i < arr.length; i++) {
  if (!arr[i].alive) continue;
  if (w !== i) arr[w] = arr[i];
  w++;
}
arr.length = w;
```

## 为什么 filter 危险

`filter` 不是"删掉元素"，是**造一个新数组**。旧下标与新下标不再对应，于是：

| 后果 | 表现 |
|---|---|
| 身份漂移 | 原来 index 5 的元素变成 index 3，任何持有旧下标的系统失效 |
| 动画错位 | tween / 插值 / 粒子发射点绑在旧对象上，视觉跳一下 |
| 断言漂移 | 基于下标的断言两次运行结果不同，「偶发」红 |
| 引用断裂 | 外部模块持有旧数组引用时，读到的还是删之前的内容 |

## 判据

**如果这个数组的下标被任何外部系统引用过**（动画目标、存档、事件参数、测试断言、渲染排序），禁止重建。只有当数组是「每帧新生、没有任何人持有下标」的临时快照时，`filter` 才安全。

## 正确写法

就地压实 + 截断长度（上面 ✅ 那段）。要点三条：

1. 写指针 `w` 只在命中时前进，读指针 `i` 一直前进；
2. 不要一边遍历一边 `splice`（`splice` 会把后续元素整体前移，O(n²) 且容易跳元素）；
3. 压实后**显式截断** `arr.length = w`，否则尾部残留旧引用（内存泄漏 + 幽灵元素）。

## 验法

- 断言**不变式**：压实前后，存活元素的相对顺序不变（不是"数量对"，是"顺序对"）。
- 断言**身份稳定**：对同一批元素连续做两次移除，元素的下标映射与预期一致。
- 若元素带稳定 id，断言 `ids` 序列在压实后是原序列的子序列。
