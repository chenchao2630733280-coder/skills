# 内容难度定级门 (content-difficulty-gate)

## 一、定位与职责

把"这关太难了/太简单了"这种手感，变成三件可执行的东西：**一个分数、一个判定口径、一张实测旋钮表**。

**适用**：关卡包由易到难排序、题库难度分层、课程章节节奏、内容序列的"断崖"排查、改配方后判断难度是升了还是降了。
**不适用**：单个内容内部的数值平衡（走对应数值设计）、纯美术复杂度评估（走 `procedural-art-forge`）、规格一致性检查（走 `game-quality-gate`）。

**核心原则：先立口径，再谈难度。**
没有口径的难度讨论必然退化成"我觉得"，最后改成"谁嗓门大听谁的"。本 skill 的价值不是替你调参，而是让每次调参都有**可复现的判据**。

---

## 二、三条判据（动手前必须写下）

1. **判定口径 = 「无脑策略必输」+「拟真策略必赢」**，两个条件缺一不可：
   - 无脑都能赢 ⇒ 该单元**没有决策**，再好看也是走过场。
   - 拟真也输 ⇒ 可能是死局，**也可能是你的拟真策略太笨**。先证伪策略，再改内容。
2. **第三个策略（贪心 / 严格 / 最优）只作参考**。它输**不能**证明内容无解 —— 它通常输在"打法失误"，不是内容问题。
3. **分数只用于排序与发现结构问题，不能跨版本直比**（归一化基准会变，见 `references/pressure-score.md` §4）。

---

## 三、五步流程

### 3.1 定义操作原语与死局条件

先回答三个问题，答不出就别往下走：

- 玩家每回合能做的**一个原子动作**是什么？（点一次 / 提交一次 / 选择一次）
- **推进**的判据是什么？（消耗了多少、完成了多少）
- 什么情况下"还能动但永远走不完"？这就是死局的定义，后面所有验证都围绕它。

### 3.2 建三个求解器（同一份数据、同一套规则）

| 策略 | 模拟谁 | 行为 | 期望 |
|---|---|---|---|
| `naive` | 看到就点的人 | 永远点"列表第一个可点项" | **必输** |
| `human` | 会看但会算的人 | 只点"有供给"的，同类不重复占并发位，没有就等 | **必赢** |
| `greedy` | 手快不做计划的人 | 按"此刻能不能推进"排序，同类照叠 | 只作参考 |

实现要点：

- 求解器与产品**共用同一份内容数据与同一套规则**，否则验证的是另一个东西。
- 每局输出一行机器可读结果（`win / clicks / ratio / idlePicks / 死局现场`），便于批量 sweep。
- **死局时必须打印现场快照**：并发位里是什么、底/前沿是什么、还剩多少供给。这张快照才是诊断材料，胜率只是结论。
- 伪代码与死局分类见 `references/solver-strategies.md`。

### 3.3 建静态诊断（不启动运行时就能出分）

三个分量（完整定义见 `references/pressure-score.md`）：

| 分量 | 衡量 | 用途 |
|---|---|---|
| **深度 D** | 一个单元要看穿几层顺序 | **只作诊断列，不参与打分**（对"少量操作、高复杂度"的内容严重高估） |
| **容量 C** | 待处理单元数 ÷ 并发上限 | 排序主力 |
| **陷阱 T** | 开局"能碰但推不动"的占比 ÷ 并发上限 | 唯一与无脑死亡率直接相关的量 |

**压力分 = C × (1 + T)**，按全量最大值归一化。

### 3.4 实测旋钮表（不要信直觉）

| 直觉 | 实测常见真相 |
|---|---|
| "把单个上限调小就会变长" | 常常**无效**，长度被另一个下限卡住 |
| "下限不能动" | 动一点点收益很小 |
| "限制单类数量只是防独占" | 往往**这才是真正的旋钮** |

模板与通用结论见 `references/knob-calibration.md`。调参顺序：**并发位 → 单类拆分上限 → 内容尺寸（最贵）**。

### 3.5 排序与编号

- **配置与编号必须分离**：内容配方（画/题/章节）一张表 × 编号顺序（有序列表）另一张表。合成时按顺序表编号。
- 编号**按实测压力排，不按制作顺序排**。
- 每次配方变动都要重排一次，并重跑 bot 矩阵 —— 配方改了而编号没改，就是给玩家一个难度断崖。

## 四、反模式（每条都付过代价）

| 反模式 | 后果 |
|---|---|
| 用"复杂度"当难度（画面更花、篇幅更长、参数量更多） | 玩家体感"怎么突然变简单了"；诊断数据可能证明操作压力只有原来的三分之一 |
| 把贪心策略的失败当成"无解" | 把好内容改坏，越改越水 |
| 用一条"看起来合理"的强约束框死产出 | 表达力被白锁。例：某美术约束声称"同类元素顺序成环必然不可解"，造三个极端反例实测全部通关 —— 真正的原因是引擎有 bug |
| 按制作顺序编号 | 难度曲线断崖 |
| 分数跨版本直比 | 归一化基准变了，绝对值失真（"从 82 掉到 61"可能只是分母变了） |

**造反例实验**：任何"这条约束必然导致不可解"的论断，先造 2–3 个强违规反例跑一遍。反例能过 ⇒ 约束是假的，删掉它，表达力白赚。反例用完记得清理，别让它们混进正式内容集。

## 五、交付物

| 产物 | 内容 |
|---|---|
| `docs/DIFFICULTY_DESIGN.md` | 分量定义 / 全量实测表 / 真问题（结构诊断）/ 使用口径 / 反模式 |
| `scripts/_difficulty_score.*` | 静态诊断：读内容 JSON 直接出分、出排序建议、打印"明显回落"告警 |
| `scripts/_bot_play.*` | 三策略求解器，输出 RESULT 行供 sweep |
| 判定矩阵 | 每次改配方后记录 `naive / greedy / human` × 全内容 |
| 旋钮实测表 | 每个旋钮"直觉 vs 实测"，注明哪些是无效旋钮 |

骨架脚本：`scripts/score_template.py`（把分量提取器换成你的内容即可）。

## 六、与其他 skill 的边界

| skill | 分工 |
|---|---|
| `game-quality-gate` | 管规格一致性（字段/契约/实跑预检）；本 skill 管难度与可解性，两者不重叠 |
| `procedural-art-forge` | "能通关"≠"看得懂"，机制全绿不代表美术可辨识，两道门都要过 |
| `failure-casebook` | 新发现的死局形态/无效旋钮归档到失败案例库 |
| `delivery-consistency-gate` | 判定矩阵、难度表这类多副本事实，用一致性门禁守 |

## 七、质量检查清单

- [ ] 判定口径写明「无脑必输 + 拟真必赢」，且两个策略都实跑过（不是推断）
- [ ] 拟真策略输时，先证伪策略（加一步"同类不重复占位"再跑），而不是直接改内容
- [ ] 三分量定义与归一化口径写清，并注明"绝对值不可跨版本直比"
- [ ] 至少实测两个旋钮，并显式记录"哪些旋钮无效"
- [ ] 编号顺序由分数生成，配方与编号在结构上分离
- [ ] 全量矩阵含 `naive / greedy / human` 三列，`greedy` 结果标注"仅参考"
- [ ] 反例实验结论写进文档：哪条约束被证伪、依据是什么
- [ ] 死局快照（并发位/前沿/剩余供给）被保存，能复现同一死法
