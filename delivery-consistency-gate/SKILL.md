# 交付物一致性门禁 (delivery-consistency-gate)

## 一、定位与职责

本 skill 解决一类结构性问题：**同一个事实被存在很多地方**（页面清单存于 spec JSON、HTML 文件名、说明文档表格、门户菜单镜像；状态标签存于多端共享脚本；金额同时出现在总表与子表……）。人工核对必然漂移，且**漂移了也不会报错**，只会在某天突然炸出来。

本 skill 把这套核对**机械化、可复跑、有覆盖面对照**，输出一部「每次交付前跑一遍」的门禁。

**适用**：交付物含「同一事实多副本」的项目 —— 多端原型/多端 App、spec + 文档 + 站点、i18n 多语言包、设计 token + 组件库、SDK 多语言实现。
**不适用**：单文件脚本、无多副本结构的小项目。

**核心原则：门禁必须有牙齿。** 一个永远返回「全绿」的门禁比没有门禁更危险 —— 它会让人以为查过了。

职责边界：
- ✅ 负责：识别「同一事实的多个副本」、为每类副本定义机械判据、生成并运行门禁、输出全绿清单与缺口清单。
- ❌ 不负责：修缺陷（只报不修）；改业务口径。

## 二、先做一件事：列出「同一事实副本表」

动手写门禁前，先做这张表。**没有这张表，门禁一定漏项**。

| 事实 | 副本 1 | 副本 2 | 副本 3 | 副本 4 | 权威源 |
|---|---|---|---|---|---|
| 页面清单 | `spec/pages.json` | HTML 文件名 | 说明文档总览表 | 门户菜单镜像 | `pages.json` |
| 标注清单 | `spec/annotations.json` | 门户镜像 | `spec/annotations.json` | — | — |
| 状态标签 | PC 共享脚本 | 移动端共享脚本 | 说明文档标签表 | 校验脚本的标签→码缩表 | 共享脚本 |
| 汇总金额 | 总表字面量 | 子表求和 | 页面渲染 | — | **派生**（不留字面量） |
| 内容指纹 | 页面文件 | 构建报告 `contentHash` | — | — | 文件 |
| 导航结构 | 侧栏分类定义 | 各页面面包屑 | 说明文档菜单树 | — | 侧栏定义 |
| 编号空间 | 编号登记表 | 各处引用（标注/文档/工件） | — | — | 登记表 |
| 渲染产物 | 页面 JS 逻辑 | 渲染出的 DOM/文本 | — | — | **代码**（产物须由代码派生） |

**两条通用结论**（几乎必然成立）：
1. **某一份副本是权威源，其余应当派生**。凡是能算出来的，就不该留第二份字面量。
2. **镜像型副本要逐字**（不是「语义一致」）—— 例如门户菜单 = 标注清单的镜像，文本改动必须两处逐字同改。

## 三、门禁族：基础 A~H + 进阶 I~K

### 基础八类（A~H）

| 门禁 | 查什么 | 判据 |
|---|---|---|
| **A 四方一致** | 页面/标注 ID 与属性在 4 份副本间完全一致 | 逐份取集合，做双向差集，两个差集都必须为空 |
| **B 单源副本逐字节相同** | 两处本该逐字节相同的共享块是否真的一致 | 二进制相等断言；不一致则直接失败并打印首个差异字节位 |
| **C 投影契约** | 同一实体在 ≥2 端出现时，其字段必须一致 | 按实体 ID 建索引，对每个字段做值比较（**按值，勿序列化整对象比较**） |
| **D 派生不变量** | 派生关系是否成立 | 子表金额 == 主子单金额；金额 == 逐条求和；某类凭证只允许挂特定状态；进入某环节的实体必有多条子记录（**反向覆盖**：不能只查「有子记录的父存在」，还要查「该有子记录的父都有」） |
| **E 陈旧术语三层扫描** | 是否有不该出现的旧口径 | **HARD** 硬禁词（出现即失败）· **QUOTE** 迁移说明引用（只允许出现在指定位置）· **CANON** 现行权威标签（出现在别处视为陈旧） |
| **F 负向自检** | 门禁自身有没有牙齿 | 造一条**已知错误**，确认门禁**报出**；再确认其余检查未被误伤 |
| **G 覆盖面对照** | 有没有「静默空转」 | 每条契约打印**「已比对 N 项」**；结尾打印「哪些文件有字面量可比对 / 哪些是全派生无从比对」 |
| **H 构建报告** | 规模与指纹 | 页数 / 标注数 / 总行数 / 每页内容 hash（行尾归一化后取摘要） |

### 关于 B：为什么必须「逐字节」
「语义一致」不是判据。真正会出的事故是**整份文件被外部工具重排/归一化**（行尾、空白、表格列宽），
语义没变但文件被换过 —— 下一次的 diff 校验会因此误判。逐字节相等是唯一无歧义的判据。

### 关于 E：三层扫描的动机
统一术语之后，旧词会残留在三类位置，处置完全不同：

- **硬禁词**：绝不该再出现（如已被废弃的能力名）⇒ 出现即失败。
- **迁移说明引用**：文档里「原 X 正名为 Y」这类说明必须保留旧词，否则该说明失去意义 ⇒ 只允许出现在文档的指定章节。
  > ⚠️ 注意：**正则里刻意保留的特殊符号不要顺手统一掉** —— 换掉它会让上下文窗口判据恒真，导致 QUOTE 检查静默空转。
- **现行权威标签**：某些词是合法的（如「待局办确认」），但**出现在非授权文件里就是陈旧**⇒ 需要一张「合法位置清单」。

### 关于 F：门禁的反向自检
门禁写好后的第一件事**不是**跑它,而是**破坏一条数据，看它报不报**。

```python
# _neg_scan_test.py 骨架
# 1) 在内存里造一条已知错误（如把某个子单的局办改成另一个）
# 2) 调用扫描器内核，断言目标契约「报出」且计数 == 1
# 3) 断言其余契约「未被误伤」（计数仍为 0）
```

没有这一步，你无法区分「真的没问题」和「扫描器根本没在扫」。

### 三类进阶门禁（I~K）

当交付物是**多端原型/应用**（有客户端 JS 渲染、有导航分类、有业务编号体系）时，A~H 之外再加三类。

#### I 渲染真值验证（DOM 桩 + 浏览器几何探针）

A~H 比对的是**源码文本**，但用户看到的是**渲染产物**。当页面把数据/导航/标注**动态渲染**出来时，源码里根本没有可比对的字面量 —— 必须验证「渲染出来的东西对不对」。

两条路子，按需选：

| 方式 | 何时用 | 判据 |
|---|---|---|
| **无浏览器 DOM 桩** | 验证「JS 渲染出的结构/文本/属性」 | 用桩 DOM **真跑**页面 JS（如渲染函数）→ 解析产物 → 断言。**不解析源码字面量**（源码里的注释/模板会误伤） |
| **真实浏览器几何探针** | 验证「布局对不对、有没有被遮挡/溢出」 | `elementFromPoint(控件中心)` 非自身/null ⇒ 被遮挡或出视口。**读 CSS 猜不出布局 bug** |

> **为什么 DOM 桩要「真跑」而不是「搜源码」**：源码里常有刻意保留的注释/死代码（例如分组注释里提到某个已废弃的分类名）。全文搜会命中它们 ⇒ 误报。**跑一遍渲染函数再断言产物**，是被渲染出来的才算数。

**DOM 桩五坑（必记）**：

1. `getAttribute` 可能恒返 `null`、`getElementById` 对不存在的 id 可能返回**可链式访问的 null 对象**（不是 `undefined`）⇒ 桩内一切「属性/存在性」断言改用 `raw()` **源码文本**核对；真实浏览器里才用 locator。
2. 可折叠容器（`<details>`）**默认收起** ⇒ 断言其正文前必须先 `.open = true`，否则恒假。
3. 同时可见的多个同选择器元素（如抽屉与二次确认框同为 `.dialog-mask.show`）⇒ Playwright strict mode 报「resolved to 2 elements」；按**打开顺序**取（如 `.last()`）。
4. 几何探针的 `null` 有两种**正常**来源：中心点**越出视口**、或**被祖先 `overflow:auto|scroll|hidden` 裁剪** ⇒ 必须先排除这两种，否则整页误报。
5. 桩与真机行为不同：桩内**无法**判样式/几何，几何类断言一律交真实浏览器。

#### J 导航 / 分类三方一致性

导航结构是典型的「同一事实多副本」：**侧栏分类定义 ↔ 各页面面包屑 ↔ 说明文档的菜单树**。任一处改了另两处不动，就会出现「侧栏有、文档没有」这类漂移。

判据：
- 三方各自解析出「分类 → 页面」的结构，做**双向差集**，两个差集都为空。
- **多角色**要逐角色比（同一套侧栏在不同角色下分类可能不同）。
- **按语义字段比对，不全文搜**：断言「某分类名已清零」时，要**提取标题字段逐个比对**，不能全文搜（分组注释里可能刻意保留该词）。
- **层级判定要看结构不看字面量**：面包屑层级别用「有几段文本」数，用**分隔符数量**（第三级可能是表达式而非字面量，正则捕获不到）。
- **菜单项 id ≠ 页面 id**（一个页面可对应多个菜单项，或多项同页）⇒ 计数用常量与动态求值，别写死。

#### K 编号空间治理（引用 ↔ 登记双向）

任何有业务编号体系（用例号 / 规则号 / 实体号 / 版本号）的项目，编号池都是共享资源，会出四类问题：

| 问题 | 判据 |
|---|---|
| **悬空引用** | 被引用的编号在登记表里不存在 |
| **孤儿登记** | 登记了但无人引用（**单向检查的经典盲区**：只查悬空会漏掉它） |
| **重复占用** | 同一编号被两处登记、语义不同 |
| **空号 / 同前缀歧义** | 编号跳号；或同一前缀被两个体系占用 |

**判据**：做**双向**交叉 —— `引用集合 − 登记集合` 与 `登记集合 − 引用集合` 都为空；再做**登记唯一性**与**区间连续性**检查。

> ⚠️ 只做单向（悬空）检查是最常见的漏洞：它会让「登记了却没被任何地方引用」静默通过。**双向都要查。**

## 四、写门禁的六条工程纪律

1. **每条契约必须打印「已比对 N 项」**，`N = 0` 视为失败。
   页面全派生之后，扫描器可能一个字面量都找不到但仍「全绿」—— 这就是静默空转。
2. **按对象配平，别用窗口式匹配**（如「前后 N 字符」），窗口会串到邻行。
3. **同名不同义要分码**：不同实体的同名字段（父表/子表都有 `status`；`merchant` 是商家而 `company` 是对手方）
   ⇒ 取「第一个命中」会取错实体；每个实体必须有自己的取值函数。
4. **跨实体按值互校**，不要序列化整个对象再比（键序不同会造成假失败）。
5. **慢门禁逐条跑、显式给长超时**：浏览器类门禁单条可能 60~200s，用 `for` 循环批量跑会被默认超时
   **SIGTERM** 掉，表现为「无输出 + 退出码 1」—— 别把它误判成断言失败。
6. **需要网络的探针**：先显式起本地静态服务器，且**必须以后台任务方式启动**（子 shell `&` 会随调用结束被杀，
   表现为连接被拒 / `ERR_CONNECTION_REFUSED`）；跑完记得停服。

## 五、门禁与被测对象的隐式契约（改 UI 前必读）

门禁断言里藏着三类**对页面结构的固定假设**。页面结构一改，它们不会报「断言过期」，而是以更隐蔽的方式失败：**取到 0 行仍全绿、拿错列当 id、探针超时崩溃**。因此改任何页面结构（加/删列、删容器、改文案、改交互形态）**之前**，必须先 grep 门禁源码。

| 固定假设 | 藏在哪 | 页面改动触发 | 失败形态 |
|---|---|---|---|
| **列索引** | `td[7]` / `children[0..8]` / `colspan="13"` | 加/删/挪列（含首列加序号） | 取到空/错列 ⇒ 断言恒假或探针崩溃 |
| **元素 id / 存在性** | `getElementById('x')` / 对某 id 的文案断言 | 删容器、删页头/汇总条 | 探针超时崩溃；页面侧未判空写入 ⇒ pageerror |
| **文案 / 结构正则** | `'更多 >'`、按「单号列」识别行 | 文案改字、行锚点列下线 | 恒假失败，或**静默取 0 行仍全绿** |

四条纪律：

1. **改 UI 前先做「门禁依赖侦查」**：grep 门禁脚本中该页相关的 `td[`、`children[`、`getElementById`、文案断言，列成**门禁同步清单**写进修改计划，与改动同批实施（UI 门禁可集中在收尾批重排，但清单必须先建）。
2. **断言重排优先换「健壮锚点」**：行识别别绑在易下线的列（如单号列）上，改按标题/稳定字段命中；列索引尽量改成语义选择器。
3. **「静默取 0 行」是失败不是通过**：探针类断言取行后必须先断言「行数 > 0」，再断言内容 —— 否则锚点列下线后整段检查静默空转。
4. **有副作用的门禁要显式标注**：绝大多数门禁只读；个别会重写产物（如构建报告脚本）⇒ 标注写进该脚本头注释与门禁清单，**纯审查轮禁跑**。

> 真实三连踩（同一项目三轮内）：删表格两列后 `_ui_states_check` 取 0 行报 5 处 FAIL；主表首列加「序号」后 `_ui_app_authz_check` 拿序号当 id 探针崩溃；删 `#pageSub` 元素后 `_ui_data_center_check` 等待超时崩溃。三次都是「先改页面、门禁炸了才知道」。

## 六、标准流程

```
1 列「同一事实副本表」         → 确定权威源与派生关系
2 为每类副本定义机械判据        → 落成 A~H 中的若干条（多端原型/应用再加 I~K）
3 写门禁脚本（每条打印已比对 N 项 + 覆盖面对照）
4 写负向自检（F）：造错 → 必须报出
5 跑门禁 → 全绿 or 出缺口清单
6 缺口清单交回需求方决策（补数据 / 补渲染 / 调整口径）
7 修完后复跑，并把「已比对项数」与「覆盖面」固化进报告
```

## 七、产出契约

| 产出 | 说明 |
|---|---|
| `consistency-report.md` | 人读：A~H（+ 进阶 I~K）逐条结论 + 已比对项数 + 覆盖面 + 缺口清单 |
| `consistency-report.json` | 机读：`{gate, checked, failures, gaps[], generatedAt}` |
| `audit_<topic>.py` | 主门禁脚本（只读，退出码 0/1） |
| `_neg_scan_test.py` | 负向自检脚本（**装备在门禁旁边，改门禁必连带改它**） |
| `_dom_stub.js` / `_ui_*_check.js` | （进阶 I）无浏览器 DOM 桩 / 真实浏览器几何探针 |
| `build-report.json` | 规模与指纹（页数 / 标注数 / 行数 / 每项 hash） |

## 八、质量检查清单

- [ ] 已列出「同一事实副本表」，并标明权威源与派生关系。
- [ ] 每一类副本都有机械判据，非人工抽查。
- [ ] 镜像型副本用**逐字节**判据，不用「语义一致」。
- [ ] 每条契约都打印**「已比对 N 项」**，`N=0` 会失败。
- [ ] 有覆盖面对照，明确「哪些脚本/文件有字面量可比对」。
- [ ] 有负向自检（造已知错误必须报出），且断言其余契约未被误伤。
- [ ] 跨实体比较**按值**，未序列化整对象。
- [ ] 同名不同义字段已分码取值。
- [ ] 陈旧术语用三层（硬禁词 / 迁移引用 / 现行权威标签）区分，未一刀切。
- [ ] 门禁**只报不修**；缺口清单已交回需求方。
- [ ] 门禁脚本与负向自检已一同纳入版本管理（改一个必改另一个）。
- [ ] （进阶 I）动态渲染的内容用 DOM 桩**真跑**验证，未解析源码字面量；几何类断言交真实浏览器。
- [ ] （进阶 J）导航三方（侧栏/面包屑/文档菜单树）双向差集为空，多角色逐角色比。
- [ ] （进阶 K）编号空间**双向**交叉（悬空 + 孤儿）都查了，不只查单向。
- [ ] （隐式契约）改页面结构前已 grep 门禁源码的 `td[`/`children[`/`getElementById`/文案断言，**门禁同步清单**已列进计划。
- [ ] 断言重排换用了**健壮锚点**；探针取行后有「行数 > 0」前置断言；有副作用的门禁已标注并告知「审查轮禁跑」。
- [ ] 慢门禁逐条跑并给了长超时；需要网络的探针以后台任务起服务器并已停服。
