# 代码审查检查项清单

本清单对应 `code-review` skill 的四个审查维度。每维度 8-12 项,共约 40 项。
审查时对每个变更点逐项过一遍,命中即记为 issue。

## 一、正确性 (correctness)

1. **逻辑条件**:if / while / 三元运算符的条件是否写反?是否错用 `=` 与 `==`、`&&` 与 `||`?
2. **边界条件**:空集合、空字符串、首元素、末元素、单元素、最大值、最小值、负数、零是否被正确处理?
3. **off-by-one**:循环边界(`<` vs `<=`)、切片区间(开闭)、数组索引是否越界?
4. **异常处理**:是否吞掉异常(catch 后空处理)?catch 范围是否过宽(如 catch Exception 把 OOM 也吞了)?是否该传播却吞了?
5. **finally 副作用**:finally 块是否意外修改返回值或抛出异常掩盖原始异常?
6. **空值解引用**:None / null / undefined 是否在解引用 / 调用方法前判空?可选链 / 空合并是否用对?
7. **资源泄漏**:文件、数据库连接、网络连接、锁、线程池是否在所有路径(含异常)下释放?是否用 try-with-resources / with / using?
8. **并发正确性**:共享可变状态是否有竞态?复合操作是否原子?锁顺序是否一致(防死锁)?是否需要 volatile / memory barrier?
9. **类型与隐式转换**:隐式转换是否丢失精度或改变语义(如 int → float、字符串数字比较)?
10. **返回值忽略**:错误码、状态码、IO 返回值是否被忽略?是否该检查却没检查?
11. **状态机 / 分支遗漏**:switch / match 是否有 default?所有状态分支是否覆盖?枚举新增值后是否所有 switch 都更新?

## 二、安全性 (security)

1. **SQL 注入**:是否拼接字符串构造 SQL?是否使用参数化查询 / ORM 的占位符?
2. **XSS**:用户输入是否未经转义输出到 HTML?是否使用 innerHTML / dangerouslySetInnerHTML / v-html?
3. **命令注入**:是否用 os.system / exec / subprocess(shell=True) 拼接用户输入?是否用参数列表形式?
4. **硬编码密钥**:代码中是否出现 API Key / Token / 密码 / 私钥?是否应从环境变量 / 密钥管理服务读取?
5. **权限绕过**:接口是否缺失鉴权中间件?是否仅前端隐藏?是否存在 IDOR(直接对象引用越权)?
6. **敏感数据明文**:密码 / Token / 身份证 / 手机号是否出现在日志、错误信息、响应体、数据库明文存储?
7. **不安全反序列化**:是否反序列化不可信数据(pickle / yaml.load / ObjectInputStream)?是否用安全版本?
8. **路径穿越**:文件路径是否包含用户输入?是否校验 `../`?是否做了路径规范化与白名单?
9. **弱加密 / 弱哈希**:是否用 MD5 / SHA1 存密码?是否用弱随机数(Math.random 生成 Token)?是否硬编码盐?
10. **CSRF / 开放重定向 / SSRF**:状态变更接口是否校验 CSRF Token?重定向 URL 是否来自用户输入?后端请求 URL 是否可被用户控制?
11. **鉴权强度**:密码策略、Token 过期、刷新机制、登录失败锁定是否合理?

## 三、性能 (performance)

1. **N+1 查询**:循环内是否执行 DB 查询或调用外部 API?是否可用 IN 批量查询 / join / 预加载?
2. **不必要的循环**:是否能用哈希表 O(1) 查找代替 O(n) 遍历?嵌套循环是否能降阶?
3. **大对象拷贝**:大数组 / 大对象是否按值传递(应传引用 / 指针)?是否在循环内重复构造大对象?
4. **缺索引**:高频查询的 WHERE / JOIN / ORDER BY 字段是否有索引?是否有全表扫描风险?
5. **内存泄漏**:闭包是否持有大对象?缓存是否无上限 / LRU?事件监听器 / 定时器是否在销毁时移除?
6. **同步阻塞**:在异步上下文或热路径中是否调用了同步阻塞 IO(文件、网络、DB)?
7. **重复计算**:循环不变量是否在循环内重复计算?是否可缓存 / 提取到循环外?
8. **大列表全量加载**:是否一次性加载全表 / 全列表到内存?是否应分页 / 流式 / 惰性加载?
9. **不必要的序列化**:是否在热路径反复 JSON 序列化 / 反序列化同一对象?
10. **资源争用**:是否在持有锁时执行慢操作(DB 调用、IO)?是否过长持有事务?

## 四、可维护性 (maintainability)

1. **命名**:变量 / 函数 / 类名是否准确表达意图?是否单字母、缩写、误导名(如 `data`、`tmp`、`info`)?
2. **函数长度**:函数是否超过 80 行?是否承担多个职责?是否难以一次性理解?
3. **参数数量**:函数参数是否超过 5 个?是否可用对象 / 结构体封装?
4. **嵌套深度**:if / for / while 嵌套是否超过 4 层?是否可用提前返回 / 卫语句扁平化?
5. **重复代码**:是否存在复制粘贴的代码块(>10 行相似)?是否应抽函数 / 基类 / 工具方法?
6. **注释缺失**:复杂业务逻辑、算法、正则、魔法数字是否有注释说明"为什么"而非"是什么"?
7. **高耦合**:是否直接依赖具体实现而非接口?是否使用全局状态 / 单例?是否存在循环依赖?
8. **单一职责**:一个类 / 模块是否承担过多职责?是否应拆分?
9. **魔法数字**:代码中是否出现未命名的字面量(如 `86400`、`0.95`)?是否应抽常量 / 枚举?
10. **错误信息**:错误信息是否可定位(含文件、行、上下文)?是否过于笼统("操作失败")?
11. **死代码**:是否有注释掉的代码、未使用的函数 / 变量 / 导入、unreachable 分支?
12. **TODO / FIXME**:是否有未跟踪的 TODO / FIXME?是否记录了负责人或 issue 编号?

---

**使用提示**:审查时不必逐条罗列"已检查 X 项",只在命中时记录 issue。未命中的维度在报告"通过项摘要"中一句话带过即可。
