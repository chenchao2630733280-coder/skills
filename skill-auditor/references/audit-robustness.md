# 维度 3:健壮性审查规则

> 审查失败回退、降级路径、占位机制。本维度关注 skill 在"异常输入/部分失败"场景下的韧性。

---

## 3.1 失败回退策略表

**检查项**:
1. 编排总纲(如 game-forge-master)有"失败回退策略"章节
2. 每类可能的失败都有对应回退策略
3. 回退策略明确"降级到什么程度"和"标记到哪里"

**标准回退策略表结构**:
| 失败场景 | 回退策略 |
|---|---|
| {失败类型} | {降级措施} + {标记位置} |

**常见失败场景清单(必覆盖)**:
- AI 生图/资源生成失败
- 代码类型检查/编译失败
- 构建/导出失败
- 浏览器自测失败
- 资源加载 404
- 依赖工具未安装(如 Unity Editor)
- 网络/API 调用失败

**检查方法**:
```
1. 提取总纲的失败回退表
2. 对照"常见失败场景清单"检查覆盖度
3. 对每个回退策略,验证:是否有降级措施 + 是否有标记位置
4. 检查下游 skill 是否也有对应的局部回退(如 game-integrate 的引擎特定回退)
```

**严重级别**:
- 无失败回退章节 → CRITICAL
- 关键失败场景无回退 → WARNING
- 回退策略缺标记位置 → INFO

---

## 3.2 降级层级完整性

**检查项**:
降级路径应遵循从轻到重的层级,不应直接从"失败"跳到"放弃":

```
自动修复 N 轮 → 降级配置 → 占位产出 → 延后到宿主 → 标记跳过
   (最轻)                                           (最重)
```

**每层含义**:
| 层级 | 措施 | 示例 |
|---|---|---|
| L1 自动修复 | AI 修复 N 轮(通常 3 轮) | typecheck 失败 → 修复 3 轮 |
| L2 降级配置 | 放宽约束/切换模式 | strict:true → strict:false |
| L3 占位产出 | 用占位资源/静音替代 | 图片 404 → 纯色占位图 |
| L4 延后宿主 | 沙箱无法执行,延后到宿主 | 无 Unity Editor → 产出代码,构建延后 |
| L5 标记跳过 | 记录到报告,不阻塞 | 浏览器自测失败 → 记录截图,继续 |

**检查方法**:
```
1. 对每个失败场景,检查是否有降级层级
2. 是否直接从"失败"跳到"阻塞/放弃"(违规)
3. 降级后是否标记到报告(ASSET_ISSUES.md / BUILD_REPORT.md)
```

**严重级别**:
- 失败直接阻塞流水线 → CRITICAL
- 缺少 L1-L2 层级 → WARNING
- 降级后未标记 → WARNING(后续无法追踪)

---

## 3.3 失败不阻塞

**检查项**:
1. 失败后允许继续往下走(不中断流水线)
2. 失败项汇总到报告(不丢失)
3. 最终产物可能不完美但可用(不白跑)

**标准表述**:
```
"所有失败都允许继续往下走,失败项汇总到 docs/BUILD_REPORT.md 的'已知问题'章节,供人工后补。"
```

**检查方法**:
```
1. 在流程描述中搜索"失败"关键词
2. 验证失败后的处理是"继续 + 标记"而非"中断"
3. 验证最终报告有"已知问题"章节
```

**严重级别**:
- 失败中断流水线 → CRITICAL
- 失败项未汇总到报告 → WARNING

---

## 3.4 错误处理边界

**检查项**:
1. **系统边界有校验**:用户输入、外部 API、文件读取等边界有校验
2. **内部信任**:skill 内部模块间调用不重复校验(信任上游已校验)
3. **校验失败有明确错误信息**:不是 silent fail

**系统边界清单**:
- 文件存在性校验(读取前)
- JSON 解析校验(消费上游工件前)
- 外部 CLI 执行结果校验(执行后检查 exit code)
- 用户输入合法性校验(AskUserQuestion 后)

**检查方法**:
```
1. 搜索文件读取操作,验证读取前有存在性校验
2. 搜索 JSON 解析操作,验证有 try-catch 或 schema 校验
3. 搜索 CLI 命令执行,验证有 exit code 检查
4. 搜索内部函数调用,验证无冗余校验(过度防御)
```

**严重级别**:
- 边界无校验 → WARNING
- 内部过度防御 → INFO
- silent fail → WARNING

---

## 3.5 占位机制

**检查项**:
1. 资源失败有占位(纯色图 + 文字标识)
2. 音频失败有占位(1 秒静音 wav)
3. 占位资源有标记(便于后续替换)
4. 占位产出可运行(不因占位导致崩溃)

**标准占位规范**:
| 资源类型 | 占位形式 | 标记位置 |
|---|---|---|
| 图片 | 纯色 + 文字标识 | docs/ASSET_ISSUES.md |
| 音频 | 1 秒静音 wav | docs/ASSET_ISSUES.md |
| 图集 | 降级散图 | docs/ASSET_ISSUES.md |
| 代码 | 降级 strict:false | docs/BUILD_REPORT.md |

**检查方法**:
```
1. 搜索"占位"/"placeholder"/"降级"关键词
2. 验证每种资源类型都有占位方案
3. 验证占位有标记(能追踪到)
```

**严重级别**:
- 资源失败无占位 → WARNING
- 占位未标记 → WARNING

---

## 3.6 重试上限

**检查项**:
1. 自动修复有重试上限(通常 3 轮)
2. 重试上限后有降级(不无限重试)
3. 浏览器自测有重试上限(通常 2 轮)

**检查方法**:
```
1. 搜索"重试"/"修复"/"retry"关键词
2. 验证有上限数字(如"最多 3 轮")
3. 验证达到上限后有降级
```

**严重级别**:
- 无限重试 → CRITICAL(可能死循环)
- 有上限但无降级 → WARNING
