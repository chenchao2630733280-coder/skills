## 1 结论

关键的一条不是格式错，而是**三套"生产路线"术语并存**（R2-01）——它直接让 Gate 2.5 的生成器规格检查可以合法地不触发。

## 2 P0 —— 会导致漏检或产物错误

### R2-01 三套"生产路线"术语并存，Gate 2.5 的生成器检查存在漏触发路径

| 位置 | 路线划分 |
|---|---|
| `references/14` §1 | 正向手调 / **反向生成** / 导入 |
| `templates/LEVEL_AUTHORING_template.md` §6 | 手工 / **生成器** / 导入 |
| `references/15` §1、§6 | 生成器（含"反向构造 vs 正向筛选"，§4）/ 导入 / 手调 |
| `game-quality-gate` 2.5.11 触发条件 | 声明为"**生成器/导入**" |

后果：项目若按 14 声明路线为"**反向生成**"，字符串不在"生成器/导入"里 → `2.5.11 / G25-11` **不触发** →
`docs/LEVEL_GENERATOR_SPEC.md` 不产出也不检查。而它实际上是生成器路线。
第二个后果：策划读作者手册（手工/生成器/导入）、agent 读 14（手调/反向生成/导入），两套名词对不上。

**修法**：统一为三条 —— **手调 / 生成器 / 导入**，把"反向生成"降为**生成器内部的构造策略**
（与"正向生成 + 筛选"并列，由 15 §4 的成本模型 `c/p > 构造成本` 选）。14 §2 标题改为
"生成器 · 反向构造分支的五步"。这样 gate 2.5.11 的触发条件无需改动即覆盖，手册也不用改。

## 3 P1 —— 内部矛盾与事实错误

### R2-04 `14 §2④` 与 `14 §9` / `15` / `16` 自相矛盾

14 §2④ 写"解路数校验是**本 skill 不含的能力**"，但同文件 §9 已指向 15/16，
而 15 工位 D 与 16 §4 恰好给了验证器规格（状态/可见性/迁移/剪枝/预算）和完整伪代码。

**修法**：改成"规格与伪代码见 15 工位 D、16 §4；本 skill 不含**可直接跑的实现**——状态表示必须按自己游戏重写"。
（"不含实现"和"不含能力"是两回事，前者是边界，后者是缺口，写错会把读者赶去自己发明。）

### R2-05 `Sprite/Body 偏移` 的章节号错了，且被复制到第二个文件

`game-integrate/SKILL.md` §10.2 与我新抽的 `references/numeric-playtest.md` §5 都写
"回到 `game-code-forge` §十二 Sprite/Body 偏移排查"。实际 `game-code-forge` **§十二 是"交互约定"**，
Sprite/Body 偏移在 **§十四**。这是被抽文件时照抄的旧错，抽一次变两处。

**修法**：两处改 §十四。

### R2-06 `2.5.10` 用序号枚举手册章节，与模板真实节号对不上

判据写"含六节：①上手 ②字段表 ③旋钮 ④硬约束 ⑤验收对跑 ⑥生产路线"，
但模板实际节号是 §1 上手 / §2 字段 / §3 语义档位 / §4 旋钮 / §5 硬约束 / §6 生产路线 / §7 验收。
按序号去找会把"④硬约束"当成 §4（旋钮），核对时必然数错。

**修法**：判据直接用模板节号（§1/§2/§4/§5/§6/§7），与 `game-level-design` 自检清单的写法对齐
（那一处已经用的是真实节号，两处不一致本身也是问题）。
