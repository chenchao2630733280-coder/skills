## 2 P0 —— 剪枝会误杀可解关卡

### 16-01 §4 剪枝 2 用"可见容量"作上界，会剪掉可解分支

原文：

> | 2 | 容量上界 | 剩余 need 总量 > 剩余**可见**容量 → 不可能完成（可按颜色分别算，更强） |

反例：某色剩余需求 10，当前可见只有 1 根容量 5 的线轴，它下面压着两根容量 3 的。
可见容量 = 5 < 10 → 按这条判死。实际取走 5 后露出 3+3，总量 11 ≥ 10，**可解**。

原因：可见集只是"现在能碰的"，被压住的部分在取走上层后同样可用。容量上界必须对**全部存活线轴**求和，
而不是对可见集合求和。

```
正确：need[c] > Σ_{j: alive[j] and color[j]==c} remaining_cap[j]  → 该色不可能凑齐
```

这条最危险的地方是**方向**：它不产出废关，它**丢弃好关**，而且不报错。
这和 §7.2 描述的症状一模一样（假阴性、无声丢弃），但 7.2 讲的是记忆化 key，根因在剪枝这里。

## 3 P1 —— 伪代码按字面写会出错

### 16-02 §2 `exact_partition` 缺 `best[]` 与 `last[]` 的初始化

```
best[0] = 0
for s in 1..amount:
    for c in cap_lib:
        if s >= c and best[s-c] + 1 < best[s]:     # ← best[s] 此时是什么？
```
只设了 `best[0]`。任何把数组默认初始化为 0 的语言（Python 的 `[0]*n`、C 的全局数组），
条件 `best[s-c]+1 < best[s]` 里两边都是 0+1 < 0 → 恒假 → `best[amount]` 永远是 0 →
`if best[amount] == INF` 永远不成立 → 回溯时 `last[s]` 未设置（0 或 None）→ **死循环或 TypeError**。

必须显式 `best[1..amount] = INF`、`last[1..amount] = None`。
文档最后一句才出现 `INF`，说明作者心里有它，只是没写进初始化——**这正是"照抄会出错"的标准形态**，
应该并进 §7 当成第 4 条坑。

### 16-03 §6 判峰值的口径与 §4 定义不一致

```
peak = simulate_plan_peak(seq, tray)   # ④ I4 检查点：只模拟 seq 这一条序
v = solve(spools, tray)                # ⑤ 验证器（§4 说 DFS 会给 peak_min）
if not v.solvable: continue
if peak < tray: return spools
```
§4 明确定义 DFS 输出 `peak_min`（所有解里的最小托盘峰值），15 的 I4 也要求
"存在**至少一条**不超容的消耗序"。这里却拿 `seq`（一条随机 shuffle 出来的序）的峰值去卡，
与 I4 的语义不是一回事：`seq` 的峰值偏大 → 关卡被丢，而它其实有更省托盘的解法。

既然 ⑤ 已经算出 `v.peak_min`，就该用它：`if v.peak_min < tray: return spools`。
`simulate_plan_peak` 只在"还没有验证器"的降级场景下才有意义，那时要写明这是保守近似。

### 16-04 §3 `pos = (i + rand(seed)) % positions` 写不出随机，且 `% positions` 类型不对

两处：

1. `rand(seed)` 是纯函数，同一 seed 每次返回**同一个数**。于是 `pos = (i + c) % positions`，
   是固定偏移的轮转，不是随机分配。要随机应写成 `rand(seed, i)` 或先 `shuffle` 出一张位置表。
   文档紧接着论证"随机性只放在 pos 上"，但代码里的 pos 恰恰不随机。
2. `positions` 在第 98 行是函数参数，后面又当整数用（`% positions`），又当容器用（`emit spool(..., pos, ...)`、
   `depth[pos]`）。应该是 `% len(positions)` 并把 `positions[pos]` 传出去。

§3 那段文字论证（层号不能随机、随机只在位置）是对的，只是伪代码没跟上。
