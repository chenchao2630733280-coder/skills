## 0. 结论先行

1. **前两份文档覆盖的是"别做错"，本文覆盖的是"不会做"**。这个项目最稀缺的不是纪律，而是四个**流水线没有（或只做了半截）的能力**：提示系统、新手引导、零素材音频、打击感配方。
2. **一个"有传感器没执行器"的缺口 + 一个反向决策**：提示在流水线里只以**数值旋钮**（`schema.py:79` 的 `hints` 次数）和**埋点字段**（`05_telemetry:17` 的 `hint_show`）存在——技能在**度量**提示，却不会**设计**提示系统。`juice` 则**全库 0 次命中**。更严重的是 `game-blueprint:192` 明确写着"**不做新手引导(除非用户要)**"：把 UX 关键环节主动排除，而本项目用 301 行导演 + 一条假绿规则证明它必需且易踩坑。
3. **一个已经被验证过、却被丢掉的方案**：音频。`game-art-spec` 的 AUDIO_SPEC 模板（§1/§2/§2.5/§3占位/§4后补）和本项目的 `docs/AUDIO_SPEC.md` 几乎逐字相同——**说明本项目就是照这个模板做的**，然后往上加了两节（合成参数表、音量层级）并换了一条策略（现场合成而非静音占位）。这条升级路径是现成的。
4. **模块层有 7 个可搬的骨架**（`EventBus` / `SaveStore` / `validateLevel` / `uiKit` / `AudioEngine` / `JuiceEffects` / `TutorialDirector`，合计 1359 行）。其中 `validateLevel.ts`（206 行，八条硬约束）就是"关卡数据即契约"的现成实现，可以直接当 Gate 2.5 的判据执行体——比再写一遍判据文档强。
5. **算法与方法论层只有 7 条是新的**（shift-not-filter、计划式求解、死锁判据、扇出记账、规则单一来源、属性归属表、不变式优先）。其余（量尺自检、必赢判据、判据分层、归因三条）已在 LGE 文档写过，本文只登记不重复。

## 3. 四个能力缺口（详述）

### 3.1 C1 提示系统 ⭐ 最大的单点缺口

**现象**：提示在流水线里**只以三个碎片存在**——

```
schema.py:79         {"param": "hints", ... "label": "提示次数", "note": "提示是软辅助"}   ← 当数值旋钮
05_telemetry:17      | hint_show | 提示展示 | hint_type, trigger_reason |                    ← 当埋点字段
03_adaptive:89       return tutorial_hint_if_confused(state)                              ← 一行伪代码
```

即：**技能在度量提示（有传感器），但不会设计提示系统（没有执行器）**。`game-level-design` 服务的正是"关卡制/解谜"品类，而这个品类最大的流失点就是"卡住"——流水线能产出难度曲线、能预测首通率，却答不出"玩家卡住时给他什么"。

**本项目做到了什么**（`HINT_SOLVER.md` 207 行，`Solver.ts` 374 行）：一套带**四层语义**的提示：

| 层 | 做法 | 为什么 |
|---|---|---|
| 规则来源 | 求解器 **import 运行时的规则实现**，不复制 | 复制必然分叉，提示会给出非法解（§2「规则只有一份」） |
| 顺序 | 连"颜色的处理顺序"都照抄运行时 | 顺序不同 → 同样局面得出不同结论 |
| 输出 | 路径是**计划**，不是每步重算 | 每步重算会让提示抖动、并在玩家回退时前后不一致（§3） |
| 预算 | 有搜索预算 + `exact` 语义；超预算返回"方向"并标 `exact=false` | **不许假装成功**（§4） |
| 呈现 | 面板分"看哪 → 点哪 → 为什么"三档 | 直接给答案等于替玩家玩（§5） |
| 边界 | 明写"哪类局面求不出" | 已知限制本身就是交付物（§7） |

**通用化后的骨架**（与新品类无关）：

```
① 规则单一来源（求解器复用运行时）  ② 搜索要有预算与 exact 标记
③ 输出是计划而非逐帧决策            ④ 提示强度可分档（方向/步骤/答案）
⑤ 已知限制要写明                    ⑥ 提示质量进验收（提示解必须能走通）
```

**落点**：`game-spec` 的 PRD 模板加 §1.5「提示与引导」（症状 → 强度分档 → 触发策略）；`game-code-forge` 加 `references/hint_solver.md`（六条骨架 + 一个最小接口签名）。**不新建 stage**。

### 3.2 C2 新手引导 ⭐ 且要撤掉一条反向决策

**现状**：`game-blueprint:192` 写着 `- 不做新手引导(除非用户要)`。**这条要么是笔误，要么是当年的取舍，但它现在挡住了一个必需能力。**

**本项目的证据是双向的**：
- 正面：`TutorialDirector.ts` 301 行，把引导做成**状态机**（步骤 / 触发条件 / 完成条件 / 只跑一次标记）；
- 反面：`ENGINEERING_RULES.md:53` **R-05** ——"有教程的关，点击会被门控吞掉"，脚本点任意轴全部无效，断言在"什么都没发生"下继续跑，**静默假绿**。修复方式是在点轴前**编程解除教程门控**。

即：引导不只是"加个弹窗"，它会**改变输入语义**，而这件事必须在设计阶段就规定清楚，否则每个验证脚本都要各自发现一次。

**通用化后的四条要求**：
1. **状态机式**：步骤 × 触发 × 完成条件 × 是否可跳过；
2. **门控可枚举**：明确列出"哪类输入在哪个步骤被吞"，写进 TECH_DESIGN；
3. **必须提供测试旁路**（`skipTutorial()` / `forceCompleteStep()`）—— 没有它，所有自动化验证都会在引导关静默假绿；
4. **只跑一次**：用存档标记，且标记要能被测试重置。

**落点**：blueprint 第 192 行改为"机制/解谜类必做，纯动作类可省"；spec PRD 加 §1.5 后半；code-forge 加引导状态机模板 + **强制要求旁路接口**；Gate 2 加一条判据「存在引导时，TECH_DESIGN 必须有旁路接口定义」。

### 3.3 C3 音频：把"静音占位"升级成"零素材合成"

这是本次最"低成本高收益"的一条，因为**模板已经存在，只差两节**。

对比同一份交付物：

| 章节 | `game-art-spec` 模板 | 项目 `AUDIO_SPEC.md` | 差异含义 |
|---|---|---|---|
| §1 默认策略 | 静音占位，人工后补 | 同（但作为兜底而非主线） | — |
| §2 音频清单 | ✅ | ✅ | — |
| §2.5 SFX 事件映射表 | ✅（含优先级/层级/并发上限） | ✅（更细，含"整批只响一次"） | **说明项目照模板做的** |
| §3 合成参数表 | **无** | ✅ 节点链 + 包络 + 增益 | **缺口** |
| §4 占位/接入 | 静音文件复制 | WebAudio 接入五步（`ctx.resume()` 手势、降级、静音、`visibilitychange`） | **缺口** |
| §5 音量层级 | **无** | 胜负 1.0 / 反馈 0.8 / 次要 0.5 / 总输出 0.7 | **缺口** |

**关键判断**：AI 流水线生成不了可用的音频素材，于是模板选了"静音占位"，结果是**交付的游戏是哑的**——这不是保守，是能力缺口被写成了默认策略。本项目给出的第三条路是：**用 WebAudio 现场合成，零素材文件，参数表就是实现契约**。

好处很硬：无资源文件、无加载、无版权、可参数化变体（连击变调只需 `1.2^n`）、包体零增长。

**落点**：`game-art-spec` §五 模板补 §3（节点链 + 包络 + 增益）与 §5（音量层级 + 总输出上限），并把"静音占位"降级为**兜底**而非默认；`game-code-forge` 引用 `AudioEngine` 的 `SFX_TABLE` 形态（参数全部常量化，与 manifest 的 `audio[].synth` 一一对应）。

### 3.4 C4 打击感：从"原则"到"配方"

`game-polish` 已有正确原则（"只加效果，不改玩法"、"视觉/手感/细节三层"），但**没有配方**——每次都要模型重新发明"什么该抖、抖多少"。

项目给了可复制的形态：

| 通道 | 实现 | 可参数化的量 |
|---|---|---|
| 位移/挤压 | `JuiceEffects`（94 行） | 缩放比、回弹时长、过冲系数 |
| 粒子 | `ParticleManager`（246 行） | 数量、寿命、初速、重力、淡出曲线 |
| 镜头 | `CameraController`（31 行） | 抖动幅度、衰减、是否跟随 |
| 顿帧 | 由 tick 驱动 | 帧数（按事件重要性分档） |
| 飘字 | HUD | 位移方向、停留、字号曲线 |

**通用化**：一张"事件 → 五通道幅度"的配方表（每个通道给**区间**而非定值，按事件重要性 P0/P1/P2 分三档），落到 `game-polish/references/juice_recipes.md`。判据：**任一通道都不得改变逻辑状态**（呼应"只加效果"），且所有幅度必须可一键归零（便于回归测试）。

## 6. 新增算法 4 条 + 方法论 3 条

### A1 `shift` 而非 `filter`

`GRAVITY_AND_TICK.md` §三专门论证了"为什么是 `shift` 而不是 `filter`"：`filter` 会**重建**数组，丢失位置身份与相对顺序；`shift` 就地压实，保留顺序与索引稳定。

**通用化**：任何"移除元素后重排"的操作，优先**就地压实**。因为重建会丢失身份，导致①动画插值错位 ②断言基于索引时漂移 ③"这个元素去哪了"无法追踪。

**落点**：`game-code-forge` 的 pitfall 清单一行。

### A2 计划式求解 + `exact` 语义

两件事绑在一起才成立：

- **路径是计划，不是每步重算**（§3）：提示给出一条计划；玩家偏离计划才重算。每步重算会造成提示抖动与前后不一致。
- **预算 + `exact` 标记**（§4）：搜索有上限，超限时返回"方向级建议"并明确标 `exact=false`，**不许把近似解当精确解返回**。

**通用化**：所有"给建议"的模块都要有 `exact` 语义——**建议是否完备，本身是输出的一部分**。这条能直接治"提示给了个走不通的步骤"这类信任崩塌。

### A4 负向判定要**充分**判据

§六的"死锁判定"给出了明确判据（无任何可推进操作），而不是"试了几步没进展"。**判"不可解"是危险动作**——错判会让玩家在可解的局面上看到"失败"。

**通用化**：负向结论（不可解/不通过/无解）必须有**充分**判据；判据不足时宁可输出"未知"，不要输出"失败"。这条与 LGE D5（充分判据零反例）同源，此处是它在机制层的实例。

### A5 扇出记账

§五："`bead:pulled` 的下游（一拍可能扇出 N 次）"——一个事件在同一 tick 内触发 N 个下游，统计口径若按"事件"计还是按"对象"计没写清，就会出现重复计数/漏计，而**两边的单元测试都能过**。

**通用化**：凡"一事件 → N 下游"，必须写明计数口径，并写进验证清单。

### E1 规则单一来源

三处独立证据，说的是同一件事：

- `HINT_SOLVER.md` §2「规则只有一份」，连颜色处理顺序也要照抄；
- `_flat_lib.mjs` 是 `runLen`/`blobPct`/`domPct` 的**唯一实现**，"审计脚本与生成器共用"；
- LGE §15 的收尾："原来 `perfectViaSolver` 和 `minSlotsToWin` 各写一份，**改一处忘一处会让两个入口的剪枝口径分叉**"。

**祈使句**：同一规则出现第二份实现时，先把它收敛成一个被双方 import 的模块，再加一条"两个入口结果一致"的断言。

### E2 属性归属表

`ANIMATION_STATE_MACHINE.md` §一「总原则：属性归属表」——每个属性标明 owner 是逻辑层、渲染层还是动画层。这解决的是最常见的双写 bug：动画改了终值、逻辑以为没变。

**祈使句**：写状态机文档，第一张表必须是属性归属表；**任何属性只允许一个 owner 写**。

### E3 不变式优先

`GRAVITY_AND_TICK.md` 的结构是：先给五条不变式（永远为真的句子），再给完整循环，最后 §八 验证清单——并且 §8.1 明确写"`_verify_drop.mjs` **究竟**断言了什么"。

**祈使句**：验证清单不是"测了哪些功能"，而是"守住了哪些恒等式"；每条不变式必须对应至少一条断言，否则不变式只是文案。

2. **有没有独立的评审维度**？有一半。音色选择主观、需要人听，但**参数表已经在 art-spec §2.6 定死了**，code-forge §九.7 是"逐行照抄不重新设计"，不存在 stage 之间的判断分歧。
3. **有没有能挡住其他 stage 的失败模式**？有，但不是"设计不足"，是**声明与实现脱节**：表里有 id 但业务从没播（有表无声）、业务 `play('xxx')` 却不在表里（有声无表，运行时静默不报）。
