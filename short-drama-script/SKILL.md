# Short Drama Script — 短剧正式剧本（阶段 3）

本 skill 是 AI 短剧制作流水线的**阶段 3**，职责是读取故事规格与分集大纲，把每集大纲扩展为可直接拍摄的竖屏短剧正式剧本。

**核心信条**：每集都是"钩子开场 + 冲突推进 + 卡点收尾"的完整单位；规格管"讲什么"，大纲管"这集发生什么"，剧本管"画面里怎么演"。

---

## 一、输入与输出

**输入**（固定路径，必读）：
- `docs/STORY_SPEC.md`：故事规格（发动机 / 核心规则 / 人物系统 / 秘密系统 / 阶段 / 情绪曲线 / 评分）
- `docs/EPISODE_OUTLINE.md`：分集大纲（每集目标与结尾卡点设计）

**输出**（固定路径，与总纲 §八 严格一致，不允许自定义路径）：
- `docs/scripts/EP{01..NN}.md`：每集一文件；NN = 大纲集数；两位数编号（01、23、60）

**读文档须知**：人物口吻 / 规则代价 / 秘密揭露节奏以 STORY_SPEC 为准；每集目标与卡点以 EPISODE_OUTLINE 为准。两者冲突时**回读规格修正剧本**，禁止擅自改规格/大纲（见 runtime.yaml degrade 第 3 条）。

---

## 二、竖屏剧本格式规范（详见 `references/script-format.md`）

### 2.1 单集结构

`开场钩子（0-5 秒出冲突/异常/结果预告）→ 冲突推进 → 结尾卡点`。

### 2.2 剧本内元素（每集完整覆盖）

| 元素 | 写法 |
|---|---|
| 场景标题 | `内/外 + 地点 + 时间`（如：内·总裁办公室·夜） |
| 景别提示 | 特写 / 近景 / 中景 / 全景 / 远景，标注在镜头行首 |
| 角色动作 | 行为描述，动词优先，不写内心独白 |
| 对白 | `角色名：台词` |
| OS / VO 画外音 | OS=内心独白，VO=旁白，标在角色名前（如 `OS-主角：`） |
| 字幕卡点文字 | 结尾卡点句 / 关键信息句，标注 `字幕：` |
| 音效提示 | 括注（如（雷声）） |
| 情绪提示 | 每场/关键镜头标注（紧张 / 甜 / 虐 / 爽 / 悬疑） |
| 预计时长 | 每场标注秒数，全集 60-180 秒 |

> 推荐用**逐镜头表格**组织（模板见 `templates/episode-script-template.md`），每行=一个镜头，便于下游 short-drama-storyboard 逐镜转分镜；也允许自由文本格式，但必须包含全部元素。

### 2.3 字号与节奏控制

- 1-3 分钟单集：台词量约 **300-600 字**，镜头数 **10-25 个**，单镜头 **3-10 秒**
- 每集场景 1-3 个，每场 2-5 个镜头
- 节奏：前 5 秒出钩子 → 中段至少一次小反转或信息增量 → 结尾 5-10 秒出卡点

---

## 三、对白规则（详见 `references/dialogue-rules.md`）

1. 短句：单句 **≤20 字**，一次发言 ≤2 句
2. 口语化：台词是"说出来的"，不是"写出来的"
3. 信息密度高：每句至少传递一个有效信息
4. 情绪推进：每句对白必须推动剧情 / 关系 / 情绪至少一项
5. 禁止无信息量寒暄（"在吗""吃了没"）
6. 禁止大段独白；内心戏用 OS / VO 代替
7. 人物口吻一致：跨集用词、句式、口头禅稳定（对照 STORY_SPEC 人物卡）

---

## 四、卡点落地（详见 `references/card-point-rules.md`）

- 每集结尾必须有**强卡点**：悬念 / 危机 / 反转 / 选择 / 关系突变 至少其一
- **必须引用 EPISODE_OUTLINE 中该集的卡点设计**，在落点处标注（呼应大纲第 X 集卡点）
- 禁止连续两集使用同类型卡点（与大纲的卡点轮换一致）
- 卡点句落为字幕文字或最后一句对白，5-10 秒内讲清并戛然而止

---

## 五、全集一致性

- 人物口吻：与 STORY_SPEC 人物卡一致
- 规则代价：每次使用规则必须按规格付代价，不因集数放宽
- 秘密揭露：节奏与 STORY_SPEC 秘密系统一致，不得提前 / 滞后 >2 集
- 主线推进：每集至少推进一条主线；支线集必须带回主线钩子
- 连集检查：写完相邻 2-3 集回读衔接（上集结尾 → 下集开场）

---

## 六、产出流程（分批，防超时超长）

1. **先摘表后动笔**：通读规格+大纲，先产出四张工作表（人物口吻表 / 规则代价表 / 秘密揭露节点表 / 每集卡点表），全程对照
2. **分批产出**：每批 **5-10 集**（长剧分 6-10 批），批间输出进度标记（如"1-10/60 已完成"），见 runtime.yaml degrade 第 2 条
3. 每集写完立即跑自检清单（§七），不通过就地重写（该集重做 ≤2 轮）
4. 全集产出后抽查：首集钩子强度、中点集转折、最低点集情绪、终局集呼应

---

## 七、自检清单（每集 10 项，全部 ✓ 才过）

- [ ] 开场 5 秒内是否有钩子（冲突 / 异常 / 结果预告）
- [ ] 主角是否有具体行动目标，且未按计划顺利完成
- [ ] 是否有状态变化（信息 / 关系 / 风险 / 目标至少一项改变）
- [ ] 结尾卡点与前集不同类
- [ ] 是否推动主线（或为支线集且有回主线钩子）
- [ ] 对白全部 ≤20 字短句，无寒暄、无大段独白
- [ ] 场景标题 / 景别 / 动作 / 对白 / OS-VO / 音效 / 情绪 / 时长元素齐全
- [ ] 台词量 300-600 字、镜头 10-25 个、时长 1-3 分钟
- [ ] 结尾卡点与大纲该集卡点一致（有引用标注）
- [ ] 规则代价 / 秘密节奏 / 人物口吻与 STORY_SPEC 一致

---

## 八、交互约定

- 读完规格与大纲后**不问用户问题**，直接产出（规格与大纲已含全部决策）
- 产出后简报："正式剧本已生成：共 NN 集，位于 docs/scripts/。单集均 1-3 分钟、结尾有强卡点。下一步可调用 short-drama-storyboard 进入分镜设计"
- 不自行调用下游 skill，等总纲 / 用户调度
- 质量不达标、超时超长、卡点冲突分别按 runtime.yaml 的 degrade 处理
