# 卡点落地规则（结尾强卡点 + 大纲引用）——懒加载参考

> 本文件由 `short-drama-script` 的 SKILL.md §四 懒加载引用。

## 一、卡点是什么

每集结尾 5-10 秒内抛出的"下一集非看不可"的信息，类型与 EPISODE_OUTLINE 该集标注一致。

## 二、五种卡点类型（与规格 §八.3 同源）

| 类型 | 剧本落地方式 | 示例结尾 |
|---|---|---|
| 信息型 | 抛出证据/真相/隐藏信息/错误对象 | 字幕：他手机的屏保，是十年前的我 |
| 危机型 | 被抓/将死/规则触发/身份暴露/倒计时 | 门被撞开，枪口对准镜头 |
| 关系型 | 盟友背叛/恋人倒戈/被利用/情感承认 | 她按下通话键：沈总，人带来了 |
| 选择型 | 二选一/主动入局/用高风险规则/牺牲关系 | 主角：选她，还是选真相？你们定 |
| 反转型 | 受害者是操控者/对手在保护主角/记忆为假 | 主角：所以……救我的从来不是他 |

## 三、落地五步

1. **回读大纲**：取 EPISODE_OUTLINE 该集的"结尾卡点"条目，确认类型与内容
2. **定载体**：卡点由 字幕文字 / 最后一句对白 / 一个画面动作 承载，三选一为主、可叠加
3. **前置铺垫**：卡点前 1-2 镜头做铺垫（道具出现/人物目光/突然安静），不许凭空冒出来
4. **戛然而止**：卡点句讲完即切黑/定格，不留解释
5. **标注引用**：在剧本结尾处标注 `（呼应大纲第 X 集卡点）`

## 四、强度检查

- [ ] 卡点信息是否**观众未知**（观众已知 = 不是卡点）
- [ ] 卡点是否**改变理解**（对剧情/人物/关系产生新的猜测方向）
- [ ] 是否**留下明确问题**（"下一集会发生什么"能一句话说出来）
- [ ] 是否与前集卡点**不同类型**（连续同型 = 追更疲劳）
- [ ] 是否与大纲卡点一致（不一致 → 回读大纲修正剧本，见 runtime.yaml degrade 第 3 条）

## 五、禁止事项

- 禁止每集都是"身份揭露"（同型卡点）
- 禁止卡点信息与已揭露内容重复
- 禁止卡点放在最后一句**寒暄/告别**上（"明天见"不算卡点）
- 禁止为凑卡点强行反转（无铺垫的反转 = 观众不信任）
- 禁止卡点句超 20 字（字幕一屏放不下）

## 六、卡点轮换表（示例：60 集轮换节奏）

| 集段 | 卡点类型序列（示意） |
|---|---|
| 1-10 | 危机 → 信息 → 关系 → 危机 → 反转 → 选择 → 信息 → 危机 → 关系 → 反转 |
| 11-20 | 信息 → 选择 → 危机 → 反转 → 关系 → 危机 → 信息 → 选择 → 反转 → 危机 |
| … | 每 10 集一轮，避免相邻集同型；情绪曲线高点（爽点/绝境）配危机/反转型，低点配关系/信息型 |
