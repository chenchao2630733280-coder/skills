# Changelog

## v2.2

- Stage 3 的 PRD 默认增加终端策略基线、产品导航树和页面层级/清单。
- 增加角色/身份可见性矩阵、核心页面流及导航展示规则。
- 输入明确单端时禁止擅自拆分多个客户端；明确多端时禁止强行合并。
- 候选接入、未开放系统和非范围页面不得作为默认可见导航。
- 用户端与运营后台、供应商端、内部办公端必须按输入保持边界。
- 终端/载体口径冲突必须保留双方证据并进入 `Q/RISK`，不得自行裁决。
- Workflow、Quality Gate 和校验脚本增加导航与页面结构完整性检查。

## v2.1

- Stage 3 的 PRD 默认增加产品能力架构图、架构分层说明、`REQ` 映射和产品边界。
- 要求架构节点从实际证据、需求、角色/渠道和外部依赖动态提取，禁止预置业务模块。
- 要求在图中明确区分已确认主线、产品建议和待确认/候选接入。
- 明确产品架构不得越权输出技术组件、部署拓扑或未经确认的接口能力。
- Workflow 与 Quality Gate 增加产品架构完整性、可追溯性和状态区分检查。
- 校验脚本增加 Stage 3、PRD 模板、工作流门禁和质量门禁的架构规则检查。

## v2.0

- 调整为“1 个主 Skill + 5 个内部 Stage + 1 个 Quality Gate”。
- 移除所有项目专属案例、业务模块、系统名称和渠道示例。
- 强化领域中立：不预置业务、角色、系统、技术栈、范围和实施阶段。
- 业务分析 Stage 改为固定十章《当前业务调研分析报告》。
- 业务分析采用 A 已确认事实 / B 当前问题 / C 用户需求 / D 待确认事项四类信息。
- 业务分析明确禁止生成 PRD、技术方案和未经调研确认的功能。
- 第六章接口需求仅允许输出调研材料明确提出的内容。
- 第八章建设机会仅允许输出“方向 + 依据”，禁止写成确定产品方案。
- Quality Gate 增加业务分析边界检查。
