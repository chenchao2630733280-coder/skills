# Incremental Review

## 可接受的历史基线

至少满足一种：

- 有上次评审报告，并能定位到当时评审的 PRD 版本或提交。
- 有上次 PRD 副本和当前 PRD，可直接比较。
- 报告记录了各维度证据位置、结论和待确认项，且当前文档结构仍可定位。

仅在 PRD 末尾写“已检查”或一个总分，不足以证明内容未变化。

## 变化映射

| 变化 | 必须复查 |
|---|---|
| 产品目标、用户或范围变化 | 产品清晰度、核心场景、成功指标 |
| 修改包含、不包含、延期项或系统边界 | 范围边界、依赖、追踪矩阵、验收标准 |
| 新增角色 | 角色权限、核心流程、异常与安全 |
| 新增业务对象 | 对象、规则、状态、验收标准 |
| 修改状态或规则 | 主流程、逆向路径、边界、验收标准 |
| 新增 P0 功能 | 范围、依赖、验收标准、指标 |
| 修改验收标准 | 验收与度量、数据可观测性 |
| 新增外部依赖 | 依赖约束、异常路径、风险 |
| 修改功能清单、流程图或章节结构 | 跨章节一致性、悬空引用、追踪矩阵 |

## 执行要求

1. 列出新增、修改、删除的章节或需求。
2. 标记受影响的历史结论，不仅检查直接修改的段落。
3. 未变化维度可以沿用，但报告中保留其历史证据来源，并标明“沿用历史证据”而非“本次重新验证”。
4. 删除需求也要检查流程、依赖和指标是否留下悬空引用。
5. 更新报告版本、日期、输入版本和仍有效的遗留项。
6. 如果章节重命名、拆分或移动导致历史证据无法定位，必须重新验证对应维度。
7. 行业、合规级别、目标端或下游交付方式变化时，重新评估适用性和风险优先级。
8. 仅当 AI 开发准备度仍是本次目标时，复查 AI Ready 附录；它不影响产品质量门禁的历史结论。
9. 任何 P0 或高风险 P1 变化都必须更新追踪矩阵，不得只复查发生变化的单一章节。
10. 修改范围、规则、状态或权限后，重新核对相关验收标准是否仍然成立。
