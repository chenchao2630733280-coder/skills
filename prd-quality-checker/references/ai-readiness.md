# AI Development Readiness

仅评估 PRD 及其关联材料是否足以交给 AI 开发流程。此评估是产品质量门禁之外的独立附录。

## 先确定目标

记录目标生成范围：

- 仅生成原型或界面。
- 生成前端应用。
- 生成后端、数据模型或接口。
- 生成端到端应用。

不同范围需要的输入不同。不要因后端材料缺失而否定仅生成界面的任务。

## 检查项

| 检查项 | 适用条件 | 最低证据 |
|---|---|---|
| 生成范围 | 始终 | 明确要生成的端、模块和不包含范围 |
| 页面或交互清单 | 生成 UI 时 | 页面、主要状态、入口和关键交互可识别 |
| 业务对象和数据 | 行为依赖数据时 | 对象、产品行为依赖的属性、关系和示例可识别 |
| 业务规则 | 始终 | 计算、校验、限制、优先级和冲突处理明确 |
| 状态与异常 | 存在状态变化时 | 正向、失败、回退、超时和终态明确 |
| 角色和权限 | 多角色或敏感数据时 | 角色、操作权限和数据范围明确 |
| 接口契约 | 生成跨端或后端时 | 输入输出、错误语义和外部依赖可定位，或已有设计文档承接 |
| 验收示例 | 始终 | 关键功能有可执行的成功、失败或边界示例 |
| 非功能约束 | 实际适用时 | 性能、安全、隐私、兼容性和合规底线明确 |
| 技术边界 | 项目已有约束时 | 技术栈、现有代码、禁止事项和集成边界可定位 |

## 结果

- `READY`：目标生成范围所需输入完整，没有会改变产品行为的未决问题。
- `PARTIAL`：产品行为基本明确，但仍需设计或技术材料；列出责任归属和补充时点。
- `NOT_READY`：存在产品目标、范围、规则、状态、权限或验收方面的阻塞歧义。

不要计算伪精确的综合分。优先输出缺口、影响和需要哪类角色补充。产品问题计入主报告；纯设计或技术输入缺口只出现在本附录。
