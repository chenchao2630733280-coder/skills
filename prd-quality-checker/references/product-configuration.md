# Product Configuration Layer

面向产品经理收集业务意图。允许自然语言、表格或对话回答，不要求技术格式。

## 最小配置

未提供时使用默认值：

| 配置 | 可选值 | 默认值 |
|---|---|---|
| 运行方式 | Audit / Improve | Audit |
| 审核范围 | Full / Quick / Incremental | 有可靠历史基线时 Incremental，否则 Full |
| 下游阶段 | 方案设计 / 排期 / 开发 / 验收 | 开发 |
| 输出 | Markdown / Markdown + JSON | Markdown |
| AI 开发准备度 | 启用 / 不启用 | 不启用 |

## 产品经理可描述的配置

- “这是内部审批工具，准备进入开发。”
- “只做快速预审，不需要逐题问我。”
- “支付和退款规则缺失必须阻塞。”
- “埋点本期可以后补。”
- “发现问题后每次问一个，并推荐一个答案。”
- “结果还要给 Web 平台读取。”

执行层将其转换为内部配置，不要求用户提供字段名。

## 自定义规则表达

产品经理只需说明：

| 业务问题 | 示例 |
|---|---|
| 检查什么 | 退款规则是否覆盖部分退款 |
| 何时适用 | PRD 涉及退款时 |
| 什么算通过 | 条件、金额、路径和失败处理明确 |
| 什么会阻塞 | 无法确定是否允许退款 |
| 有问题怎么处理 | Improve 模式逐题确认 |

自定义规则不得覆盖证据纪律，不得把缺失证据直接判为通过。与核心门禁冲突时采用更严格结果，并在报告中说明冲突。

## 评审画像

从材料和用户描述推断：

- 变更类型：新产品、存量迭代、修复或合规变更。
- 产品类型：用户产品、内部工具、平台能力、数据或 AI 产品。
- 风险等级：普通或高风险。
- 目标下游：方案设计、排期、开发或验收。
- 交付方式：人工开发、AI 辅助或 AI 代码生成。

推断不确定且会改变适用规则时再询问用户，否则标为合理假设。
