# 执行模式（Execution Modes）

> 本文件定义 agent-runtime-exec 支持的多 Agent 执行模式。

## 一、模式总览

| 模式 | 结构 | 适用场景 | 失败影响 |
|------|------|---------|---------|
| 主从模式 | 一主多从 | 任务可拆分的并行场景 | 单从失败不影响其他从 |
| 对等模式 | 多 Agent 协商 | 需要多方观点汇总/投票决策 | 需多数达成一致 |
| 管道模式 | 串行接力 | 流水线式处理(PRD→设计→实现) | 前阶段失败阻断后阶段 |
| 扇出扇入 | 一主扇出多从 | 并行处理 + 结果聚合 | 单从失败不影响聚合 |

## 二、主从模式（master-slave）

### 2.1 结构

```
        ┌──────────┐
        │  Master  │
        └────┬─────┘
             │ delegate
   ┌─────────┼─────────┐
   ▼         ▼         ▼
┌──────┐ ┌──────┐ ┌──────┐
│Sub-1 │ │Sub-2 │ │Sub-3 │
└──┬───┘ └──┬───┘ └──┬───┘
   │        │        │
   └────────┼────────┘
            │ result
            ▼
       ┌──────────┐
       │  Master  │ (collect + merge)
       └──────────┘
```

### 2.2 执行流程

1. Master 把任务拆分为 N 个子任务
2. 并行委派给 N 个 Slave(每个分配 deadline)
3. 各 Slave 独立执行,回传 result
4. Master collect 收集全部 result
5. Master merge 按策略合并

### 2.3 失败处理

- 单个 Slave 失败:标记 failed,不影响其他 Slave
- Slave 超时:标记 timeout,Master 可选择重试或转人工
- 多数 Slave 失败:整体标 partial,提示人工介入

## 三、对等模式（peer）

### 3.1 结构

```
┌──────┐    ←──→    ┌──────┐
│Agent1│            │Agent2│
└──┬───┘            └──┬───┘
   │                   │
   └───────←──→────────┘
           │
           ▼
    ┌─────────────┐
    │  投票/协商   │
    └─────────────┘
```

### 3.2 执行流程

1. 各 Agent 独立处理同一任务
2. 各 Agent 回传 result
3. 按 voting 策略投票(相同结果占比 >50% 取胜)
4. 无法达成多数时转人工裁决

### 3.3 适用场景

- 需要多方观点汇总(如多个 Agent 评审同一代码)
- 需要投票决策(如多个 Agent 评估风险等级)

## 四、管道模式（pipeline）

### 4.1 结构

```
┌──────┐     ┌──────┐     ┌──────┐
│Stage1│ ──→ │Stage2│ ──→ │Stage3│
└──────┘     └──────┘     └──────┘
  PRD         设计         实现
```

### 4.2 执行流程

1. Stage1 执行,产出中间结果
2. Stage1 的输出作为 Stage2 的输入
3. 串行接力,直到最后阶段
4. 收集最终阶段的结果

### 4.3 失败处理

- 前阶段失败:阻断后阶段,整体标 failed
- 前阶段超时:等待或降级,后阶段暂停

## 五、扇出扇入（fan-out/fan-in）

### 5.1 结构

```
        ┌──────────┐
        │  Master  │
        └────┬─────┘
             │ fan-out
   ┌─────────┼─────────┐
   ▼         ▼         ▼
┌──────┐ ┌──────┐ ┌──────┐
│Sub-1 │ │Sub-2 │ │Sub-3 │
└──┬───┘ └──┬───┘ └──┬───┘
   │        │        │
   └────────┼────────┘
            │ fan-in
            ▼
       ┌──────────┐
       │  Master  │ (聚合)
       └──────────┘
```

### 5.2 与主从模式的区别

| 维度 | 主从模式 | 扇出扇入 |
|------|---------|---------|
| 任务 | 各 Slave 不同任务 | 各 Slave 相同或相似任务 |
| 目标 | 分工完成不同部分 | 并行处理 + 结果聚合 |
| 合并 | 拼接各部分结果 | 聚合/投票选最佳结果 |

## 六、模式选择建议

| 需求 | 推荐模式 |
|------|---------|
| 任务可拆分,各部分独立 | 主从模式 |
| 需要多方观点/投票 | 对等模式 |
| 流水线式处理 | 管道模式 |
| 并行处理同一任务,选最佳 | 扇出扇入 |
