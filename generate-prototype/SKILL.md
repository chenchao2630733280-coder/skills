# Generate Prototype — 页面原型文档生成器

本 Skill 用于从系统产品设计文档（PRD）中生成**标准化的页面原型文档**，将 PRD 中的页面设计章节展开为前端可执行的完整规格。适用于企业管理后台、原生移动 App、移动 Web/H5、小程序、混合应用及多端产品。

---

## 一、触发条件

当用户提出以下任一需求时，立即激活本 Skill：

1. 需要根据产品设计文档**生成页面原型文档**
2. 需要为系统编写**UI/UX交互规格**
3. 需要将PRD中的页面设计章节**展开为完整的原型文档**
4. 用户提供了设计文档，要求输出**可指导前端开发的页面规格**

### 终端判定（最小规则）

- 优先读取 PRD 中的 `client_type`、页面所属端和导航定义。
- `admin_web` 沿用侧边栏、顶部导航、表格、分页和弹窗模式。
- `native_app`、`mobile_web`、`mini_program`、`hybrid` 使用移动端单列布局、卡片/列表、页面级导航和底部操作模式。
- `multi_end` 按页面所属端分别生成规格，禁止把 PC 表格和复杂弹窗直接缩放到移动端。

## 移动端原型补充规则

当 `client_type` 为移动端时：

1. 页面默认采用单列布局，避免直接缩放 PC 表格和复杂弹窗。
2. 每个页面仅需说明：
   - 页面入口
   - 返回规则
   - 主要操作位置
   - 加载、空数据、失败、提交中等核心状态
3. 输入类页面需避免键盘遮挡；底部固定操作需适配安全区。
4. Deep Link、离线、弱网恢复、应用生命周期、相机、定位、通知及权限降级等内容，仅在 PRD 明确涉及对应场景时生成。
5. Bottom Sheet、Action Sheet 或全屏页面由内容复杂度决定，不要求每个浮层都提供多种方案。

## 二、文档结构框架

原型文档由以下**5类内容板块**组成，板块的划分和排列根据业务需要灵活组织：

---

### 板块A：全局设计规范

定义系统级的视觉和交互基线，确保所有页面风格统一。

**必须包含：**

#### A1 页面总览
- 表格形式：编号 | 页面名称 | 所属模块 | 所属端 | 页面类型 | Route/文件名 | 导航标识
- 每个页面必须有唯一编号

#### A2 全局布局
- 使用 ASCII 字符画绘制主框架布局图，并标注各区域功能。
- 后台端：遵循 `../_shared/references/pc_admin_ui_spec.md` 纵向布局（`vertical`），标注以下尺寸：
  - 左侧深色侧边栏：宽 `266px`（允许 266/277/288 三档），折叠 `64px`；背景 `#282c34`，文字 `hsla(0,0%,100%,0.95)`，选中项背景主色 `#1890ff`
  - 顶部导航栏：高 `60px`，白底；位于侧边栏右侧，含折叠按钮、面包屑、搜索、消息、用户头像
  - 工作区页签栏：高 `50px`，白底；标签文字与菜单标题同源
  - 内容区：背景 `#f6f8f9`，内边距 `20px`，内容置于白色卡片内
  - 定义无独立菜单入口页面的到达方式
- 移动端：定义顶部导航、内容滚动区、底部 Tab 或主要操作区；输入页面需说明键盘遮挡处理，底部固定操作需适配安全区。
- 多端产品需分别给出各端布局，不得共用一张按比例缩放的布局图。

#### A3 设计规范
- **色彩规范**：表格形式，用途 | 色值 | 说明。
  - **后台端（admin_web）**：必须遵循 `../_shared/references/pc_admin_ui_spec.md`，使用以下色值体系：
    - 主色 `#1890ff`（blue 主题，另有 green `#41b584` / purple `#6954f0` 可选）
    - 功能色：成功 `#13ce66`、警告 `#ffba00`、危险 `#ff6700`、错误 `#ff4d4f`
    - 文本色：主要 `#303133`、常规 `#606266`、次要 `#909399`、占位 `#c0c4cc`
    - 边框：基础 `#dcdfe6`、浅 `#e4e7ed`、更浅 `#ebeef5`、超浅 `#f2f6fc`
    - 背景：页面 `#f6f8f9`、基础填充 `#f5f7fa`、深色菜单 `#282c34`、卡片 `#ffffff`
  - **移动端**：根据系统需要定义色值体系，项目已有 Token 或 `_shared` 默认档案优先
- **状态标签色**：表格形式，状态 | 标签样式 | 色值 | 使用场景。从业务实体的状态枚举推导；后台端使用 `el-tag` 风格（success/warning/danger/info），颜色与语义严格对应
- **字体规范**：表格形式，用途 | 字号 | 字重。
  - 后台端：页面主标题 18px、卡片/区块标题 16px、正文 14px、辅助说明 12px、数据看板核心数字 22px；字重正文 400、强调/标题 500~600
  - 移动端：根据系统需要定义
- **间距规范**：表格形式，场景 | 间距值。
  - 后台端：4px 基数，基准 20px（卡片内边距、卡片间距、页面留白）；嵌套层级越深间距越小（20→16→12→8）
  - 移动端：根据系统需要定义
- **组件参数**：通用组件的圆角、高度、尺寸等。
  - 后台端：圆角 `2.5px`（全局统一）、阴影 `0 1px 4px rgba(0,21,41,0.08)`、控件高度 `32px`、输入框常规宽 `320px`/短输入 `220px`
  - 移动端：根据系统需要定义

> 后台端设计规范的具体条目必须遵循 `../_shared/references/pc_admin_ui_spec.md`，不自行编造色值或尺寸。移动端设计规范根据系统UI风格决定。

---

### 板块B：各页面规格

按业务模块分组，每个页面输出完整的布局与交互规格。

**页面规格的通用要素（所有页面类型均适用）：**

| 要素 | 说明 |
|------|------|
| 页面编号与名称 | 如“P02 经营总览” |
| 终端与路由 | 所属端、Route（如适用）、登录要求；Deep Link 仅在 PRD 明确涉及时说明 |
| 页面类型 | 列表页/表单页/详情页/仪表盘/报表页/流程页/系统能力页/其他 |
| 入口与退出 | 来源入口、返回目标及未保存退出规则 |
| 页面头部 | 标题、筛选器、操作按钮或移动端导航栏 |
| 页面内容 | 根据页面类型定义（见下方） |
| 页面状态 | 加载、空数据、失败、提交中等核心状态；离线和权限受限仅在 PRD 涉及时说明 |
| 浮层规格 | 仅在页面需要浮层时说明；移动端形式由内容复杂度决定 |
| 交互逻辑 | 联动、计算、校验、刷新和返回等 |
| 端能力 | 仅在 PRD 明确涉及相机、定位、通知等能力时说明权限与降级策略 |
| 特殊样式 | 条件样式与终端适配规则 |

**按页面类型定义内容规格：**

#### 列表页
- 后台端：筛选条件、工具栏、表格列、操作列、分页和特殊行样式规则。
- 移动端：搜索入口、筛选方式、卡片/列表字段层级、主次操作和空/失败状态；下拉刷新、上拉加载仅在业务需要时说明。
- 移动端仅在确有横向比较价值时使用表格，并说明横向滚动或字段折叠方式。

#### 表单页
- 表单区块：每个区块的字段列表（字段 | 类型 | 必填 | 说明）。
- 自动计算字段标注公式；条件必填字段标注触发条件。
- 后台端可使用多列和动态表格行；移动端默认单列，并定义键盘类型、键盘遮挡、焦点顺序和长表单分步策略。
- 明确底部操作按钮是否固定、安全区留白、重复提交防护和未保存退出提示。

#### 详情页
- 页面头部：返回、标题、状态和操作按钮。
- 概览指标：指标 | 口径说明。
- 内容组织：后台端可使用 Tab；移动端优先使用卡片分组、锚点或独立子页面，避免过深嵌套 Tab。
- 定义关联跳转和返回后的数据刷新规则；滚动位置恢复仅在长列表或长详情确有需要时说明。

#### 仪表盘
- 筛选器组
- 指标卡片：分组列出，每项含口径说明
- 图表规格：类型 | 数据 | 颜色 | 轴定义
- 列表区域（如适用）

#### 报表页
- 筛选器组
- 表头定义（含多行表头，如适用）
- 数据规则：条件样式、汇总行
- 明细下钻（如适用）

#### 浮层规格（通用）
仅当页面确有浮层时输出规格：
- 名称、用途、字段/选项、操作按钮、关闭方式和校验规则。
- 后台端可使用弹窗；移动端按内容复杂度选择 Bottom Sheet、Action Sheet 或全屏页面，不要求提供多种方案。
- 输入型浮层需说明键盘遮挡和未保存内容的处理。

> 页面类型不限于以上几种，根据实际需要增减。

---

### 板块C：全局组件规范

识别页面中复用的交互模式，提取为通用组件规格。

**每个组件规格包含：**
- 组件名称和用途
- 视觉参数（尺寸、颜色、圆角等）
- 交互行为
- 使用场景

> 组件列表完全由业务需要决定，不预设固定组件。

---

### 板块D：全局交互规范

定义跨页面通用的交互行为规则。

**按页面类型定义交互规范：**
- 每种页面类型的标准交互流程（筛选、提交、切换、关闭等）。
- 表单校验规则（必填、格式、联动）和重复提交防护。
- 消息提示规范（成功、错误、警告、信息的样式和持续时间）。
- 后台端可补充键盘快捷操作；移动端说明系统返回、页面返回、键盘遮挡和安全区处理。弱网、离线、应用恢复、手势刷新等仅在 PRD 明确涉及时生成。

---

### 板块E：页面流转关系

定义页面间的导航和跳转关系。

#### E1 页面跳转关系图
- 使用ASCII箭头绘制：`PXX 页面名称 ──→ PYY 目标页面（触发条件）`

#### E2 核心业务流转
- 使用ASCII箭头绘制核心操作链路
- 标注关键数据流向

## 三、从PRD提取信息的映射方法

本 Skill 的输入是一份系统产品设计文档（PRD），需要从中提取信息填充原型文档。

**映射原则：**

| 原型文档板块 | PRD中的信息来源 | 提取方法 |
|------------|--------------|---------|
| 页面总览 | 产品架构/页面清单 | 映射页面编号、名称、所属端、类型和路由 |
| 全局导航 | 导航与信息架构 | 后台端提取侧边栏/顶部导航；移动端提取 Tab、页面入口和返回规则，Deep Link 按需提取 |
| 状态标签色 | 数据模型的状态枚举 | 汇总所有实体的状态值，定义标签色 |
| 页面字段/筛选/表格或卡片 | 页面设计规格章节 | 按所属端提取，并补充层级、对齐和样式说明 |
| 仪表盘指标 | 报表与统计体系章节 | 提取指标定义、公式、口径 |
| 浮层规格 | 页面设计规格章节 | 按终端提取弹窗、Bottom Sheet、Action Sheet 或全屏流程 |
| 页面状态与端能力 | 页面设计规格/移动端专项章节 | 默认提取加载、空、失败和提交中状态；离线、权限及端能力降级按需提取 |
| 交互函数 | 页面设计规格章节 | 提取计算逻辑、联动、刷新和返回规则 |
| 页面跳转 | 页面设计规格 + 业务流程 | 从链接跳转和按钮行为提取 |
| 校验规则 | 数据完整性校验章节 | 映射到表单/浮层的校验说明 |

> 章节编号不固定，根据PRD实际结构定位对应内容。

## 四、生成流程

### Step 1：读取PRD文档与上游JSON工件

1. 读取用户提供的系统产品设计文档（PRD .md）
2. **优先读取上游 JSON 工件**（若存在，路径 `output/spec/`）：
   - `pages.json` — 页面清单与端类型（权威来源，优于从 .md 重复提取）
   - `data-model.json` — 实体字段约束
   - `permissions.json` — 权限角色定义
   - `business-rules.json` — 业务规则
   - `state-machines.json` — 状态流转
   - JSON 工件缺失时回退到 PRD .md 提取，并在产出工件中标记 `sourceLevel: INFERRED`
3. 定位终端类型、页面清单、导航、页面规格、数据模型和校验规则等关键章节；移动端专项能力仅在 PRD 明确涉及时提取。
4. 建立"页面编号 → 所属端 → 页面规格"的映射表。

### Step 2：生成全局设计规范

1. 从页面清单生成页面总览表
2. 根据所属端生成侧边栏/顶部导航或移动端 Tab/页面栈结构。
3. 定义设计规范（色彩、字体、间距、组件参数）。
4. 从所有实体的状态枚举汇总状态标签色表

### Step 3：按模块生成页面规格

1. 按模块分组
2. 每个页面根据类型选用对应的规格要素
3. 从 PRD 提取字段、筛选、表格/卡片及核心页面状态；浮层、Deep Link、离线和端能力等按需提取。
4. 补充交互说明、异常状态和终端适配规则。

### Step 4：提取组件规范和交互规范

1. 识别页面中复用的组件模式
2. 定义通用组件规格
3. 定义全局交互规范

### Step 5：生成页面流转关系

1. 从所有页面的跳转链接汇总页面间跳转关系图
2. 从业务流程提取核心业务流转图

### Step 6：交叉校验

1. **页面覆盖完整性**：原型文档覆盖PRD中的所有页面
2. **状态标签一致性**：状态标签色表覆盖所有实体的状态枚举值
3. **跳转关系一致性**：页面跳转目标与页面清单中的编号对应
4. **字段一致性**：表单与浮层字段和领域模型/API 契约对应。
5. **终端模式一致性**：移动端不得直接套用宽表格、复杂弹窗或仅鼠标可完成的交互。
6. **状态完整性**：关键页面覆盖加载、空、失败和提交中；离线、权限拒绝等仅在涉及对应场景时校验。
7. **指标口径一致性**：仪表盘/报表指标与 PRD 指标定义对应。

---

## 五、质量标准

1. **完整性**：每个页面都有完整的规格定义，无遗漏
2. **精确性**：字段类型、对齐方式、样式参数明确可执行
3. **一致性**：同一组件在不同页面中的规格完全一致
4. **可开发性**：前端开发人员可直接依据文档实现，无需二次确认。
5. **终端适配性**：移动端页面具备可触达的主操作、明确返回路径、核心页面状态和必要的键盘/安全区处理。
6. **ASCII图表**：布局图、导航结构、流转关系均使用 ASCII 字符画。
7. **口径标注**：所有指标必须标注计算口径说明。
8. **产物自评**：本 skill 产出后,按 skill-auditor 执行后评测模式自查(可选)。

## 六、页面规格模式参考

以下是管理后台和移动端常见的页面规格模式，生成文档时应**根据业务需要和所属端主动评估是否适用，不强制套用**：

### 列表页模式
- 筛选条件区 + 工具栏 + 数据表格 + 分页
- 操作列按实体状态区分可用操作
- 条件行样式（如超期/风险高亮）

### 表单页模式
- 多区块组织，动态行区域支持增删
- 自动计算字段标注公式
- 底部操作：取消 + 保存草稿 + 提交

### 详情页模式
- 概览指标栏 + 多Tab/多卡片组织
- 关联实体可跳转

### 仪表盘模式
- 筛选器 + 分组指标卡片 + 图表 + 列表
- 每项指标标注口径

### 浮层模式
- 后台端新增/编辑弹窗：字段 + 校验 + 自动计算。
- 移动端浮层形式由内容复杂度决定：轻量选择/确认可使用 Bottom Sheet 或 Action Sheet，复杂录入/详情可使用全屏页面。

### 移动端页面模式
- 列表：搜索/筛选入口 + 卡片列表 + 明确的加载、空数据和失败状态。
- 表单：单列字段 + 键盘适配 + 明确主操作 + 未保存退出提示。
- 详情：顶部返回 + 状态/摘要 + 卡片分组 + 明确主操作。
- Deep Link、离线、弱网恢复、应用生命周期、相机、定位、通知及权限降级，仅在 PRD 明确涉及对应场景时生成。

### 通用样式规则
- 数值列：等宽字体，右对齐
- 负值：红色字体
- 自动计算字段：灰色背景，只读
- 进度条/状态标签：根据阈值或状态映射颜色

### 标注与 JSON 工件（可选输出）

- 页面标注使用 `SXX` 编号，按真实功能区域生成（不固定数量）；当需要机器可读工件时，向 `output/spec/annotations.json` 写入，结构参考 `../_shared/references/schemas/annotations.example.json`。
- `annotations.json` 由本 Skill 创建和维护；`generate-html-pages` 不读取、不绑定标注（不生成 `data-spec-id`/`data-page-id`），`generate-portal` 在门户层读取 `annotations.json` 并按 PXX 分组展示标注。
- 其他可选工件（`actions.json`、`navigation.json`、`overlays.json`、`components.json`、`design-tokens.json`）写入 `output/spec/`，结构参考 `../_shared/references/schemas/` 下对应示例。
- **本 Skill 更新 `output/spec/pages.json`（富化）**：在 generate-system-prd 产出的 pages.json 基础上，填充 `archetypeId`（页面原型分类 ID）、`applicableStates`（适用状态）、`actionIds`（关联动作）、`specIds`（关联标注 SXX）等富化字段。generate-html-pages 读取这些字段路由 HTML 生成；product-pipeline-master §十质量门禁"原型 | pages.json 的 archetypeId 已填充"依赖此富化。
