# 页面原型设计核心规范

本文件适用于 `generate-prototype`。页面原型必须保持一个完整Markdown主文档，JSON只作为同一规格的辅助结构化表达。

## 1. 交互闭包

- 每个可操作元素必须闭包到页面、弹层、命令或明确外部动作。
- 不允许“点击后进入详情”“弹出窗口”等无目标ID的模糊描述。
- 弹层和复用组件在全局目录定义一次，页面通过稳定ID引用。
- CRUD完成后的刷新范围、状态变化和用户反馈必须明确。

## 2. 信息分层

- 全局布局、基础状态、默认反馈、权限行为、分页和格式只定义一次。
- 页面章节写真实业务区域、字段、动作、状态差异和异常。
- 简单组件使用轻量规格；复杂页面按需增加流程、布局和状态转换。
- 禁止为了模板完整而输出空章节、空排序、空分页或重复短语。

## 3. 页面与对象分类

- `routePage`：独立路由页面。
- `component`：复用组件。
- `overlay`：Modal、Drawer、Sheet等弹层。
- `preview`：文件、图片、材料预览。
- `tab`：父页面内容区。

组件、Tab和弹层不应自动升级为独立页面。

## 4. 图示规则

- ASCII只用于差异化布局、复杂分栏、核心主界面或用户明确要求的线框图。
- Mermaid只用于条件分支、循环、回退、异步和多角色流程。
- 图中必须使用真实业务模块名称。
- 通用“加载成功/空/失败/无权限”不得逐页绘制。

## 5. 标注规则

- 标注数量由真实功能区决定，不固定为四个。
- 主文档记录标注的业务含义和关键四维信息。
- `annotations.json`只结构化同一内容，不得新增主文档不存在的规则。

## 6. 健壮性

- 覆盖首次使用、空数据、网络失败、权限不足、重复提交、并发冲突和中断恢复。
- 写操作具备防重复和幂等语义。
- 高风险和敏感场景不得只依赖颜色表达。
- 设备只按真实业务声明生成，不强制PC和移动镜像。
